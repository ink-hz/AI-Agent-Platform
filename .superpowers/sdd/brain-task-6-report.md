The implementation uses exact authorization route templates and keeps the Execution Worker namespace on its existing device-auth boundary. A management role alone does not bypass Agent-use grants.

## Security and data-boundary behavior

- Mission ownership is checked before encrypted content is decrypted.
- Mission IDs are generated by the server.
- `Idempotency-Key` must be a UUID; a first request returns `201`, an exact replay returns `200`, and a payload collision returns `409`.
- Input is strictly limited to 32 KiB of UTF-8 bytes. Request bodies reject unknown fields, including unsupported attachment fields.
- Mission listing uses an owner-bound, signed, opaque keyset cursor and newest-first ordering.
- All Agent Brain responses, including validation and authorization errors, carry no-store headers.
- Existing CSRF and Origin enforcement applies to mutating endpoints.
- Public errors do not expose internal exception text.

## Cancellation linearization

Cancellation and execution enqueue both lock the Mission before updating or creating relay jobs. This closes both important races:

- A queued job is atomically converted to terminal `cancelled` without a worker lease.
- A leased/dispatched/running job receives a pending `cancelled` stop request.
- If cancellation wins between Mission run creation and relay enqueue, the relay row is inserted directly in the constraint-valid terminal `cancelled` state and is never leasable.
- Repeated cancellation is idempotent and does not repeatedly increment the Mission row version.

## SSE behavior

- Frames contain `id: <seq>`, `event: mission`, and one-line JSON data.
- `after` supports replay; heartbeats are comments; terminal Missions close the stream.
- A second tail read closes the event/terminal-status commit race.
- Stream reservations are released on normal completion, generator close, and response-start disconnect.
- Limits are enforced at 3 streams per owner, 2 per owner/Mission, and 200 process-wide.
- Rejected reservations do not retain zero-count map keys, preventing counter-map growth under global saturation.

## TDD and review evidence

Representative RED cases caught and drove fixes for:

- missing API/router and creation-result contract;
- 100-item pagination sentinel handling;
- terminal-event query race;
- missing no-store headers on validation failures;
- invalid direct-Agent path response classification;
- cancellation versus lease and the create-run/enqueue gap;
- missing per-Mission/global SSE limits;
- rejected SSE reservations accumulating zero-valued counter keys.

Independent review initially found two Important issues: cancellation/lease atomicity and incomplete SSE concurrency limits. Both were fixed and re-reviewed. Final result: **Critical 0, Important 0**.
