# HR 未消费工具批次硬窗口修复

日期：2026-09-11。

先前实现保护最新工具批次，确保后续 work 直接看到原始正文；但保护在硬窗口超限时仍然生效，导致多条各自可装入窗口的读取结果整批无法压缩，工作永久进入 `waiting_budget`，追加预算也不能改变模型窗口。

本次把软阈值与硬窗口分开。普通软压缩继续保护最新未消费批次；只有完整 work 输入超过硬窗口时，允许该批次按完整 entry 进入 summary 候选，并优先于旧 summary，以保证每次成功摘要都缩短新正文。来源 provenance、作用域标签、原始 entry 和 checkpoint 均保留；不裁剪正文或扩大窗口。

若固定当前状态或单个完整 entry 加输出预留本身超过窗口，系统进入 `blocked` 并返回 `context_too_large`。追加较短输入不会删除旧历史，因此不能承诺原 work 可由“缩短输入”恢复；界面要求保留旧 work、历史与成果，拆分范围后创建新 work，或由管理员核实模型窗口配置。该情况不再伪装成追加预算可解决的 `budget_exhausted`。

真实数据库测试以同一 attempt 返回三条各 20,000 个中文字符的读取结果，模拟已在等待预算的工作追加后恢复；两次逐 entry 摘要后，第三条原始工具正文进入可发送 work 上下文。另覆盖软阈值原始批次保护、单条/固定前缀超窗 blocked、summary 重试与未提交 work 不算消费、后续已提交 work 才解除保护。
