## 已实现的边界

冻结命令使用现有 P01 哈希原文，不含虚构回调地址、租约或授权凭据；实际传输信息后补，并用完整 v5 校验器核对哈希。P01 共享资产和哈希字节保持不变。内部模板支持有序附件描述与输出范围，但本切片的绑定入口仅接当前可执行的文字/工具策略输入；真实材料与任务准备仍需后续接入。

现有 `execution_jobs` 加密正文保存唯一命令内容。新增 `direct_command_bindings` 仅维护 Attempt、命令、任务、序号、哈希与交接/接收证据，不新增执行状态权威。准备操作在调用方同一事务中写入加密任务、绑定和 Attempt 的 run 引用；既有绑定可在重建上下文前取回。

锁顺序为 Conversation→Turn→Attempt→binding→job。校验真实 owner、Turn/用户消息身份、当前路由、领取者及版本；最后一把锁取得后再次依据数据库时钟校验租约。不存在跨网络或模型调用持锁。

命令序号是串行保留位：基于已证实接收的最大序号分配，同命令重传不消耗新序号。只有从未交接、从未领取且仍排队的任务，才可在同时使任务永久不可派发的事务中退还保留位；已交接但结果未知的记录保持占位，不能因本地查无命令或超时释放。

服务端 owner 引用为 `principal:` 加 SHA-256（域 `hr-worker-principal-v1`、NUL、owner UUID 字节），仅是脱敏标识，不是权限。Turn 顺序取真实用户消息序号对应的 Turn 顺序并冻结；不依赖时间戳/随机 UUID 排序，也不在重传时重算。当前范围不硬删除这段 Turn 历史。

旧 Relay 的领取、指定任务领取、取消、中断、超时更新、按 owner 更新和心跳批量更新均隔离 `worker_direct_v5`；原 Brain 数据库函数已有任务类型过滤，无须改写已编号 SQL。

MetaBot 既有 Bearer 接收接口在原 202 响应中附加 `hr_dispatch_acceptance_v1` 回执。原启动代次来自同事务中的持久执行意图，不从请求或回调猜测；新租约重传可取回旧启动代次。Platform 严格校验完整回执及前次身份，`ended` 或空启动代次均不等于执行已停止证明。
