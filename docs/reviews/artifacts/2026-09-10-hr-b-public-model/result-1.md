# 岗位校准（参考）：多模态生成动作大模型工程师/专家 — 竞对公开归档解读

来源与性质：竞对（AGIRobot，飞书社招）公开静态归档，观察时点 2026-09-06T14:38Z，来源 URL 见材料。此为竞对参考，非奥比中光已确认标准，不作为本公司门槛。归档说明未重新抓取官网、未回查缺失原始证据包，故仅代表该观察时点的公开文本。

一、岗位真正要交付什么（从职责链路推导，非头衔）
核心交付：打通「说什么→怎么说→怎么动」闭环——以文本/语音韵律/视觉为条件，生成全身动作与手势，且动作必须在真实动力学约束下可执行，并可被量化评测与线上迭代。
关键张力：既要可控且有表现力的生成（风格/人设/情绪/节奏），又要满足硬约束（空间/安全/可执行、动力学、接触平衡、IK、拼接过渡）。可执行性与可度量性（自然度/稳定性/可执行性指标 + A/B + 回归）是重心，而非单纯生成好看动作。
协作面：需与 TTS/对话/控制/安全多团队协作（职责5）。

二、条件歧义与边界（影响后续校准）
1. 要求与加分项逐字重复：JD 中「要求1/2/3」与「加分项」三条完全相同，实际未区分必备门槛与加分，无法据此定硬性条件。疑为发布方复制错误。此为最影响校准的缺陷。
2. 执行载体不明：「全身动作+动力学/平衡/IK」既可指实体人形机器人，也可指虚拟数字人/动画，二者候选人背景（机器人控制 vs 计算机图形/动画）差异大。来源域名含 robot 倾向实体，但正文未点明。
3. 职级/头衔跨度：「工程师/专家」双头衔，未给职级、年限、研究型 vs 落地型主导；职责同时含「研究可控生成」与「线上A/B落地」，跨度大。

三、反证与不应做的推断
- 「熟悉扩散/序列模型」不等于必须顶会论文；职责更重落地与可执行性。
- Text2Motion/Speech2Motion/风格控制/韵律对齐为「任一方向」，不应要求全部具备。
- 不应将 JD 每句自动当硬门槛，尤其在要求/加分不可区分的情况下。
