# HR 知识上下文受控试验

2026-09-08。真实 Claude Code CLI 调用；不是生产网页或 MetaBot PTY 的端到端验收。

## 已观察到的事实

使用 `claude-opus-5`、CLI `2.1.258` 和现有用户配置的模型提供方，加载 Orbbec-Agent-Team `e791caa` 对应的 HR 角色说明。两个独立的新会话都仅提供 Read / Glob / Grep，不联网、不写业务数据；输入是三组明确标注的教学案例。

先保存无知识索引的基线，再在相同案例和角色说明上附加固定版本索引。两个会话均成功完成：基线耗时约 46.21 秒，附知识耗时约 46.45 秒。单次耗时不可用于推断延迟变化。

附知识会话自主发起了三次成功的 Read，读取固定版本目录中的 `requirement-calibration`、`sourcing-and-transfer`、`comparison-and-learning`。原生工具调用 ID 与工具结果一一对应，结果未标记错误。这是本次受控试验实际读文件的证据，独立于回答末尾的自报引用。

内容版本为 `6cea3c8877c3c66e5e3310e22f10b72032cbeaab`。Platform 冻结字段只包含入口与说明，没有附正文；本次试验也通过工具结果取得正文。

## 对回答的初步判断

| 场景 | 基线与附知识回答的差异 | 保留的问题 |
| --- | --- | --- |
| 长期招聘空缺 | 基线已经指出不能直接认定市场缺人；附知识回答明确并列需求、供给、吸引力、甄选四类解释，要求把门槛对应到任务和业务理由 | 附知识回答提出抽查 20–30 份简历，未解释样本量依据 |
| 跨行业能力迁移 | 两者都能跳出行业标签；附知识回答更明确地区分共享任务机制与领域/环境条件 | 附知识回答提出 3–6 个月补齐知识，缺少岗位和个人学习条件的依据 |
| 不同形式的候选人证据 | 两者都拒绝没有证据的百分制排名；附知识回答进一步关注共同任务版本、评价锚点和可观察行为 | 附知识回答提出 4–6 项任务，不能把该数字当作组织的既定要求 |

这说明自主发现和读取机制可行，也看到部分回答组织方式的变化。三个案例、各一次回答，不能证明整体 HR 质量已稳定提升；基线本身已有较好的判断能力。上述数字仍需要明确为建议并解释依据，后续真实业务评审应继续关注。
