# HR 情报原始资料 / AI 分析两层交付

用户批准两层设计并要求开始实施。2026-09-11 已实现并完成生产发布。

## 产品行为

`/hr/panorama` 默认打开「原始资料」，与「AI 分析报告」并列。两层共享公司选择，分别保留筛选、当前岗位/报告和阅读位置；历史研究/版本深链接仍直接打开报告。旧模板分析仍归历史发布入口。

资料层：12 公司、3,437 条岗位身份，按公司、正文关键词、地点和渠道分页查阅。岗位详情包含从确切归档记录恢复的职责/任职要求、原文已有的公开字段、来源和证据身份；公司资料展示清洗后的官网文本，渠道失败与缺失独立说明。未明确的状态显示未知，未单独列出的内容不补写。

报告层：复用已有 38 篇研究/7 公司，原 Markdown 和研究 edition 不变。报告能回到其使用的资料版本；唯一来源定位到岗位，共用归档入口定位到公司范围。尚无报告的公司保留资料入口。

## 接口、验证与审查

新增现有 HR 登录/中央 grant 保护的目录、公司分页和单岗位读取接口：`/api/hr/panorama/sources`、`/sources/{company_key}`、`/sources/{company_key}/jobs/{job_id}`。公司/岗位读取必须携带 edition；错版本或错归属 404，损坏包 503。私有 no-store，不将正文打进公开 JS。

本地真实 HTTP 使用一次性 PostgreSQL、真实持久会话和 HR grant，验证目录、过滤/分页、固定版本、跨公司拒绝、同会话撤权及一份研究到资料的引用；相关清洗/库测试通过。新增页面组件验证默认资料层、切层保留对象、详情返回、401/403 清除正文、固定研究深链接和精确来源跳转；旧目录导航小范围回归和构建通过。

独立代码审查仅发现切层滚动恢复时序问题：切回时旧 loading=false 提前发出 ready，以及正文快捷切层绕过位置保存。已在 `bb5faa5` 修复：当前请求完成才触发 ready，所有切层入口统一在切换前保存位置；两个针对性失败用例修复后通过，相关组件检查与 TypeScript/Vite 构建通过。复核没有剩余重要问题。其余资料、权限和版本引用审查无重要阻塞。

浏览器发现结果为空，未进行浏览器验收；未新建生产用户会话读取全文、未故障注入、未调用模型或重评报告质量。工程检查不是研究质量证明。
