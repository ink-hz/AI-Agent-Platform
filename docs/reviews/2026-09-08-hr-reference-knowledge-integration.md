# HR 方法与模型库工程验收

本次范围为独立工作树中的知识来源、发布包、Platform 接入及网页使用。未合并主分支，未发布生产。

## 已验证的后端链路

- 从已提交 Git 内容构建不可变版本目录；校验正文、元数据和 manifest 的身份及哈希一致性。新领域可以按目录和 frontmatter 发现，首批七份资源不是硬性数量上限。
- 通过一次性 PostgreSQL 和真实会话身份执行 HTTP 测试：资源浏览、详情、权限及 CSRF、带资源的新建与续问、幂等比较、历史版本指定、刷新后恢复输入。
- 知识字段纳入预算并进入冻结输入；已有任务重试复用原冻结命令，不能在活动内容版本变化后静默换版。
- 完整应用启动验证了配置到实际 DirectWorker 上下文构造器的注入。默认不启用知识接入。

相关上下文、接口、持久化及 DirectWorker 回归共 80 项通过；后续知识异常映射的相关 4 项通过。新增来源完整性用例先观察失败，再修复并通过来源与 HTTP 相关测试。现有会话 API 测试报告 44 条 TestClient cookie 弃用告警，不是本次新增失败。

## 最终评审发现与修正

最终整体评审发现，最初前端把 revision 当作字符串，而后端使用正整数；独立前端模拟数据也使用字符串，未暴露问题。使用真实应用 API 的浏览器预览复现了“方法库暂时无法读取”。因此，前端通过自身模拟测试并不构成前后端契约一致的证据。

另一处问题是从非对话页面选择方法时，所选资源可能保存在错误的页面状态键下，返回之前的对话后丢失。两项已在 `3e3637b` 修复：前后端统一为正整数版本号，使用真实后端形状的测试数据；选择目标按实际保留的对话或新对话解析，并直接呈现对应输入区。详情请求返回顺序也已处理，避免旧请求覆盖新选择。针对性复审无剩余 Critical / Important 问题。

## 前端及浏览器验收

修复后的 7 个相关前端测试文件共 115 项通过，生产构建通过。构建仍提示既有 chunk 大小建议，测试环境存在既有 Node localStorage 实验性提示。

随后使用新构建与真实应用 API 做一次关键页面复验：

- 方法库正确加载，筛选按钮状态变化，单篇详情显示正整数版本 1。
- “带着这个方法讨论”关闭面板、在输入区显示所选方法和版本，不自动发出消息；移除后标签消失。
- 先打开已有对话，再转到“全景分析”并选择方法，页面回到同一对话且保留选择。
- 检查桌面抽屉布局；使用合成短正文，不据此宣称真实长文及移动端排版均已验收。

预览由自有测试进程提供，完成后已关闭浏览器测试页并正常释放一次性环境，完整应用测试返回通过。没有向生产或真实 Agent 发送业务消息。本轮未新增真实进程故障试验；重试证据来自相关上下文与持久化测试，不能代替生产进程恢复验收。
