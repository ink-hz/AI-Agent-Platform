# HR 全景分析 V2 交付计划

**目标：** 在现有全景采集、版本、证据和失败隔离底座上，交付 10 家重点公司、社招/校招分轨、岗位筛选和 Excel/PDF 下载，不另建爬虫或任务系统。

## Task 1：10 家公司目录与历史线索池

- 新增前端可审计的重点公司目录，保存已核验的官方招聘入口或明确标注的公开招聘平台入口。
- 页面始终显示 10 家重点公司；已持久化的显示“已关注”，缺失的显示“待添加”。
- 提供“一键补齐重点公司”，复用现有幂等 `addCompany` API，单家公司失败不回滚其他成功项。
- 影石、华为显示在“历史会话线索”中，仅供确认，不自动加入采集范围。
- 测试：目录完整、重复公司不添加、部分失败可重试、添加后自动选中。

## Task 2：社招/校招和岗位明细视图

- 在报告中增加总览、社招、校招、产品与业务方向、岗位明细、来源证据六个视图。
- 依据公开岗位标题、职责、要求和来源 URL 做确定性分轨；无法判断的进入“待确认”，不得算作社招或校招。
- 支持公司、招聘类型、地点、技术方向和状态筛选；切换视图不清空筛选。
- 采集提示明确要求每家公司分别核验社招、校招/应届/实习，并报告“未发现”或“采集失败”，不得解释为没有招聘。
- 测试：10 家校招不是单家公司专题、筛选准确、事实/推断/未知保持分离、首次报告不虚构同比。

## Task 3：Excel 与 PDF 下载

- 增加 owner-scoped 报告导出接口；导出内容只能来自不可变报告版本和当前显式筛选。
- Excel 包含公司、招聘类型、岗位、地点、技术方向、状态、观测时间、来源 URL 和证据状态。
- PDF 包含口径、版本、事实、推断、未知项和主要来源；中文字体不可用时应明确失败，不生成乱码文件。
- 下载使用附件响应，不暴露对象存储定位符；失败不影响页面查看。
- 测试：内容类型、文件名、owner 隔离、筛选一致性和 URL 证据完整。

## Task 4：组合验收与发布

- 跑全景现有单元、契约、数据库和前端验收，再跑完整 HR 套件与生产构建。
- 真实浏览器检查 10 家目录、社招/校招切换、岗位筛选、PDF/Excel 下载和岗位 Agent 的“本次参考”。
- 只发布 Platform HR 相关代码；不修改其他应用或共享 Nginx。
- 按既定磁盘门禁记录发布前后 `df -B1 / /data`、版本、回滚、镜像、staging 和 HTTP 验收。
