## 5. TDD 纪律与证据格式

每个任务列出的多个场景应逐个循环，不一次写完全部实现。首次缺模块导致 ImportError 只是脚手架检查；补齐接口后必须观察业务断言因旧行为失败，才计为 RED。

每个完成任务在同目录的执行记录追加：
~~~text
Task ID:
候选代码 SHA / 冻结契约 hash:
RED 命令、失败断言、输出摘要:
GREEN 同命令与结果:
相关回归:
进程故障是否执行（若否明确未执行）:
修改文件:
未解决问题:
~~~

数据库测试用现有 tests/test_control_plane_migration.py 的一次性 PostgreSQL fixture，测试连接不得来自生产环境变量。并发测试用 Barrier/Event 和受控时钟，不用 sleep(300)；进程测试必须是真实进程，不把服务对象重建当 kill/restart。

测试样例中的 fixture 只承担生成测试数据和调用真实仓储，不能用内存状态机伪造数据库互斥、提交和恢复。传输/模型可模拟，授权、事件账本、JSON解析、Result投影必须用实际实现。
