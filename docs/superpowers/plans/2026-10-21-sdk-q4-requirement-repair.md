# 2026 Q4 SDK 禅道需求修复实施计划

**目标：** 把现有 67 条禅道需求按原 Excel Q4 工作表重新呈现为可追溯的待评审计划项。

**实现：** 独立修复工具解析指定工作表、生成预览、核对现有禅道故事、经原生“变更需求”API 修改正文并逐条回读。来源备注由受条件保护的数据库事务更新。工具默认只读，保存备份和执行回执，不改变 SDK 或行政服务入口。

1. 测试先行：用最小 Excel 测试指定工作表、行号、栏目、超链接与 Q3 排除；再实现解析器。
2. 测试先行：对完整信息与模糊任务分别测试正文和来源备注；再实现格式化器，禁止哈希进入正文。
3. 测试先行：模拟禅道读取、冲突、编辑和回读，验证 67 条严格匹配、字段保护和断点续跑；再实现执行器。
4. 用原工作簿生成只读预览，人工抽查 Android Wrapper、带日期/风险的任务、带链接的任务；运行相关后端测试。
5. 在线保存 Excel、旧故事逐条快照和 MariaDB 转储；检查转储可读性。
6. 单条受控更新 Android Wrapper 并回读；确认禅道普通编辑接口的字段副作用后改用“变更需求”接口，保护负责人、标题和评审状态。再处理其余条目，发现差异立即停止。
7. 根据更新后的 67 条故事生成来源备注 SQL，逐条精确匹配身份和版本，在单一事务内写入；异常整体回滚。重启禅道容器刷新长驻 PHP 进程。
8. 全量只读核对 67 条和 8 个链接，检查禅道、SDK 入口与行政服务的 HTML、JS 和 CSS，记录生产回执和剩余待澄清信息。
