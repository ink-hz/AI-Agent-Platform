# 删除数据飞轮占位页设计

## 背景

平台曾实现独立的 `FlywheelPage`，后续导航重构删除了该页面，并将 `/admin/operations` 替换为没有真实数据交互的占位页。当前管理中心仍展示“数据飞轮”入口，用户点击后会误以为已经完成的功能发生故障。

本次不恢复旧版数据飞轮，也不新建数据飞轮功能。目标是删除误导性的占位入口，同时保护仍被其他页面使用的 Operations 能力。

## 用户体验

- 管理中心导航不再展示“数据飞轮”。
- `/admin/operations` 不再作为产品页面存在；访问该历史地址时，保留查询参数并跳转到 `/admin`。
- `/flywheel` 作为更早的历史地址，同样保留查询参数并跳转到 `/admin`。
- 页面标题、路由解析和导航状态中不再保留 `admin-operations` 产品路由。

## 变更范围

前端只修改以下职责：

1. 从管理中心导航删除 `/admin/operations`。
2. 从路由类型、解析和路径生成逻辑删除 `admin-operations`。
3. 将 `/admin/operations` 和 `/flywheel` 统一解析为指向 `/admin` 的兼容重定向。
4. 从页面分发逻辑删除 Operations 占位页。
5. 更新路由、导航和标题相关测试，锁定上述行为。

## 明确保留

本次不删除、不重命名、不调整以下能力：

- `/api/operations/*` 后端接口。
- Operations repository、scheduler、source、rules 和 service。
- 管理总览中的 Daily Brief 和 Operations 轮询。
- Agent 详情页的运行事件与运行记录能力。
- 数据库、同步任务、云端副本与部署配置。
- FAE 工作台及其他管理中心页面。

## 兼容与错误处理

历史链接不返回 404，也不进入空白页。客户端通过现有 `legacy-redirect` 机制跳转到 `/admin`，原查询字符串继续保留。鉴权和角色控制沿用管理中心现有规则，不新增权限路径。

## 并行开发安全

- 所有修改在 `chore/remove-operations-placeholder` 独立 worktree 中完成。
- 分支以创建时最新本地 `master` 为基线，包含其他会话已提交的改动。
- 不修改其他 worktree、分支和共享目录中的未跟踪文件。
- 合并前重新同步最新 `master`；如目标文件发生并行修改，先人工合并并重新验证，不覆盖对方改动。

## 验证标准

- 路由测试证明 `/admin/operations` 与 `/flywheel` 均重定向到 `/admin`。
- 导航测试证明管理中心不再出现“数据飞轮”。
- 页面分发和文档标题测试中不再存在 `admin-operations`。
- 前端完整测试通过。
- 前端生产构建通过。
- `git diff --check` 通过，且变更中不包含后端、数据库或其他会话文件。

## 发布边界

实现完成后只提交并合并代码；推送远程和云端部署属于独立步骤，未获得明确授权时不执行。
