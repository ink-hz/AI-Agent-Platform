# 禅道静态资源重复下载修复设计

## 已核实的问题

`/sdk/` 切换时，代理在所有禅道响应上添加 `Cache-Control: no-store`。禅道自身给 CSS/JS/图片提供最长 7–30 天的缓存头，但代理新增的 `no-store` 使浏览器反复下载同一资源。线上日志中，`zui.zentao.css`、`zin.js`、图标字体等在连续页面访问期间各被取回约 11 次；单个 `/sdk/js/` 请求的服务器记录中位耗时约 0.17 秒。禅道本机读取代表性 CSS 约 1 毫秒。代理对每个静态请求也执行平台会话和 SDK 准入子请求，其中身份数据库查询新建连接的中位耗时约 14.5 毫秒。

## 方案

只在 `/sdk/` 代理响应中按路径区分缓存：`/sdk/js/`、`/sdk/css/`、`/sdk/static/`、`/sdk/theme/` 返回 `Cache-Control: private, max-age=86400`；其他禅道页面和接口继续 `no-store`。隐藏禅道上游的 `Cache-Control`、`Expires`，避免冲突的重复缓存指令。`auth_request /_sdk_access` 保持原样，所有到达服务器的请求继续核对当前平台会话、账号绑定和 SDK 准入；浏览器命中私有静态缓存时无需重复请求。旧 IP 入口、行政服务和其他平台路由不修改。

选择 1 天的私有浏览器缓存，是为兼顾页面切换速度与静态文件更新。连接池等服务端优化要改身份数据访问架构，当前量测的瓶颈先由静态文件重复下载解释，本轮不修改实时授权链路。

## 验收

- 配置契约测试先失败再通过：静态路径与动态路径缓存策略不同，SDK 代理仍保留 `auth_request`。
- 隔离 Nginx 容器从实际线上配置生成候选并验证语法及响应头：静态资源仅有 `private, max-age=86400`；HTML 仍为 `no-store`；未认证仍跳登录，敏感 API 仍为 403。
- 上线前备份并比对现行配置，生产只执行默认完整 `nginx -t`；上线后核对行政服务完整静态资源哈希、SDK 入口、权限日志及 Nginx 临时目录属主。浏览器真实交互验收由业务方执行。
