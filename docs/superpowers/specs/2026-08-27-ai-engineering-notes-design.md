# AI 工程笔记设计

日期：2026-08-27

## 1. 背景

平台需要增加一个面向全体企业员工的 AI 工程文章入口。文章由公司 AI 工程变革负责人持续撰写，目标是通过技术文章帮助员工学习 AI、Agent、LLM、RAG、架构设计和工程实践。

个人仓库 `~/Developer/personal/starship-blog-source` 中已有 41 篇 Markdown 文章，其中 14 篇已发布文章带有 `AI技术` 标签，可以作为后续迁移候选。旧文章不能直接复制上线：其中带有上一家公司的组织语境和时间印记，迁移时还必须逐篇检查名称、项目、人员、链接、语气和易变化的技术事实。页面基础设施必须先完成，文章清洗与迁移随后逐篇进行。

功能正式名称为 **AI 工程笔记**。

## 2. 目标

- 在平台顶级导航中提供清晰、克制的 `AI 工程笔记` 入口。
- 用左侧分类文件树和右侧 Markdown 阅读器承载文章。
- 支持长篇中文技术文章、GFM、代码高亮、表格和 Mermaid。
- 复用现有企业登录，让所有已登录员工可读，未登录用户不可获取文章正文。
- 用仓库内 Markdown 和 Git 管理内容，不引入数据库或后台编辑器。
- 为后续逐篇清洗、审核和发布旧文章建立严格内容门禁。
- 将该功能的失败隔离在自身边界内，不影响 Agent 大脑、专业 Agent 或管理中心。

## 3. 非目标

首期不包含：

- 旧文章的实际迁移和批量发布；
- 首页推荐卡片、营销文案、学习路径或课程系统；
- 在线编辑器、富文本编辑、审批后台或数据库存储；
- 点赞、评论、收藏、阅读进度、阅读统计或推荐算法；
- 全文检索；
- 多作者管理；
- 未登录公开阅读；
- 自动从个人博客仓库同步内容。

## 4. 产品信息架构

### 4.1 导航与路由

顶级产品导航在 `Agent 大脑` 和 `专业 Agent` 之外增加 `AI 工程笔记`。

- 入口：`/ai-notes`
- 文章深链接：`/ai-notes/{category_slug}/{article_slug}`

路由支持浏览器刷新、前进、后退、复制和同事间分享。文章深链接进入后，左侧目录自动展开所属分类并高亮当前文章。

Agent 大脑首页主体保持不变，不增加文章推荐卡片或宣传区域。

### 4.2 页面布局

桌面端使用全高双栏布局：

- 左侧固定宽度目录栏；
- 右侧自适应 Markdown 阅读区；
- 目录栏内部滚动，文章区域独立滚动；
- 页面延续现有平台的浅色视觉变量、边框、字号和顶部导航，不引入新的营销视觉语言。

左栏包含：

- `AI 工程笔记` 标题；
- 已发布文章数量；
- 只匹配文章标题和文件显示名的搜索框；
- 可折叠的一级分类；
- 分类下的文章文件；
- 当前文件高亮；
- 每个分类的已发布文章数量。

右栏包含：

- 简洁路径，例如 `Agent 架构 / Agent 系统手册.md`；
- 文章标题；
- 平台发布日期、更新时间、标签和派生阅读时长；
- Markdown 正文。

窄屏下，目录收进可打开的抽屉。文章阅读区占满可用宽度。抽屉必须可通过键盘关闭，并在关闭后把焦点交还给目录按钮。

### 4.3 分类

左侧树是人工维护的主分类，不由标签自动生成。首期只支持一级分类和二级文章，不支持更深嵌套。每篇文章只属于一个主分类，但可以拥有多个标签。

初始分类为：

1. 基础与原理
2. Agent 架构
3. 工具与框架
4. AI 工程实践
5. 思考与方法

分类顺序和文章顺序由目录及文件的数字前缀控制；数字前缀不出现在界面和 URL 中。

## 5. 内容存储与模型

### 5.1 存储位置

线上唯一内容源位于平台仓库：

```text
backend/app/ai_notes/content/
├── 01-foundations/
│   ├── _index.md
│   ├── 01-agent-system-handbook.md
│   └── 02-ai-llm-architecture.md
├── 02-agent-architecture/
├── 03-tools-and-frameworks/
├── 04-ai-engineering/
└── 05-thinking-and-methods/
```

个人博客仓库不是运行时依赖，也不是部署输入。迁移时把单篇源稿复制到平台仓库后独立清洗；原仓库保持不变。

### 5.2 分类元数据

每个分类目录必须包含 `_index.md`，其 frontmatter 为：

```yaml
---
title: 基础与原理
slug: foundations
---
```

分类正文为空。`slug` 必须匹配 `[a-z0-9][a-z0-9-]{0,63}`，并在全部分类中唯一。

### 5.3 文章元数据

每篇文章必须使用以下 frontmatter：

```yaml
---
title: Agent 系统手册：从概念到工程实践
slug: agent-system-handbook
description: 系统梳理 Agent 的核心闭环、运行时、工具、安全和评估。
publishedAt: 2026-08-27
updatedAt: 2026-08-27
tags:
  - Agent
  - 架构设计
draft: false
---
```

约束如下：

- `title`、`slug`、`description`、`publishedAt` 和 `draft` 必填；
- `updatedAt` 和 `tags` 可选；
- 文章 `slug` 必须匹配 `[a-z0-9][a-z0-9-]{0,127}`，并在所属分类中唯一；
- `publishedAt` 不得早于 `2026-05-25`，也不得晚于执行发布校验的当天；
- `updatedAt` 不得早于 `publishedAt`；
- 未准备发布的内容使用 `draft: true`，而不是未来日期；
- 阅读时长由后端根据正文规模派生，不由作者维护；
- 草稿不进入公开给员工的运行时索引，也不能通过深链接读取。

数字文件名前缀只控制显示顺序。URL 使用 frontmatter 中的稳定 `slug`，调整排序不会改变链接。

## 6. 后端设计

### 6.1 模块边界

新增独立 `backend/app/ai_notes/` 模块，至少分为：

- 内容模型与 frontmatter 校验；
- 文件系统仓库与目录索引；
- 内容发布校验器；
- 认证 API 路由。

模块不依赖 PostgreSQL、Operations SQLite、个人博客仓库或外部 CMS。

### 6.2 内容加载

仓库在应用启动或首次访问时扫描内容目录并生成只读内存索引。扫描规则：

- 只接受预期分类目录、`_index.md` 和 `.md` 文章；
- 拒绝符号链接；
- 拒绝未知文件类型、重复 slug、无分类元数据和不合法 frontmatter；草稿也必须结构合法；
- 请求参数从不直接拼接为文件路径；
- 文章读取只通过预构建的 `(category_slug, article_slug)` 白名单映射；
- 任意已部署分类或文章（包括草稿）不合法时，整个 AI 工程笔记功能进入 unavailable 状态并返回 503，但平台其他模块继续启动和服务。

内容随平台部署更新。生产环境不监听文件变化；内容变更通过正常测试、构建和应用重载生效。

### 6.3 API

`GET /api/v1/ai-notes`

返回已发布目录树：

```json
{
  "categories": [
    {
      "slug": "foundations",
      "title": "基础与原理",
      "articles": [
        {
          "slug": "agent-system-handbook",
          "title": "Agent 系统手册：从概念到工程实践",
          "description": "系统梳理 Agent 的核心闭环、运行时、工具、安全和评估。",
          "published_at": "2026-08-27",
          "updated_at": "2026-08-27",
          "tags": ["Agent", "架构设计"],
          "reading_minutes": 35
        }
      ]
    }
  ]
}
```

`GET /api/v1/ai-notes/{category_slug}/{article_slug}`

返回目录元数据中的同一组文章字段，以及原始 Markdown 正文。不存在、草稿或不合法 slug 均返回 404；内容模块不可用时返回 503。

API 响应遵循现有认证响应的 `no-store` 策略，不允许共享缓存保存内部文章正文。

### 6.4 认证与授权

- 页面 Shell 和两个 API 都复用现有 DingTalk 企业登录与 `IdentitySecurityMiddleware`；
- 全部已认证角色，包括 `member`、`management_viewer`、`platform_admin` 和 `platform_owner`，均可读取；
- 未认证请求返回 401，不能通过前端静态资源获得文章正文；
- 文章正文不得编入登录页可访问的 JavaScript bundle 或其他公开静态资源；
- 首期没有文章写接口，不需要 CSRF 变更面。

## 7. 前端设计

### 7.1 组件边界

新增聚焦的组件：

- `AiNotesPage`：页面数据与路由协调；
- `AiNotesTree`：分类、搜索、折叠、选中和窄屏抽屉；
- `AiNoteArticle`：元数据和长文布局；
- `ArticleMarkdown`：安全 Markdown、代码、表格、链接和 Mermaid 渲染；
- `aiNotesApi` 与类型校验：目录和正文 API 客户端。

聊天使用的 `MessageMarkdown` 继续服务短消息。文章阅读器共享必要的安全原则，但使用独立组件和长文样式，避免聊天与文章需求互相耦合。

### 7.2 Markdown 渲染

- 基于现有 `react-markdown` 和 `remark-gfm`；
- 不启用原始 HTML 渲染；
- 代码块根据语言标识执行本地语法高亮；
- `mermaid` 代码块延迟加载本地 Mermaid 包并使用严格安全模式；
- Mermaid 单图失败时显示该图的源码和“图表暂时无法渲染”，不隐藏文章其他内容；
- 表格在窄屏横向滚动；
- 标题生成稳定锚点，并支持文章内链接；
- 外部链接标识为外部目标，使用 `target="_blank"` 与 `rel="noopener noreferrer"`；
- 拒绝 `javascript:`、`data:` 等危险协议；
- 不从第三方 CDN 加载脚本、样式或字体。

### 7.3 状态与导航

- `/ai-notes` 默认打开目录中的第一篇已发布文章；
- 没有文章时显示 `暂无已发布文章`；
- 搜索只过滤客户端已取得的标题、显示文件名和分类名；
- 搜索无结果时显示 `没有匹配的文章`，不改变当前正文；
- 目录加载失败时显示功能级失败状态；
- 从一篇文章切换到另一篇失败时保留上一篇已成功正文，并显示非阻塞错误；
- 深链接 404 时保留目录并显示文章不存在，用户可选择其他文章；
- 浏览器前进和后退同步选中状态、展开状态与正文；
- 当前展开分类可保存在页面会话状态，首期不写本地持久化存储。

## 8. 内容清洗与发布门禁

旧文章迁移不属于本阶段实现，但发布基础设施必须支持以下流程：

1. 从个人博客复制一篇候选原稿，默认设置 `draft: true`；
2. 扫描上一家公司名称、域名、项目、人员、客户、内部链接和特定措辞；
3. 清除或重写旧组织语境，不把旧日期当作当前公司内部发布日期；
4. 核对易变化的技术事实，优先使用官方文档和一手来源；
5. 更新标题、摘要、标签、分类、代码和 Mermaid；
6. 运行内容校验和完整平台测试；
7. 本地预览长文、表格、代码、链接和图表；
8. 由内容负责人确认；
9. 设置当天的 `publishedAt`、更新 `draft: false`，再随平台发布。

仓库维护版本化的旧组织标记拒绝清单。当前页面基础阶段可以是空清单；首次文章迁移前必须补充已识别的旧公司名称、域名、项目代号和其他禁止标记。发布校验对非草稿正文、frontmatter 和链接执行大小写不敏感扫描，命中即失败。拒绝清单本身不发送到前端。

## 9. 错误隔离

- AI 工程笔记内容初始化失败只禁用自身 API 和页面，不使平台健康接口、Agent 大脑、专业 Agent 或管理中心失败；
- 目录 API 失败不伪造空目录，页面明确显示暂时不可用；
- 文章切换失败保留上一份成功正文，防止阅读内容突然消失；
- Mermaid 失败降级为单图源码，不影响文章；
- 无内容是合法空状态，不记录为平台故障；
- 错误响应和日志不得包含 Markdown 正文、绝对文件路径或拒绝清单内容。

## 10. 测试与验收

### 10.1 后端

- 合法分类与文章生成稳定、有序的目录树；
- 数字前缀影响顺序但不进入标题和 URL；
- 重复 slug、无效 frontmatter、错误日期和更新时间被拒绝；
- `publishedAt < 2026-05-25` 或晚于校验当天被拒绝；
- 草稿不进入目录，并且深链接返回 404；
- 符号链接、路径穿越、编码绕过和未知文件被拒绝；
- 请求只读取白名单索引中的文章；
- 所有已认证角色可读，匿名请求不可读；
- 内容模块 503 与平台其他 API 隔离；
- 日志和错误不泄露正文、绝对路径或旧组织拒绝清单；
- 发布校验能发现旧组织标记和危险链接。

### 10.2 前端

- 顶级导航和路由解析正确；
- `/ai-notes` 默认文章选择正确；
- 深链接、刷新、前进和后退正确同步；
- 目录折叠、文章数量、选中态和跨分类标题搜索正确；
- 空目录、无搜索结果、目录失败、文章 404 和切换失败状态正确；
- 切换失败保留上一份正文；
- Markdown 标题、列表、引用、表格、代码和中文长文正确渲染；
- 原始 HTML、脚本标签和危险链接不能执行；
- Mermaid 成功渲染，单图失败正确降级；
- 外部链接具有安全属性；
- 窄屏目录抽屉支持键盘、焦点回交和关闭；
- 文章正文不出现在公共登录 Shell 或无需认证即可取得的前端资产中。

### 10.3 首期上线验收

- 页面可以在零篇已发布文章的情况下上线并显示合法空状态；
- 生产内容目录只包含五个初始分类元数据，不包含未经清洗的博客文章；
- 不迁移任何个人博客文章，不修改个人博客仓库；
- 不新增数据库迁移、内容写 API 或后台编辑器；
- 平台现有测试、前端构建和身份授权测试保持通过。

## 11. 实施顺序

本设计对应一个页面基础设施实施计划：

1. 内容模型、目录仓库和发布校验；
2. 认证 API 与 Shell 路由；
3. 前端路由、目录树和空状态；
4. 长文 Markdown、代码和 Mermaid；
5. 响应式、可访问性和错误保留；
6. 安全、构建与回归验收。

页面基础验收完成后，再为 14 篇候选文章建立独立的清洗与迁移计划，逐篇审核和发布。
