# Agent 大脑统一对话工作区设计

> 执行架构说明：本文继续作为 Web 持续对话工作区的 UI 设计。本文中“沿用现有
> Agent 执行协议”的假设，已由
> `2026-08-24-cloud-agent-brain-durable-loop-design.md` 取代；实现不得因此继续
> 依赖 V1 `planning -> professional -> synthesis` 或本地 `agent-brain-bot` 主链路。

## 目标

Agent 大脑是产品默认使用入口，不是任务创建页，也不是管理看板。用户进入平台后应停留在一个持续工作的对话界面中：左侧选择 Session，右侧继续当前 Session。历史记录是工作区导航的一部分，不再是独立页面。

本文只定义 Web 使用体验，沿用 Conversation、Message、Turn、SSE、权限和加密
边界，不修改 FAE。Agent 执行协议及 Mission 的后续演进由云端持久化 Loop 设计
定义，不再由本文冻结。

## 已选方案

采用 DeepSeek/ChatGPT 式统一工作区。

```text
┌────────────────────────────────────────────────────────────────────┐
│ Orbbec Agent Platform       专业 Agent   企业账号   管理中心   用户 │
├──────────────────┬─────────────────────────────────────────────────┤
│ ＋ 新对话         │ Agent 大脑                         当前对话标题 │
│                  │                                                 │
│ 今天             │               消息时间线                        │
│  当前 Session    │                                                 │
│  另一个 Session  │                                                 │
│                  │               执行过程（默认折叠）              │
│ 更早             │                                                 │
│  …               │  ┌───────────────────────────────────────────┐  │
│                  │  │ 输入消息……                          发送 │  │
│ 加载更早对话     │  └───────────────────────────────────────────┘  │
└──────────────────┴─────────────────────────────────────────────────┘
```

不采用以下方案：

- 独立“历史对话”页面：会打断对话工作流，已被本次需求明确否决。
- 弹窗或下拉历史：无法承载较多 Session，也不利于快速切换。
- 每轮生成一条历史任务：破坏一个 Session 对应一段持续对话的基本模型。

## 信息架构与路由

- `/`：统一工作区，右侧是尚未创建 Session 的新对话状态。
- `/conversations/{conversation_id}`：同一个统一工作区，右侧选中并持续该 Session。
- `/conversations`：兼容旧链接，立即替换为 `/`，不再渲染独立历史页面。
- `/missions/{mission_id}`：仅保留诊断深链，不进入普通导航。
- `/agents` 与 `/agents/{agent_id}`：保留专业 Agent 目录和启动入口；启动后进入统一工作区中的对应 Session。
- `/admin/*`：继续作为管理中心，与使用工作区隔离。

顶部产品导航删除“历史对话”。Agent 大脑入口始终指向 `/`。点击品牌标识或 Agent 大脑时回到新对话状态，不创建空 Session。

## 桌面端交互

### 左侧 Session 栏

- 固定在 Agent 大脑工作区左侧，建议宽度 280px，拥有独立滚动区域。
- 顶部是高识别度的“＋ 新对话”按钮。
- Session 按 `updated_at` 逆序排列，最新在最上面。
- 每条只显示一行标题、更新时间；专业 Agent 对话增加轻量 Agent 标签。
- 当前 Session 有明确选中态，不使用“可继续”等无信息价值文案。
- 点击 Session 只切换右侧内容并更新 URL，不进行整页刷新。
- 使用现有游标分页；底部“加载更早对话”在左栏内完成，不跳页。
- 创建首轮或发送追问后，立即在本地将该 Session 移到列表顶部，再用服务端结果校准。
- 左栏读取失败时只显示局部重试，不阻断右侧当前对话或新对话。

第一版不增加搜索、分组重命名、置顶和文件夹，避免把工作区再次做成管理工具。

### 右侧新对话状态

- 页面中心显示“Agent 大脑”和一句简短能力说明，下面直接是输入框。
- 示例提示可以保留，但不再在输入框下方展示“最近对话”。
- 用户发送第一条消息后创建一个 Conversation，URL 使用 `replaceState` 变为 `/conversations/{id}`；视觉上仍停留在同一个工作区。
- 空白状态点击“新对话”不会提前创建数据库记录，只有首条消息成功接受后才产生 Session。

### 右侧持续对话状态

- 顶部仅展示当前 Session 标题和 Agent 身份，不出现“返回历史对话”。
- 中间是同一 Session 的完整消息时间线，Markdown 正常渲染。
- Agent 大脑与子 Agent 的分发、执行和结果继续显示在默认折叠的执行卡片中。
- 输入框固定在右侧底部；每轮完成后仍然可输入下一条消息。
- 发送追问不会创建新 Session，也不会导航到 Mission 页面。
- 新消息提交后自动滚动到底部；若用户主动向上阅读，则显示“回到最新”而不强制抢夺滚动位置。
- 运行中允许停止当前 Turn；连接中断继续沿用 SSE 序号恢复，不重复创建 Turn。

## 移动端交互

- 默认只显示右侧对话区，顶部提供“对话列表”按钮和“新对话”按钮。
- “对话列表”打开左侧抽屉，抽屉覆盖页面并带遮罩；选择 Session 后自动关闭。
- 抽屉不改变当前 Session 的消息或输入草稿。
- 输入框固定在可视区域底部并避开移动端安全区；键盘弹出时不遮住发送按钮。
- 浏览器返回遵循 URL 历史；从 Session A 切到 Session B 后可返回 A。

## 组件边界

新增统一容器 `BrainWorkspacePage`，负责组合而不复制业务逻辑：

- `ConversationSidebar`：加载、分页、选择与本地 upsert Session。
- `NewConversationPanel`：承接现有 `BrainPage` 的首轮提交能力。
- `ConversationThread`：承接现有 `ConversationPage` 的消息、SSE、追问、停止、反馈和执行卡片能力。
- `BrainWorkspaceContext` 或容器状态：协调新建、选中 Session、列表置顶和移动抽屉，不存储服务器权威身份或权限。

`ConversationsPage` 停止作为产品页面使用并删除其导航入口。可复用其中的时间格式和游标合并逻辑到 `ConversationSidebar`，避免维护两套 Session 列表。

## 数据流

1. 进入 `/` 或 Conversation 深链时并行读取账号和第一页 Session 列表。
2. 深链存在时，右侧独立读取该 Conversation、Messages 与 SSE；左栏失败不影响右侧。
3. 首轮提交成功后，将返回的 Conversation upsert 到左栏顶部并替换 URL。
4. 追问成功后，保持 Conversation ID，更新当前 Turn，并把该 Session 移到左栏顶部。
5. SSE 终态后重新读取 Messages 与 Conversation 快照；不创建新的历史条目。
6. 切换 Session 时中止旧 Session 的 fetch/SSE，启动新 Session 的读取，避免串台。

所有权限继续由后端按 `internal_user_id` 与 Conversation owner 校验；浏览器列表不是授权边界。

## 状态与错误

- Session 列表失败：左栏局部错误与“重试”，右侧保持可用。
- 当前 Session 读取失败：右侧明确错误与重试，左栏仍可切换其他 Session。
- 首轮发送失败：保留输入及同一个 Idempotency-Key，允许安全重试。
- 追问失败：保留输入及同一个 Idempotency-Key，不创建新 Session。
- `401`：进入现有企业登录流程，并保留合法 return path。
- `403` 或不存在的 Session：右侧显示无权访问/不存在，不泄露其他用户 Session 信息。
- hard-stale：列表与历史消息可读，所有新建、追问、停止和反馈操作禁用。

## 视觉原则

- 产品入口优先体现“可立即对话”，避免大标题、指标卡片和管理式说明占据首屏。
- 左栏低对比、右侧内容高对比；选中态使用品牌蓝浅底，不使用密集边框。
- 消息区保留充足留白，但减少现有每条消息的厚重卡片感，使长对话更易连续阅读。
- 执行过程默认折叠，既让用户看到 Agent 大脑确实在分发工作，又不挤占答案主体。
- 桌面端工作区使用视口剩余高度；不在对话页底部显示站点 Footer。

## 验收标准

- 登录后访问 `/`，首屏直接出现可输入的 Agent 大脑工作区和左侧 Session 列表。
- 顶部不存在“历史对话”入口，访问 `/conversations` 会回到统一工作区。
- 第一轮发送后不离开工作区，URL 变为 Conversation 深链。
- 同一 Session 连续发送三轮后，左栏仍只有一条对应记录，右侧显示六条用户/助手消息。
- 刷新 Conversation 深链后恢复同一 Session、全部消息和执行状态。
- 在两个 Session 间切换不会串消息、串 SSE 或丢失服务端内容。
- 左栏分页可读取全部 Session，最新 Session 始终在顶部。
- 移动端可通过抽屉选择 Session，并能持续发送消息。
- 普通用户无法读取他人 Session；未授权专业 Agent 仍返回 `403`。
- 前端全量测试和生产构建通过；生产人工验证首轮、追问、切换、刷新和移动端。
- FAE 容器、域名、配置、启动时间和重启次数保持不变。

## 发布与回滚

- 先完成前端测试和构建，再以现有原子部署脚本上线同一提交。
- 后端数据模型不变，不需要数据库迁移或历史数据重写。
- UI 回滚只需部署上一 Platform release；Conversation 数据继续保留。
- 发布前后都核验 FAE 不变性和 Platform 五个服务健康状态。
