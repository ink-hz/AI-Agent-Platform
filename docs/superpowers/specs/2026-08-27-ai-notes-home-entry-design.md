# AI 工程笔记首页入口调整设计

## 背景与决策

现有实现把 `AI 工程笔记` 与 `Agent 大脑`、`专业 Agent` 并列放在产品顶部导航中。该层级过高：Agent 大脑和专业 Agent 是平台的高频工作入口，工程笔记是供员工学习和查阅的次级知识入口，不应长期占用全局导航。

本设计覆盖 `2026-08-27-ai-engineering-notes-design.md` 中“顶级导航增加 AI 工程笔记”和“Agent 大脑首页主体完全不变”两项约定。文章路由、认证 API、内容仓库、左侧分类树和 Markdown 阅读器均保持不变。

## 交互设计

- 从产品顶部导航删除 `AI 工程笔记`。
- 只在 Agent 大脑首页（`/` 且未打开具体对话）显示一个轻量入口。
- 入口位于 Agent 大脑说明文字之后、任务输入框之前。
- 入口文案固定为 `AI 工程笔记 →`，不增加副标题、宣传语、图标、推荐文章或大卡片。
- 入口使用语义化链接，目标为 `/ai-notes`；站内点击沿用现有客户端导航，保留正常的新标签页、复制链接和键盘操作能力。
- 在对话详情页、专业 Agent 页面、管理中心和其他页面不显示该入口。
- `/ai-notes` 和 `/ai-notes/{category_slug}/{article_slug}` 继续使用现有独立阅读工作区；左侧分类树仍是该页面的本地导航。

## 视觉层级

入口是次级操作，视觉权重低于任务输入框和“开始对话”按钮：

- 居中、单行、紧凑尺寸；
- 使用现有品牌链接颜色和清晰的 `focus-visible` 状态；
- 可以有轻微 hover 背景或下划线，但不使用高阴影、渐变、大面积色块或插画；
- 在窄屏下保持可点击尺寸，不改动首页现有内容顺序。

## 组件与数据流

- `AppShell` 的 `USE_NAVIGATION` 删除 AI 工程笔记项；路由 section 类型继续保留 `ai-notes`，因为阅读工作区仍需据此控制全高布局和页脚。
- `BrainPage` 增加可注入的笔记导航回调，默认调用现有 `navigate("/ai-notes")`；测试可传入 spy，避免依赖全局历史状态。
- 入口使用平台现有的前缀路径生成规则，确保根路径和带部署前缀的环境都能得到正确 `href`。
- 点击入口只发生客户端路由跳转，不预取文章目录，不改变 Agent 大脑请求、会话列表或错误状态。

## 错误与边界

- AI 工程笔记 API 不可用时，首页入口仍可点击；目标页继续显示现有模块级不可用状态，不影响 Agent 大脑。
- 当前生产内容仍为 5 个空分类、0 篇文章；本次只调整入口，不迁移文章。
- 已登录角色的访问规则、未登录 401、`no-store` 和正文保密策略不变。

## 验证

- `AppShell` 测试确认所有角色的顶部产品导航不再包含 `AI 工程笔记`。
- `BrainPage` 测试确认首页入口存在、`href` 正确、普通点击调用 `/ai-notes` 导航。
- `BrainWorkspacePage` 测试确认具体对话页面不出现该入口。
- 路由、登录回跳、AI 工程笔记页面和全高阅读布局测试继续通过。
- 前端全量测试和生产构建通过；后端不改动，无需新增后端行为测试。

## 非目标

- 不增加文章推荐、最新文章、阅读进度、角标、未读数或轮播区域。
- 不改变 AI 工程笔记阅读页设计。
- 不迁移或清洗个人博客文章。
- 不执行远端推送或生产部署。
