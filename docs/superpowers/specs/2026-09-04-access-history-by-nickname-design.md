# 访问记录按花名索引设计

日期：2026-09-04  
状态：已确认，进入 TDD 实施

## 1. 目标

把管理中心现有的平铺访问事件表改成面向人员的访问审计页。页面首先回答“谁在使用系统”，再允许所有者展开查看“何时访问了哪个产品、模块和具体页面”。

首期只允许 `platform_owner`（当前为“苍渊”）访问。数据库继续以 `internal_user_id` 作为事实关联键；浏览器界面以企业唯一花名作为人员索引，不显示内部 UUID、Session ID 或钉钉原始标识。

## 2. 已确认的产品形态

默认视图按花名分页，每一行展示：

- 花名；
- 当前有效部门；
- 所选时间范围内的访问次数；
- 最近访问时间；
- 最近访问的产品、模块与页面。

点击人员行后，在原位置展开该人员的访问时间线。时间线按自然日分组，单条事件展示时间、登录或访问类型、产品、模块、具体页面及适用的专业 Agent。

支持按花名、产品、事件类型、开始日期和结束日期筛选。快速连续访问同一页面可以在展示层合并，但底层事件不删除、不覆盖。

## 3. 数据语义

### 3.1 身份与部门

访问事件的主体仍是 `platform_control.user_access_events.internal_user_id`。人员摘要通过当前完整钉钉目录代际关联 `directory_members`、`member_departments` 和 `directory_departments`，返回当前有效部门名称数组。

部门是“当前组织投影”，不是历史快照。员工调岗后，历史访问事件仍保持原时间和原页面事实，但管理页展示该员工当前部门。没有可用目录关系时明确显示“部门未同步”，不能猜测。

### 3.2 页面层级

`access_page_catalog` 是页面语义的唯一权威，新增 `module_display_name`，形成：

```text
workspace_key       -> 产品
module_display_name -> 模块
display_name        -> 具体页面
```

采集端只能提交目录内的固定 `page_key`。禁止提交或保存原始 URL、query、fragment、资源 UUID、Session ID、服务表单内容和用户输入。

已有 v65 事件原样保留。迁移为现有目录行补齐模块名称，并增加必要的固定页面键；不重写历史事件。

### 3.3 花名索引

企业花名在产品规则中唯一。服务端按 `internal_user_id` 聚合，返回花名但不返回内部 ID；展开接口继续使用精确花名筛选。若底层出现违反唯一花名规则的数据，人员摘要不得把两个主体合并，迁移与生产验收必须检查重复花名并显式失败。

## 4. API

保留：

```text
GET /api/v1/manage/access-events
```

事件响应增加 `module_display_name` 和当前 `departments`。它只用于展开某一花名后的时间线，仍支持现有筛选和事件分页。

新增：

```text
GET /api/v1/manage/access-subjects
```

参数与事件接口使用同一时间、产品和事件类型过滤，`display_name` 在人员索引上执行受控包含搜索。响应按最近访问倒序、花名稳定排序，分页单位是人员而不是事件，返回：

```text
display_name
departments[]
event_count
latest_occurred_at
latest_event_kind
latest_workspace_key
latest_module_display_name
latest_page_display_name
latest_agent_id
```

两个接口都执行应用层和 `SECURITY DEFINER` 数据库函数双重 owner 校验，时间范围最多 90 天，分页和返回数量有硬上限。普通成员、管理查看者和平台管理员均为 403。

## 5. 前端交互

访问记录页不再默认渲染大表：

1. 首次加载最近 7 天人员摘要；
2. 点击人员行才读取该花名的事件；
3. 同时只展开一个人，避免一次请求全部明细；
4. 展开时显示独立加载、空状态和失败状态；
5. 日期按 Asia/Shanghai 展示和分组；
6. 移动端使用卡片布局，不依赖宽表横向滚动。

筛选变更会收起当前人员并重新读取人员索引。花名搜索输入只有点击查询后生效，不在每次按键时请求。

## 6. 采集精度

Platform 自有页面补齐 HR 岗位工作台等已经存在的固定路由语义。Office、FAE、VOC 等独立前端继续通过相同的页面访问端点上报，但只能使用 Platform 目录提前登记的页面键。

Office 的具体行政服务只能使用业务代码中固定、公开的服务类型映射为目录键；未知或动态服务 ID 统一落入“其他行政服务”，不得把 query 中的原始 `service_id` 直接写入事件。

本次不采集按钮点击、表单字段、对话内容、附件名、IP、User-Agent 或停留时长。

## 7. 数据库迁移

当前主线最高迁移为 066，本功能使用 067：

- `access_page_catalog` 增加并回填 `module_display_name`；
- 增加固定页面目录项；
- 新增人员摘要读取函数；
- 新增包含模块和部门投影的事件读取函数；
- 重审全部函数执行权限，不授予应用角色表级读取权限；
- 保留 v65 函数作为短回滚窗口，应用切换后使用 v67；
- 生产迁移前检查活动身份花名唯一性。

## 8. 安全与隐私

- 只有平台所有者可读；
- 只展示花名和当前部门，不返回手机号、真实姓名、钉钉 userId 或内部 UUID；
- 不把生产数据编入前端静态资源；
- 页面键来自封闭目录，拒绝任意字符串；
- 日志不得记录筛选结果、Cookie 或事件正文；
- 保留 v65 的 90 天数据留存上限和会话级采集限流。

## 9. 验收

- “苍渊”可看到按花名分页的人员索引并展开时间线；
- 人员行展示当前有效部门，缺失时明确标注未同步；
- 同一花名的事件按日期分组且产品、模块、页面层级正确；
- HR 岗位页与 HR 对话页不再都显示为“HR 工作台”；
- Office 固定服务能显示具体服务页面，未知服务不泄漏原始 ID；
- 筛选、人员分页、事件分页、加载/失败/空状态可区分；
- 非 owner 在路由、API 和数据库函数三层均不可读；
- 响应中不存在内部用户 ID、Session ID、原始 URL、query 或业务内容；
- 历史 v65 数据继续可读；
- 全量后端、前端、迁移、构建和云端验收通过后才允许发布。
