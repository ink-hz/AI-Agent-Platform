# SDK 禅道单点登录设计

## 目标与边界

已通过 AI Agent Platform 钉钉登录、拥有 SDK 工作台成员权限并已绑定个人禅道账号的员工，从 `/sdk/` 一次点击进入自己的禅道会话。未绑定、已失效、只读或无 SDK 权限的身份不得签发票据。禅道继续决定产品、项目和需求权限。现有 `sdk-api` 与 `sdkadmin` 账号不能绑定给员工。

本次完成从平台入口进入禅道的单点登录。禅道直达入口及已创建的禅道会话保持原有行为；平台退出不会立即注销另一个站点的现存会话，单点退出另行设计。

## 选择与理由

采用短时单次票据和服务端禅道会话桥接。让禅道直接进行第二次钉钉 OAuth 会重复配置身份关系；公开 ZenTao `apilogin` 链接的官方时间戳签名不含账号，不能交给浏览器。公网对 `apilogin` 的现有封锁保持有效。

## 组件与数据流

1. 平台所有者用受平台 CSRF 保护的管理 API 将内部用户 UUID 显式绑定到唯一的禅道账号；禁止绑定服务账号和管理员账号。绑定表存于现有 Control DB 的 `sdk` schema。
2. `/sdk/` 调用同源 `POST /api/v1/sdk/sso/start`。平台用钉钉会话中的内部 UUID 和 session ID 检查 SDK 成员权限及绑定，签发 45 秒、随机且仅能使用一次的票据。数据库只保存票据摘要。
3. 浏览器用 HTTPS 表单 POST 将票据送到禅道同源 `/sdk-sso/consume`；票据不出现在 URL、Referer 或访问日志。禅道站点 Nginx 只将该精确路径转发给平台 API。平台 API 原子核销票据，重新检查平台会话、人员状态、SDK 成员资格及当前绑定。
4. 平台 API 从数据库原子分配严格递增的十位时间戳，经内部 Docker 网络调用禅道旧版 `apilogin`。禅道每个应用每秒只接受一个时间戳，不能直接使用当前秒数。密钥只从只读私密文件加载，且不转发浏览器原有的禅道 Cookie。只接受成功的内部跳转和单个合法 `zentaosid`，在禅道 HTTPS 源设置 `Secure; HttpOnly; SameSite=Lax` 会话 Cookie，并 303 跳转到禅道首页。公网继续拒绝任何直接 `apilogin` 请求。

## 失败处理与验收

无登录、无 SDK 权限、未绑定、过期/重放票据、无效 ZenTao 用户、后端不可用均拒绝会话创建。消费失败后的票据不能重试；员工回平台入口重新签发。桥接响应不缓存，禁用跨站 Referer，并屏蔽访问日志中的请求体。账号绑定变更不能使尚未消费的旧票据登录旧账号。

自动测试覆盖签发与核销、CSRF、账号冲突、不同会话、超时、重放、异常 ZenTao 响应及 Cookie 属性；隔离实例验证真实 ZenTao 会话；生产验收只替换平台 API 和 SDK 站点配置，核查行政服务的静态资源和权限日志，不在共享生产机执行独立配置 `nginx -t -c`。
