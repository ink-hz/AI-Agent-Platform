# SDK 工作台真实场景验收与上线设计

日期：2026-10-19。基线为平台 `25c63551`、[首版业务设计](2026-10-19-sdk-development-v1-design.md)和[SDK 试运行说明](../../../deploy/sdk/README.md)。本设计只推进已实现的首版流程，不接入 GitLab 开发事件。

## URL 与部署边界

员工入口定为 `https://agent.orbbec.com.cn/sdk/`；需求详情为 `https://agent.orbbec.com.cn/sdk/requirements/{禅道需求ID}`。API 保持同源 `/api/v1/sdk/`。本地入口沿用现有开发服务：`http://127.0.0.1:5173/sdk/`（Vite）或本地 API 静态服务的 `/sdk/`。禅道本身只在私网服务名 `zentao:80` 和管理员 SSH 隧道的回环端口可达，不给员工单独公开域名。

选同域子路径的理由是现有平台的公开根域、企业会话、CSRF、导航和路由均已支持它，无需第二套登录、证书或 DNS。独立 `sdk.orbbec.com.cn` 会增加跨站会话与代理配置；直接公开禅道会绕过 SDK 专属评审、证据和发布权限。因此首版不采用这两种入口。

正式上线保持“先部署、后启用”：主平台镜像从已合入主线的准确提交构建，默认 `PLATFORM_SDK_WORKBENCH_ENABLED=0`。禅道、MariaDB 用独立 Compose 项目和持久卷运行；仅禅道服务加入平台内部网络。完成安装、服务账号、两项 SDK 数据库迁移、备份与真实接口试验后，再对平台 API 配置服务账号密码文件、产品 ID、执行 ID 和启用开关。SDK 密码使用仅挂载到平台 API 的独立卷，不进入 HR Worker。Nginx 沿用根路径代理，不增加公开禅道路径。

## 测试数据与证据

选择一个真实 SDK 问题，填写设备型号、固件、操作系统、复现步骤和可测量验收标准。候选清单从打包仓库的实际 Git 提交与全部八个子模块路径读取，并记录 `git status` 为干净的证据。构建产物必须来自该清单及所记脚本，记录实际命令、日志 URI、文件大小、SHA-256 和保存位置。单元测试与硬件测试必须有对应产物的真实报告；硬件未到位只能记 `blocked`，不得补写 `passed`。测试专用需求放在隔离禅道实例及其产品中，测试记录不得当成正式 SDK 发布。

每次试验保留：平台提交、禅道版本与镜像 digest、数据库迁移编号、请求 ID、HTTP 状态、禅道需求/任务 ID、候选与证据 ID、最终门槛理由和结果。凭据、Cookie、Token、客户敏感内容不进入仓库或测试报告。首错即停并保存原输入与错误；修复后建立新批次，只重测受影响段及最终串联。

## 真实场景与通过条件

1. **需求到任务**：开发成员通过平台创建真实需求；禅道 API 读回同一 ID、正文与验收标准；评审成员批准当前版本；开发成员创建任务，禅道任务 `story` 与 `execution` 指向预期对象。修改禅道需求版本后，旧评审不能放行新任务。
2. **候选与两平台构建**：冻结真实打包仓库和八个子模块 SHA，规划实际准备发布的 OS/架构。至少登记两个目标时，逐个核对命令、日志和产物摘要；其中一个目标的最近构建失败时门槛关闭，另一目标原证据不被改写。修正构建须产生新证据，不能修改旧行。
3. **测试门槛**：针对最近成功构建的每个产物登记真实单元测试与硬件测试报告。设备缺席、阻塞、失败或跳过均不能审批；通过数、失败数和报告 URI 必须与原报告一致。录入前由人员核对报告对应的产物 SHA；首版平台只保存报告 URI 与构建 ID，不自动解析报告内容。没有真实硬件报告时，本例止于门槛关闭，不填写通过、审批或发布。
4. **审批与追溯**：非候选创建人的发布负责人在证据齐全时审批。审批后新增评审、构建或测试证据应使原审批失效。登记测试发布后，从发布 ID 反查需求、任务、全量源码 SHA、每个产物摘要、报告、审批者和回退说明。测试发布仅代表系统验收，真实业务发布仍须有正式产物与目标渠道。
5. **失败恢复与权限**：无 SDK 成员、错误角色、只读身份、跨产品需求、CSRF 缺失分别被拒绝；相同请求 ID 重放不复制记录、改内容返回 409；禅道写入超时停在待核对，管理员核实实际记录后绑定；确定认证拒绝留下拒绝事件，可在修复凭据后用原请求 ID 重试。禅道停机时 SDK 历史证据仍可读，但不能审批或发布。

## 验收顺序

**本地工程门槛**：在隔离工作树运行 SDK 相关后端 HTTP/真实 PostgreSQL 测试、前端组件测试与构建。随后用独立真实禅道 22.6 实例做 API 形状与全链路试验；本机没有容器引擎时先补齐本地运行条件，或明确标记真实实例试验未执行，不以 MockTransport 结果代替。

**上线前门槛**：核对现行线上发布提交、远端主线、SDK 两项迁移的生产/预览库权限、数据库与禅道备份、镜像 digest、服务账号最小权限、Nginx 代理和回退点。新版平台先以 SDK 开关关闭的状态发布并做原平台回归；随后在可回退的配置变更中启用 SDK。真实登录/角色与核心 API 通过后，才向用户开放 `/sdk/`。

**页面验收**：按仓库 `AGENTS.md`，浏览器连接和最终页面验收由用户执行。开发侧给出明确 URL、角色、试验记录和检查项；未收到页面验收结果时，报告“接口/服务已验收，页面待验收”，不写“业务闭环已上线可用”。

## 中止与回退

任一前置或真实接口门槛失败，保持 SDK 开关关闭，不触碰现有其他工作台。启用后若 SDK 接口、权限或数据追溯失败，先关闭该开关并回到已记录的平台发布提交；禅道与 SDK 数据库保留供诊断，不删除证据。不得用假测试结果、伪造硬件报告或直接更新证据行让发布门槛变绿。
