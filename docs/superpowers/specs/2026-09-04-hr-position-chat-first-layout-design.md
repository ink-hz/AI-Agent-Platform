# HR 岗位详情页对话优先重构设计

**日期：** 2026-09-04  
**状态：** 已确认，待实施  
**范围：** HR 智能工作台中的单个岗位详情页

## 1. 背景与问题

当前岗位详情页把岗位摘要、岗位 ID、三项统计、四个业务页签、五个快捷任务、任务恢复状态、对话历史侧栏和材料侧栏同时放在首屏。虽然底层功能已经接入，但页面层级混乱，对话宽度不足，空数据与接口异常提示会重复出现，用户无法把它当作日常 HR Agent 工作入口。

本设计从一个真实工作场景出发：招聘负责人打开一个岗位，围绕该岗位持续与 HR Agent 对话，按需上传材料、生成正式成果、查看候选人，并在刷新或长任务执行期间保持上下文连续。

## 2. 设计目标

- 岗位详情打开后立即进入可用的持续对话。
- 对话、长回答、表格和生成成果拥有足够的横向空间。
- 岗位事实作为 Agent 上下文存在，但不以仪表盘压过对话。
- JD、JR、人才画像、搜寻策略和面试方案容易发现，但不常驻占用首屏。
- 材料、候选人和成果按需查看，不形成常驻三栏布局。
- 空数据、局部异常和整体异常有清晰且互不混淆的恢复方式。
- 复用现有 Position、Conversation、Attachment、Candidate 和 HR R1.2 服务，不新增招聘事务系统能力。

## 3. 明确不做

- 不新增 ATS 流程、审批、排期、Offer 或入职功能。
- 不新增岗位仪表盘、招聘漏斗或统计卡片。
- 不展示 Mission、Run、Trace、Adapter、数据库状态或内部状态码。
- 不增加新的外部系统、权限模型或数据同步链路。
- 不重写现有 Conversation、附件、任务恢复和下载底座。

## 4. 页面信息架构

### 4.1 全局工作台栏

保留独立 HR 工作台顶部栏，只显示：

- HR 智能工作台品牌；
- “对话”和“岗位”两个全局入口；
- 当前用户身份。

不展示授权人数、技术状态或管理信息。

### 4.2 紧凑岗位栏

岗位栏固定在全局栏下方，单行承载：

- 返回岗位列表；
- 岗位名称；
- 部门和地点；
- 业务状态；
- “岗位资料”；
- “新对话”。

官网岗位 ID、对话数、材料数和成果数不在首屏展示。它们只在确有业务价值的资料视图中出现，零值不形成统计卡片。

### 4.3 主对话区

主内容只有岗位对话。桌面端正文和输入区使用同一宽度，最大约 `1180px`，保留必要的响应式页边距；不再被常驻左右侧栏压缩。

对话流按时间显示：

- 用户消息；
- Agent 的真实执行进度；
- Agent 最终回答；
- 可预览、下载和继续修改的成果卡。

对话历史默认收起，按需打开覆盖式抽屉。切换历史对话不得刷新整个岗位页面，也不得清空输入内容或当前滚动位置。

### 4.4 输入区

输入区固定在可视区域底部，宽度与对话正文一致。包含：

- 文本输入；
- 添加文件或图片；
- “岗位任务”入口；
- 发送按钮；
- `Enter` 发送、`Shift+Enter` 换行提示。

已选附件显示在输入区上方。附件默认只进入本轮，只有用户明确操作后才成为长期岗位材料。

### 4.5 岗位资料抽屉

“岗位资料”使用覆盖式右侧抽屉，不常驻占用对话宽度。抽屉包含三个业务页签：

1. **岗位信息：** 官网岗位事实、当前岗位理解和必要的版本来源；
2. **候选人：** 当前岗位候选人列表和进入候选人详情的入口；
3. **材料与成果：** 长期岗位材料、Agent 生成成果、预览和下载。

“岗位上下文”不再作为面向用户的技术页签；使用“当前岗位理解”表达。复杂编辑、版本确认和候选人详情可以在抽屉内继续展开，但不能让多个面板同时常驻首屏。

移动端抽屉改为全屏或底部面板，主对话仍保持唯一滚动区域。

## 5. 岗位任务交互

### 5.1 入口

五个正式任务收进输入区旁的单一“岗位任务”菜单：

- 生成岗位说明（JD）；
- 梳理岗位要求（JR）；
- 生成人才画像；
- 生成搜寻策略；
- 生成面试方案。

每个菜单项使用业务结果说明，例如“形成可修改、可下载的岗位说明”。用户也可以直接通过自然语言发起同一任务。

### 5.2 执行

点击任务后直接创建任务，不能只把预设文字写入输入框。

- 当前没有岗位对话时，先创建并绑定一个岗位对话；
- 有当前对话时继续该对话；
- 使用当前确认的岗位上下文和本轮明确选择的材料；
- 任务受理后立即关闭菜单并在对话流加入真实状态；
- 状态从已受理、执行中到已完成或失败持续更新；
- 页面刷新、断网或重新进入后从持久任务记录恢复。

页面不再保留独立的常驻“岗位任务状态”栏。

### 5.3 结果

任务完成后：

- 最终回答进入当前对话；
- 生成文件作为成果卡紧跟对应回答；
- 成果卡显示名称、版本、格式和创建时间；
- 可以预览、下载或继续在对话中修改；
- 成果同时出现在“材料与成果”页签；
- 历史版本保留，不用新结果覆盖旧结果。

## 6. 状态与错误设计

### 6.1 空数据

空数据是正常业务状态：

- “暂无候选人”；
- “暂无岗位材料”；
- “暂无生成成果”。

不得把空数据显示为“暂时不可用”。空状态只在用户打开相应抽屉页签后出现。

### 6.2 局部异常

候选人、材料或成果读取失败时，只在对应页签内显示简短原因和“重试”。主对话保持可用，最后一次有效数据保持可见，不因刷新失败清空。

任务失败时，错误附着在该次任务消息上，显示业务可理解的原因和“重试本任务”。不得在页面顶部增加全局任务状态栏。

### 6.3 整体异常

身份失效或 HR 工作台整体服务不可用时只显示一条统一状态，不允许上下文、候选人、材料和任务同时重复报错。重新认证或恢复后原岗位、当前对话和输入草稿应继续保留。

权限语义必须一致：能够进入 HR 工作台且拥有 HR Agent 使用权的用户，可以访问同一岗位工作台的子能力；岗位与候选人数据仍由 Owner 范围隔离。

## 7. 组件边界

- `HrWorkspacePage` 只负责全局“对话/岗位”路由切换和页面保活。
- `HrPositionWorkspace` 负责岗位详情装配、当前对话和抽屉状态，不直接堆叠所有业务面板。
- 紧凑岗位栏独立为单一展示/动作组件。
- 岗位任务菜单独立负责任务选择与发起，任务展示复用对话消息模型。
- 岗位资料抽屉统一承载岗位信息、候选人、材料和成果的按需加载。
- `DirectAgentWorkspace` 继续负责消息、流式事件、附件输入和会话恢复；岗位模式关闭常驻历史侧栏和材料侧栏，改由覆盖式入口调用。
- HR R1.2 API、Position API、Conversation API 和附件 API 保持现有职责，不因布局重构复制服务。

## 8. 数据流

1. 路由提供 `position_id` 和可选 `conversation_id`。
2. 页面加载基础岗位信息并立即渲染对话骨架。
3. 当前岗位对话独立加载；岗位资料抽屉的数据只在打开对应页签时加载。
4. 用户发送消息或选择岗位任务时，Platform 绑定准确岗位、当前对话、本轮材料和已确认上下文。
5. Conversation 事件驱动对话流中的进度、回答和成果卡。
6. 任务完成后刷新资料抽屉的成果投影，不刷新或替换整个页面。

## 9. 可访问性与响应式

- 可见正文最小字号不低于现有平台标准。
- 所有按钮具有文本或明确的可访问名称。
- 菜单和抽屉支持键盘打开、关闭、焦点圈定和 `Escape`。
- 主对话、菜单和抽屉不形成无法退出的嵌套滚动。
- 桌面端主对话最大约 `1180px`；窄屏使用完整可用宽度。
- 输入区在桌面和移动端均保持可见，不遮挡最后一条消息或下载操作。

## 10. 验收标准

1. 打开一个岗位后首屏只有紧凑岗位信息、当前对话和输入区。
2. 页面不存在常驻统计卡、五个任务按钮、任务状态栏或左右双侧栏。
3. 桌面端对话正文和输入区最大宽度约 `1180px`，在常用分辨率下明显宽于现状。
4. 岗位详情、对话列表、消息区和抽屉都有明确且可用的滚动容器。
5. “岗位任务”菜单的五个任务点击后直接执行，不修改输入框文本。
6. 任务受理、执行、失败、重试、完成和成果下载均在对话流可见。
7. 添加文件或图片入口位于输入区底部，附件默认只用于本轮。
8. “岗位资料”抽屉可以查看岗位信息、候选人、材料和成果，不压缩主对话。
9. 空数据使用“暂无”，HTTP 或解析失败才使用“不可用”。
10. 一个子面板失败不影响岗位对话；整体异常只显示一次。
11. 刷新和岗位/对话切换不丢失当前会话、输入草稿或已有有效数据。
12. 现有岗位权限、跨岗位隔离、附件下载和长任务恢复测试继续通过。
13. 桌面端和移动端都完成真实滚动、键盘、菜单、抽屉和下载验收。

## 11. 发布边界

本次只修改 HR 工作台前端及确有必要的 Platform HR 会话投影适配；不修改 Nginx，不改 FAE、VOC、行政或其他 Bot，不新增持久数据目录。发布继续遵守根盘、数据盘、staging、回滚版本和镜像保留纪律。
