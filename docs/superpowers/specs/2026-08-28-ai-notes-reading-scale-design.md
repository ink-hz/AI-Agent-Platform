# AI 工程笔记阅读尺度优化设计

## 问题

在约 2048px 宽的实际截图中，左侧目录正常，但右侧阅读区接近 1600px；文章容器仍固定为 820px，扣除两侧 42px 内边距后，正文有效宽度只有约 736px。正文为 15px，手机为 14px。结果是大屏两侧留白过多，正文、代码和表格整体偏小，不像适合持续浏览的技术博客。

## 设计

- 桌面文章容器从 820px 增至 1040px，水平内边距从 42px 调整为 48px，正文有效宽度约 944px。
- 正文字号从 15px 增至 17px，行高从 1.82 调整为 1.78；保持较舒展的中文阅读节奏，同时避免每行过长。
- Markdown 二、三、四级标题分别调整为 25px、20px、17px；正文代码和表格提升到 14px。
- 手机正文从 14px 增至 16px，文章左右内边距从 20px 收至 18px；手机标题按层级回落，避免占用过多纵向空间。
- 阅读区顶部错误提示与 1040px 文章容器对齐。
- Mermaid、表格和代码块继续使用正文容器完整宽度；不改变左侧目录树、导航、文章数据、Markdown 渲染器或图表逻辑。

## 响应式行为

- 大屏：正文明显扩大，减少左右无效留白。
- 中等屏幕：容器受可用宽度约束自然收缩，保留 48px 桌面内边距。
- 720px 及以下：隐藏桌面目录，正文 16px，18px 左右内边距，维持现有移动目录抽屉。
- 打印：继续使用现有无最大宽度、无内边距规则。

## 验收

- 样式合同锁定桌面容器、正文、标题、代码、表格和移动端字号。
- AI notes 相关前端定向测试、全量测试和生产构建通过。
- 在用户提供的同类大屏视口中，正文占用更合理的阅读区域；手机正文无需缩放即可阅读。
- 不改变其他页面的 Markdown 或通用布局。
