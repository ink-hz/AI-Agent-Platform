# SDK 简洁工作区与自动开通设计

## 背景与目标

SDK 团队目前从 `https://agent.orbbec.com.cn/sdk` 进入完整禅道。平台钉钉会话已能换取个人禅道会话，但平台所有者必须先逐个在禅道创建用户并绑定账号。用户希望日常只看需求、任务、测试和发布，且合格员工首次进入时自动拥有个人账号。

首版让 `/sdk` 成为简洁的个人工作入口，禅道仍保存需求、任务、用例和发布记录。员工的写操作在个人禅道会话中完成，确保禅道显示真实操作人。现有平台 SDK 服务账号只用于受限读取和集成，不代替员工做个人写入。CSV 来源页与旧候选证据页不恢复为日常入口。

## 准入与账号

平台已验证的活跃钉钉员工才可申请进入。准入策略包含 SDK 部门及显式配置的协作部门（含子部门），并保留已有 `sdk.members` 授权。部门策略需要配置具体目录部门 ID，空列表不授予新员工权限。目录处于硬过期、人员已停用或身份不确定时，停止新建账号与签发登录票据。

首次进入时，用平台不可变的 `internal_user_id` 派生禅道账号 `sdk_<UUID 的小写 Base32 无填充编码>`（整串 30 字符，符合禅道 22.6 账号长度）；账号名不取显示姓名或邮箱。现有经人工核对的绑定继续使用原禅道账号，不重建。平台以专用、私网可达的禅道建号凭据先创建**无权限组、无产品白名单**的新账号，设置随机不可见口令、当前目录显示名和随机归属标记。平台再次核对准入并完成唯一绑定后，才分配 SDK 精简权限组和私有产品白名单；核对成功后签发单次票据。建号期间失去准入资格时，账号保持零权限，不会留下已授权但未绑定的账号。建号超时或响应不确定时保持 `待核对`，下一次请求先核对同一个确定账号与归属标记，不盲目再创建；显示姓名变化不会阻断核对。两个并发首登只允许一个执行建号，另一请求得到明确的开通中状态。禁止自动认领任何名称相似的旧账号。

账号被移出准入部门或停用时，平台立即停止签发新票据；后台同步任务按每批 100 个账号连续消化撤权队列，正常轮询间隔五分钟。目录硬过期时停止新票据，暂不按过期目录批量撤销禅道权限。隔离实例证明撤权后原有 API Token 不再可访问产品、重新进入四个页面不再得到业务页；已打开的浏览器页面是否即时退出尚未验证，不能宣称即时单点退出。人工已有绑定在权限收回时保留审计记录，不自动删除禅道历史。部门策略每次变更记录操作者、部门、动作及时间。

## 简洁工作入口

`/sdk` 显示四个清晰入口：需求、我的任务、测试、发布。每个入口只请求固定的目标标识，由平台将目标绑定到 45 秒单次票据；消费后仅跳转到服务器端固定映射的禅道站内地址。浏览器不能提供任意 URL。用户首次点击时先完成自动开通，再进入相应个人页面。平台所有者可根据带上级路径及覆盖人数的目录列表配置准入部门；公司根部门不能从页面直接勾选。

禅道内为 SDK 权限组只配置需求、任务、测试、发布及必要辅助动作；成员通过四个固定入口进入，管理员仍能进入完整后台。隔离的禅道 22.6 实例已验证 56 项权限组的四个目标页面可达。列表列与表单字段仍由禅道提供，首版不改全局配置，也不改禅道源码或注入脚本。产品私有白名单由平台服务账号独占维护；若同时由禅道管理员修改，现有全量更新 API 缺少并发写入保护，运维需避免同时修改。

完整禅道保持独立浏览器源，不代理到主平台同源 `/sdk/`。公开企业子域名 `sdk.orbbec.com.cn` 的 DNS 和证书尚未具备，域名切换作为独立发布门槛；此功能不依赖把完整禅道放在主平台源上。

## 边界与验收

后端测试覆盖活跃员工、部门准入、原有 SDK 授权、离职/硬过期、既有绑定、首次建号、并发、账号冲突、禅道超时后的核对、权限组分配、票据目的地白名单和重放。真实禅道 22.6 隔离实例验证 API 创建、权限与个人会话归属。生产发布前核对部署镜像准确提交、数据库迁移、原有账号映射和备份；发布后验证真实钉钉身份的首次进入及复登、需求/任务操作人、权限撤销、平台及行政服务静态文件完整性。浏览器交互最终由业务方按仓库约定验收。
