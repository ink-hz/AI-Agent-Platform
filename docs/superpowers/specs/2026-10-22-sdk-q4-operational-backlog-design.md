# 2026 Q4 SDK 需求首版运行设计

## 目标与依据

把现有禅道产品 `OpenOrbbecSDK` 的 #3–#69 作为可追溯的 Q4 待评审工作队列使用。唯一需求来源是 SHA-256 为 `402030f9a76fb966b23fc6c9ad843d5f9abd85bcdce1d685835440ae6c51b7d0` 的原 Excel 中“2026年Q4上线版本”工作表。其 67 个非空任务行和既有 67 个禅道 ID 一一对应；不重复创建需求。#1、#2 为部署和场景测试记录，不属于 Q4。

用户已经选择禅道原生研发管理流程。比较过继续润色 67 条正文、另建 SDK 页面、使用禅道原生计划/模块/评审流程三种路线；采用第三种。原始工作簿不改写，禅道保留业务对象与操作历史。

## 现状和首版变更

2026-10-22 线上只读核对：产品 1 有 69 条未删除需求，其中 #3–#69 的 `sourceNote` 全部指向 Q4 工作表；67 条均为 `reviewing`、`openedBy=sdk-api`、当前版本评审人 `cangyuan`，`module=0`、`plan` 为空或 `0`。产品目前没有非删除计划。原 Excel 的 67 条均有 C 列责任人，但只填了 24 个版本、6 个计划开始日期、5 个计划结束日期、50 个优先级、6 个风险、7 个进展、14 个备注和 8 个超链接；没有提出人、指定评审人或可直接验收的标准。

1. 建立一个禅道原生产品计划，名称“2026年Q4上线版本”，时间为 2026-10-01 至 2026-12-31。描述注明它是原始计划的需求范围，不代表发布承诺或完成状态。只关联 #3–#69；#1、#2 留在历史测试记录，不关联此计划。创建前按产品、名称、日期和来源检查幂等；发现同名异义计划时停止。
2. 将原表 16 个有任务的栏目作为 Q4 来源分组映射到禅道需求模块。长栏目名中的版本日期移到来源说明，模块名采用栏目主题；映射表保存原文、目标名称和对应 Excel 行。创建前检查名称冲突；逐条关联只改 `module`，不改标题、正文、验收、负责人或优先级。产品原有 chart/pivot 模块不动。
3. 现有 67 条统一“苍渊评审中”不是原表事实。若业务选择“待指定”，使用禅道原生动作使它们回到待补充/待提交评审状态；不能仅清空数据库评审人字段。具体动作先在隔离副本验证版本、负责人、历史和后续重新提交评审。若业务选择统一苍渊评审，保持当前评审设置，但明确这是业务新决定而非原表字段。两种选择都不得自动批准。
4. 为 67 条形成可核对的来源与差距清单：原 Excel 行/单元格、栏目、标题、原责任人、已绑定禅道账号或待核定状态、计划版本与日期、风险/进展/备注、链接、禅道 ID、当前状态、缺失的提出人/设备场景/验收/评审人。原值与建议讨论点分开。首轮优先审第 2–6 行五条，已有逐格复核卡可复用；随后由业务逐条补足需求，不从标题推断完成或验收。

## 执行与验收

先冻结当前 67 条快照并备份禅道数据库和数据卷。所有写入前检查来源 SHA、固定行→ID 映射、产品、标题、版本、状态、计划、模块和评审记录；发现人工改动则停止并复核。原生 API/动作先在隔离实例用生产备份副本验证，执行后逐条读回 67 条，确认没有重建、重复、误改或丢失关联。生产发布不改 Nginx、平台 API 或行政服务；不运行独立生产 `nginx -t -c`。

完成首版数据整理的定义是：Q4 原生计划只含 67 条、16 个来源模块可浏览、67 条来源映射和差距可查、评审人状态与业务选择一致、#1/#2 不混入 Q4 视图。业务可用还需真实责任人补足场景、验收标准和评审人，并在个人钉钉会话中完成一次创建/编辑/提交评审/任务关联的人工验收；工程核对不能替代这些业务结论。
