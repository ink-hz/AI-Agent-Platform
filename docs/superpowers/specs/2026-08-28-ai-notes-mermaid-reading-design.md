# AI 工程笔记 Mermaid 阅读体验设计

**日期：** 2026-08-28  
**状态：** 待最终确认  
**作者：** Codex（与苍渊共同确认产品方向）

## 1. 背景

AI 工程笔记已采用左侧目录树、右侧 Markdown 正文的技术博客布局。正文阅读尺度调整后，文章有效宽度约为 944px；Mermaid 图表仍使用与正文相同的宽度约束：

```css
.mermaid-diagram { max-width: 100%; overflow-x: auto; }
.mermaid-diagram img { max-width: 100%; height: auto; }
```

该规则能避免横向溢出，却没有限制图表高度。对于 `flowchart TB`、多层 `subgraph` 等纵向图，浏览器按可用宽度放大 SVG 并保持宽高比，图表会随正文一起变宽、变高。当前“能力递进”图因此需要滚动约两屏才能看完。

问题不能通过重新缩窄正文解决。正文和图表具有不同的阅读目标，应使用独立的尺寸与交互策略。

## 2. 行业处理方式

行业实践通常组合三种方式，而不是只依赖一个尺寸规则：

1. **响应式适配。** Mermaid 支持 `useMaxWidth`，使图表跟随容器宽度；它能解决横向溢出，但不会自动解决纵向长图。  
   参考：<https://mermaid.js.org/syntax/flowchart>
2. **控制图表范围与复杂度。** GitHub Docs 要求图表有明确范围；信息越多，图表越难理解。小尺寸难以查看时，应提供大图入口。  
   参考：<https://docs.github.com/en/contributing/writing-for-github-docs/creating-diagrams-for-github-docs>
3. **克制的内嵌尺寸与按需放大。** GitBook 提供分级尺寸和 Fit；Notion 支持调整内嵌尺寸、查看原图和全屏；Confluence 支持按比例调整和大图预览。  
   参考：
   - <https://gitbook.com/docs/creating-content/blocks/insert-images>
   - <https://www.notion.com/en-gb/help/images-files-and-media>
   - <https://support.atlassian.com/confluence-cloud/docs/work-with-images-videos-and-files/>

本平台采用相同的组合思想：**正文中一屏概览、需要时全屏查看、内容侧逐图治理。**

## 3. 目标

1. 桌面和手机正文中的 Mermaid 图默认不超过约一屏高度。
2. 默认状态展示完整图，不裁剪，不引入嵌套滚动条。
3. 点击或键盘操作可进入大图模式，查看细节时支持缩放和拖动。
4. 保持现有严格渲染、SVG 清洗和 CSP 兼容能力。
5. 对现有 16 张 Mermaid 图逐图精读，改善图表本身的结构、方向、语义颜色和无障碍信息。
6. 正文宽度与字号保持不变，不因图表问题回退阅读尺度。

## 4. 非目标

1. 不建设 Mermaid 在线编辑器。
2. 不允许用户在页面内修改或保存图表源码。
3. 不引入重型第三方缩放、画布或图表查看依赖。
4. 不用机械的节点数量、源码长度或关键词匹配代替人工图表审查。
5. 不在本次工作中迁移新的文章。

## 5. 方案比较

### 方案 A：只跟随正文宽度

保持当前实现。图中文字最清楚，但纵向图会持续向下增长，一张图可能占两屏以上。该方案不能满足连续阅读目标。

### 方案 B：一屏概览与点击放大

正文内完整缩放到约一屏；点击后进入全屏，支持缩放和拖动。它同时兼顾文章连续性与细节查看，是本次选择的产品方案。

### 方案 C：只依赖人工拆图

逐图调整 `TB/LR`、精简节点或拆分，单篇内容质量最高；但缺少平台兜底，新文章仍可能再次出现长图。它适合作为内容治理原则，不能代替方案 B。

### 最终选择

以 **方案 B 作为平台能力**，同时采用 **方案 C 的逐图治理原则**。

## 6. 内嵌图表设计

### 6.1 尺寸

- 桌面端：图表最大宽度为正文可用宽度，最大高度为 `min(720px, 70vh)`。
- 手机端：图表最大宽度为正文可用宽度，最大高度为 `68svh`。
- 图像使用等比缩放与 `object-fit: contain`，水平居中。
- 小图不强制放大到正文全宽，保留其自然尺寸。
- 不裁剪图表，不在内嵌区域增加纵向或横向滚动条。

这使读者先看到完整结构。对于文字因缩放而变小的复杂图，使用大图模式查看细节。

### 6.2 入口

- 整张图可点击，鼠标显示放大指针。
- 右下角显示克制的“查看大图”提示，避免读者不知道图表可交互。
- 图表容器可获得键盘焦点；Enter 或 Space 打开大图。
- 提示和按钮不覆盖关键节点文字。

## 7. 大图查看器

### 7.1 结构

新增独立的 Mermaid 大图查看器。它接收已经清洗过的 SVG data URL 和图表标题，不重新调用 Mermaid 渲染器。

查看器使用原生模态对话框语义：

- `dialog` 为模态界面；
- 标题作为可访问名称；
- 打开时焦点进入关闭按钮；
- Tab 焦点保留在对话框内；
- Esc 或关闭按钮退出；
- 退出后焦点回到原图；
- 打开期间锁定正文滚动，关闭后恢复原有滚动位置。

### 7.2 查看行为

- 初始状态为“适合窗口”，完整图表位于白色中性画布中央。
- 工具栏仅提供：放大、缩小、恢复、关闭。
- 初始比例记为 `1`；每次缩放变化 `0.25`，范围为 `1` 到 `4`。
- 比例大于 `1` 时可以使用鼠标或触摸指针拖动画布。
- 恢复操作同时重置比例与位移。
- 页面一次只打开一张图，不保留上一张图的缩放和位移。
- 手机端使用相同的全屏查看器与触摸拖动，不增加单独的交互模式。

## 8. Mermaid 渲染与安全

保留现有安全链路：

1. `securityLevel: "strict"`；
2. `htmlLabels: false`；
3. DOMPurify 使用 SVG profile；
4. 禁止 `script` 和 `foreignObject`；
5. 通过本地 data URL 显示清洗后的 SVG；
6. 单张图失败时只回退该图的 Mermaid 源码，不影响文章其余内容。

大图查看器只能接收现有清洗函数的输出，不新增原始 SVG 注入路径，也不降低 Mermaid 安全级别。

## 9. 图表无障碍信息

现有统一的 `alt="Mermaid 图表"` 信息不足。每张图应在 Mermaid 源码中包含：

```mermaid
accTitle: 图表的简短标题
accDescr: 图表表达的核心关系与阅读顺序
```

渲染组件从源码读取 `accTitle`，作为内嵌图片、大图对话框和查看入口的可访问名称；缺失时才回退到“Mermaid 图表”。`accDescr` 保留在 SVG 中，同时图前后的文章正文必须完整传达相同结论，图表不能成为唯一信息来源。

颜色不能作为唯一语义。分层颜色需同时由标题、节点文字、边或分组结构表达。

3. 是否存在无信息价值的嵌套 `subgraph`；
4. 是否需要拆成“总览 + 细节”两张图；

## 11. 响应式、打印与降级

### 响应式

- 使用动态视口单位限制手机图表高度，避免浏览器地址栏变化造成两屏图。
- 图表入口始终保留可见焦点样式。
- 全屏工具栏避开安全区，按钮满足触摸尺寸要求。

### 打印

- 隐藏“查看大图”提示和大图对话框。
- 取消视口高度限制，图表按打印区域宽度等比排版。
- 不依赖交互才能获得文章结论。

### 降级

- Mermaid 加载或渲染失败：显示现有源码回退。
- 图片 data URL 加载失败：切换到同一源码回退。
- 浏览器不支持大图交互时：内嵌完整图仍可阅读，正文不受影响。

## 12. 测试策略

### 组件测试

- 清洗后的 SVG 被复用，不重复调用 Mermaid 渲染。
- 点击、Enter、Space 打开大图。
- Esc、关闭按钮关闭，焦点正确恢复。
- 放大、缩小、恢复的比例边界正确。
- 拖动仅在放大后生效，恢复同时清除位移。
- 组件卸载或切换文章时清理滚动锁和查看状态。
- 渲染失败继续显示源码回退。

### 样式契约

- 桌面、手机内嵌高度限制及居中规则被锁定。
- 查看入口具有 hover 和 focus-visible 状态。
- 打印规则移除交互控件与视口高度限制。

### 真实 Mermaid 集成

- 16 张现有图全部使用真实 Mermaid 渲染器通过。
- 每张图都保留语义颜色且不存在脚本或 `foreignObject`。
- 每张图都包含 `accTitle` 和 `accDescr`。

### 视觉验收

- 桌面真实浏览器：内嵌图不超过约一屏；大图打开、缩放、拖动和关闭正常。
- 手机真实视口：一屏概览、触摸打开与拖动正常，工具栏不被安全区遮挡。
- 对 16 张图逐张截图复核，不以单张样例代替内容验收。

1. 内嵌一屏概览和大图查看器全部实现；

3. 无障碍标题和描述补全；
4. 定向测试、前端全量测试和生产构建通过；
5. 桌面与手机真实浏览器视觉验收通过；
