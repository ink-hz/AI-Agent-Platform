# HR Agent 网页会话工作台设计

**日期：** 2026-09-03

**状态：** 待书面评审

**首个适用 Agent：** HR Agent

**后续适用范围：** 支持文档、图片和结果文件的专业 Agent 网页工作台

## 1. 项目定位

本项目把 HR Agent 网页版从“只能发送文本的聊天页”升级为可持续完成招聘研究、简历与
访谈材料分析、JD/JR 修订、报告和演示文稿生成的会话工作台。

产品体验以 FAE 已验证的简洁对话方式为参考，但不让 Agent Platform 在运行时依赖
`AI-FAE-Agent` 仓库。上传、附件身份、存储、权限、预览、下载、保留期和审计统一落在
Platform Attachment Service；HR Agent 只保留领域理解、任务执行和结果生成职责。

这不是 HR 专用文件柜。首版优先覆盖 HR 的真实工作流，同时把附件和结果能力建设成其他
专业 Agent 可复用的通用平台能力。

### 1.1 术语边界

- 用户界面的一个“Session / 会话”对应一个 Platform `Conversation`；
- 一个 `Turn` 对应该 Conversation 中的一次用户请求及其 Assistant 处理结果；
- MetaBot 原生 Session、Mission、Run 和 Task 是下游执行或治理对象，不是第二份用户会话；
- 管理中心 Session 详情通过稳定映射查看同一 Conversation 及其下游执行事实。

后文的“Session”均指用户可见的一个 Platform Conversation，除非明确写为“MetaBot 原生
Session”。

## 2. 事实依据与当前问题

本设计基于生产网页、FAE 网页、本地代码和本地 HR Session 的核查结果。

### 2.1 当前产品缺口

- HR Catalog 声明不支持附件，浏览器消息契约也只有文本；
- 输入区不支持点击选择、拖放、粘贴图片、上传进度、失败重试或附件移除；
- Agent Runtime 向专业 Agent 派发时没有真实的附件引用；
- 回答没有复制按钮，生成文件没有统一结果卡片和可靠下载入口；
- 现有点赞/点踩能力存在，但入口弱，点踩原因没有形成完整的问题分诊闭环；
- 页面卡片和说明过多，输入区占用过大并可能遮挡回答，长会话可用性差；
- 历史列表的链接地址没有始终携带 HR Agent 作用域，复制链接、新标签页或直接访问时可能
  落到错误工作区；
- 搜索通道失败时只有一次性失败答案，缺少任务续跑、证据状态和恢复机制。

### 2.2 真实 HR 工作流

本地 Session 显示，HR Agent 已经被用于：

- 结合原始 JD/JR 和用人经理访谈记录修订岗位材料；
- 分析简历、面试记录和人才资料并生成报告；
- 搜索候选人、岗位、公司和薪酬信息；
- 分析、生成和多轮修改 Word、PPT、图片等交付物；
- 在长会话中反复引用同一批材料并保留多个结果版本。

真实失败包括附件未随消息到达、临时目录在轮次间被清理、用户被迫重复上传、多图顺序或
关联丢失、文本声称“已生成”但网页没有文件，以及联网搜索暂时不可用后整项任务无法继续。
因此，首版不能只增加一个上传按钮；必须同时解决持久化、绑定、恢复、输出登记和下载。

### 2.3 历史数据限制

本地 HR Session 中存在消息文本提到附件或生成文件，但当前 `platform_read.attachments`
无法为这些历史 Turn 找到对应附件记录。迁移只能恢复仍有可信源对象的文件和绑定，不能根据
文本重新伪造附件。无法恢复字节的历史记录显示“历史附件不可用”，保留原消息和审计事实。

## 3. 目标与非目标

### 3.1 目标

1. 用户能在 HR 网页上传图片和常见文档，并在同一 Session 内持续复用。
2. 用户能明确选择本轮启用哪些 Session 材料，避免长会话误用旧文件。
3. Agent 生成的每个文件版本都成为可预览或可下载的正式结果，而不是消息正文里的本地路径。
4. 刷新或关闭网页不取消长任务；重新进入后恢复真实进度和结果。
5. 回答支持复制、点赞和带文字说明的点踩，点踩进入待分诊队列。
6. 联网研究结果带可核验来源，导出文件保留来源与检索时间。
7. 管理中心能在既有权限和审计边界内查看同一 Session 的输入、输出和反馈附件。
8. 首版在桌面浏览器中稳定完成真实 HR 文档工作流，并为其他专业 Agent 提供可复用底座。

### 3.2 非目标

- 不建设 HR 专属 ATS、候选人库、审批流或招聘流程状态机；
- 不把 FAE 应用嵌入 HR 页面，也不让 Platform 运行时调用 FAE 前端或附件 API；
- 不在首版提供 Office 文档的完整在线编辑或高保真在线预览；
- 不在首版提供对其他员工的文件分享链接；
- 不把点踩自动转换为已确认工程 Issue；
- 不承诺恢复已经丢失且没有可信对象源的历史附件；
- 不允许 Agent 或浏览器直接接触对象存储凭据、Object Key 或服务器本地路径。

## 4. 方案选择

### 4.1 采用：简洁对话 + 可折叠 Session 材料抽屉

页面保留三段式信息架构：左侧 HR 历史会话、中间对话、右侧可折叠的“Session 材料 / 生成
结果”抽屉。右侧抽屉负责跨轮次资产管理；每条消息仍就地展示与该轮直接相关的输入附件、
生成结果、引用和操作。

该方案兼顾聊天的连续性和文档任务的可管理性。用户无需离开对话寻找文件，长 Session 也不会
把所有材料永久堆在消息流或输入区中。

### 4.2 不采用：仅在消息气泡里展示附件

实现较轻，但长会话中难以找到旧文件、选择本轮上下文或管理多个生成版本，不符合真实 HR
Session 的连续修改场景。

### 4.3 不采用：独立全屏文件工作台

适合重型文档管理，但会切断提问、回答、来源和文件之间的上下文，首版复杂度也过高。

## 5. 页面与交互设计

### 5.1 整体布局

```text
┌──────────────┬──────────────────────────────────┬────────────────────┐
│ HR 历史会话  │ 对话时间线                       │ Session 材料       │
│ 新对话       │ HR Agent 身份 + 简短状态         │ 本轮启用           │
│ 标题/时间    │ 用户消息 / 回答 / 结果卡 / 引用  │ 已上传材料         │
│ 未读/处理中  │                                  │ 生成结果与版本     │
│              │ 固定但不遮挡内容的输入区         │ 保留期与容量       │
└──────────────┴──────────────────────────────────┴────────────────────┘
```

- 视觉基线采用 FAE 的清爽白底、低噪声层级和紧凑输入区；
- 移除占据首屏的大型能力、边界和身份卡片；能力说明进入空会话状态或帮助入口；
- 中间列保持阅读宽度，右侧抽屉默认记住用户上次展开状态；窄屏时变为覆盖式抽屉；
- 输入区固定在底部，但消息列表必须预留准确高度，最后一条回答和操作区不可被遮挡；
- 用户界面不显示 Mission、Run、Trace、Adapter、内部状态码或服务器路径。

### 5.2 上传与发送

输入区支持：

- 点击选择文件；
- 拖放文件；
- 粘贴剪贴板图片；
- 多文件队列、缩略图、文件名、大小、真实上传/扫描状态；
- 单文件失败重试和发送前移除；
- 文本为空但存在已就绪附件时允许发送。

HR Catalog 首版限制为：

```text
单文件最大                    50 MB
单条消息最多                  5 个文件
单条消息附件合计最大          50 MB
单个 Session 用户上传材料最多          50 个文件
单个 Session 用户上传材料合计最大      500 MB
```

Catalog 可以按 Agent 降低 Platform 全局上限，不能绕过全局安全策略。首版支持常见图片、
PDF、纯文本、DOC/DOCX、XLS/XLSX、PPT/PPTX；压缩包、可执行文件、脚本、带密码文件和
无法安全解码的对象拒绝接收。

Session 数量和容量限制只计算用户上传材料，不因 Agent 生成的新版本挤占用户上传额度。输出
仍受 Platform 的单任务与总存储安全配额约束；触发输出配额时保留已完成结果并明确提示用户，
不得静默丢弃或错误标记为成功。

发送必须具有原子语义：服务端只在文本和所有选定附件均可绑定时创建用户消息与 Turn。
附件仍在上传、验证或扫描时，发送按钮显示明确原因；网络重试复用同一个
`client_request_id`，不得创建重复消息或重复任务。

### 5.3 Session 材料与本轮启用

上传成功的文件默认加入当前 Session 材料。右侧抽屉按“本轮启用 / 已上传材料 / 生成结果”
分组，显示文件类型、大小、上传时间、来源 Turn 和状态。

每轮发送前，用户可选择哪些 Session 材料作为本轮上下文：

- 新上传且随本轮发送的文件默认启用；
- 上一轮启用状态可以延续，但必须在输入区以紧凑标签可见；
- 用户可在输入区或抽屉中取消启用，取消不会删除文件；
- Agent 只获得本轮显式启用附件的短期 Task Grant；
- 检测到明显换题或材料过多时，页面建议新建 Session 或重新确认启用材料，不自动替用户
  删除或切换。

系统显示每个文档的处理覆盖情况，例如 PDF 页数、表格 Sheet 数、演示文稿页数、图片 OCR
是否完成。解析不完整时必须在提交给 Agent 前或回答中明确指出，不能让用户误以为全部内容
已读取。

### 5.4 消息附件、预览和下载

用户消息下方显示该轮输入附件；Assistant 回答下方显示该轮输出结果卡。结果卡至少包含：

- 文件名、类型、大小、生成时间；
- `生成中 / 校验中 / 可下载 / 生成失败 / 已删除` 状态；
- 当前版本标记和版本号；
- 图片或 PDF 的预览入口；
- Office 文件的元数据和下载入口；
- 明显可见的单文件下载按钮；
- 同一回答多个结果时的“全部下载”。

“全部下载”由服务端生成安全 ZIP，ZIP 内只包含当前用户有权下载且状态为 `ready` 的结果，
文件名冲突使用确定性后缀处理。Office 首版不做完整在线预览；图片和 PDF 使用安全派生物预览，
原文件下载保持不变。

Agent 每次生成或修改文件都登记为新版本，所有版本保留，最新成功版本标为“当前版本”。失败
版本保留状态与审计，但不替换当前版本。用户可以查看和下载任一仍在保留期内的成功版本。

系统只有在文件完成格式、大小、非空、可打开和基本结构校验后才显示“可下载”。PPT、PDF、
图片等视觉交付物按类型执行必要的渲染检查；校验失败时不得在正文中声称文件已成功交付。

### 5.5 回答操作与反馈

每条已完成的 Assistant 回答提供：

- 复制：复制用户可见 Markdown 的纯文本表达，不包含隐藏诊断字段；成功后短暂显示“已复制”；
- 有帮助：一次点击提交；
- 需改进：打开输入框，不立即提交；
- 重新生成：以原问题、当前仍可用的本轮附件和新 `client_request_id` 创建新尝试，不覆盖旧
  回答或旧结果。

“需改进”面板包含一个原因类型和最多 1,000 个 UTF-8 字符的可选补充：

- 结论不准确；
- 信息不完整；
- 表达不清；
- 没有解决问题；
- 文件或格式有问题；
- 来源或时效有问题；
- 其他。

提交后反馈进入“待分诊”，不会自动创建或关闭工程 Issue。管理中心分诊视图可以看到原问题、
原回答、反馈原因、补充内容、Agent、用户可审计标识、Conversation/Turn 关联、当轮附件元数据
及有权限的预览/下载入口。

### 5.6 联网研究与来源

需要联网核验的回答采用两层来源展示：正文中的编号引用，以及回答底部默认收起的来源列表。
来源至少保存标题、规范化 URL、站点、检索时间和支持的结论位置。

导出的 Word、PDF、表格或演示文稿必须保留可读来源和检索时间。搜索通道不可用与“没有搜索
结果”是两个不同状态：

- 通道不可用：任务保持可恢复状态，显示已尝试次数、最后尝试时间和“继续重试”；
- 没有结果：显示实际检索范围和空结果结论；
- 部分来源成功：交付已有结果并明确覆盖缺口，不把部分成功说成完整搜索。

恢复搜索时复用原任务上下文，不要求用户重传附件或重新输入问题，也不得重复生成已经登记的
相同结果版本。

### 5.7 长任务、关页和未读

浏览器连接不拥有任务生命周期。用户刷新、断网或关闭页面后，已经被服务端原子接收的任务继续
执行；重新打开同一 Conversation 时，从持久化事件序号恢复进度、消息和结果。

Session 历史项显示 `处理中 / 需要补充 / 未完成` 等有业务意义的状态。任务在用户离开期间完成
时显示未读标记；用户进入并看到完成结果后清除。首版不默认发送飞书通知，后续可做用户可选通知。

同一 Conversation 首版仍只允许一个非终态 Turn。输入区在执行中允许用户编辑草稿，但不创建
第二个并发 Turn；用户可停止当前任务。停止保留已产生的消息和结果版本，不删除历史事实。

### 5.8 历史会话路由

HR 历史列表、新建对话、复制链接、浏览器新标签页和刷新都使用带 Agent 作用域的规范 URL。
后端再次验证 Conversation 属于当前用户且绑定 HR Agent。前端事件拦截不能成为维持 HR 作用域
的唯一手段；不带或错误 Agent 作用域的旧链接应安全重定向到规范 HR URL，越权访问返回 404
或 403，不落到 Agent Brain 工作区。

## 6. 架构与数据流

### 6.1 系统边界

```text
HR Web Workspace
  │  Platform Session + CSRF
  ▼
Conversation API ─────── Platform Attachment Service ─────── Private Object Store
  │                         │ validation / scan / preview
  │                         │ binding / retention / audit
  ▼                         ▼
Conversation Turn ─── task-scoped attachment grants
  │
  ▼
MetaBot HR Runtime ─── register output ─── Platform Attachment Service
  │                                           │
  └── public answer + citations               ├── User preview/download
                                              └── Admin session projection
```

Platform Attachment Service 是输入和输出文件的唯一附件事实源。MetaBot 通过绑定
`task_id + attachment_id + agent_id` 的短期 Grant 流式读取本轮启用文件，通过输出登记接口
回传结果；不得接收永久 URL、Object Key、MinIO 凭据或浏览器本地路径。

FAE 中已经验证的拖放、粘贴、进度、重试、复制和安全下载交互可以迁移为 Platform 共享组件和
模式，但不直接 import FAE 代码包或运行时调用 FAE 服务。

### 6.2 统一附件身份与绑定

一个 `attachment_id` 贯穿：

```text
upload → conversation message → turn/task input → MetaBot grant
       → task output → assistant message → admin session projection
```

每个附件必须有所有者、状态、原始文件名密文、检测 MIME、大小、Hash、保留截止时间和显式
业务绑定。输入和输出分别绑定到具体 Message、Turn 和 Agent Task；仅把文件名写进消息正文不算
附件交付。

每个输出版本使用独立 `attachment_id`，并通过逻辑 artifact/version 关系归组。当前版本由最新
成功且通过校验的版本确定，不能由文件名猜测。

### 6.3 消息提交

1. 浏览器创建上传并提交字节；
2. Platform 重新计算大小、Hash、MIME 和 magic bytes，完成安全扫描与派生物生成；
3. 附件进入 `ready` 后，浏览器连同文本、附件 ID、本轮启用附件 ID 和
   `client_request_id` 提交消息；
4. 服务端在一个事务内验证所有权、Session 容量、状态和 Agent 能力，创建 Message、Turn 和
   附件绑定；
5. Turn 开始时只为本轮启用附件签发短期 Task Grant；
6. MetaBot 读取内容并返回公开回答、结构化引用和输出文件清单；
7. Platform 校验、扫描并登记输出，再把成功结果绑定到 Assistant Message；
8. 回答、附件和完成事件持久化后，前端才显示完成。

### 6.4 输出契约

MetaBot 的终态返回必须把三个通道分开：

- 用户可见回答 Markdown；
- 结构化引用；
- 输出文件登记信息。

日志、工具调用、临时路径和运行中草稿永远不进入用户消息。若文本声称生成了文件但没有成功的
输出登记，Platform 将该轮标为“结果文件登记失败”并提供重试，不能生成虚假的下载卡片。

### 6.5 保留与删除

- 输入附件、输出附件、预览派生物和版本默认保留一年；
- 保留期从对象创建时间计算，界面显示到期日期；
- Conversation 归档不改变附件保留期；
- 用户删除附件后立即停止本轮选择、预览、下载和新 Grant，受控存储异步擦除；
- 安全审计只保留最小元数据、删除事实和不可逆 Hash，不保留已删除文件内容；
- 到期任务可重试且可审计，不允许对象存储静默提前过期；
- 法务或安全要求的紧急擦除沿用 Platform Attachment Service 的擦除作业。

## 7. 权限与安全

首版下载权限：附件所有者可以访问自己的 Conversation 文件；Platform Owner 在管理中心通过
特权审计流程预览或下载。普通同事不能通过转发 URL 获得访问权限，内部受控分享放入后续版本。

每次预览或下载都由后端重新校验用户、附件状态和业务绑定，并签发短时、单用途或有限次数票据。
票据 URL 不含身份信息和原始文件名，不作为长期分享链接。响应使用安全
`Content-Disposition`、准确 Content Type 和 `nosniff`；HTML、SVG、Office 等主动内容不在
Platform 同源页面内联执行。

附件只有在 `ready` 状态才能离开隔离区。扫描器不可用、超时或病毒库失效时 fail closed。
解析 Worker 禁用外网、宏、脚本、外链加载和递归解包，并设置 CPU、内存和时长限制。

普通日志不记录文件正文、原始文件名、下载票据、对象键、候选人个人资料或完整反馈内容。
管理端访问记录操作者、附件、目的、时间、结果和支持引用，满足一年保留期内的追溯要求。

## 8. 状态与故障恢复

### 8.1 附件状态

```text
uploading → validating → scanning → ready
                           ├──────→ quarantined
                           └──────→ rejected
ready / rejected / quarantined ──→ deleted
```

前端显示真实状态，不模拟已经完成的扫描或解析。失败只影响对应附件，用户可移除或重试，不需要
重传其他成功文件。

### 8.2 Turn 与结果状态

- `accepted/running`：后台继续执行，SSE 只负责观察；
- `waiting_for_input`：明确需要用户补充什么，原附件绑定继续有效；
- `completed`：公开回答和所有声明交付的结果均已持久化；
- `partially_completed`：有可用回答或结果，但明确列出缺失部分；
- `failed/interrupted`：显示用户安全原因、重试操作和可供支持查询的引用；
- `cancelled`：用户主动停止，保留已经登记的部分结果。

事件使用 Conversation 内单调序号。重连携带最后已见序号；服务端幂等提交和输出登记，避免网络
抖动造成重复任务、重复回答或重复文件版本。

### 8.3 用户可见错误

用户可见文案使用业务语言，不泄漏堆栈、Provider 响应或内部 ID：

- 文件类型或容量不支持：指出具体文件和限制；
- 安全扫描失败：说明文件暂不可使用并允许安全重试；
- 文档仅部分解析：指出未覆盖页、Sheet 或幻灯片；
- 搜索通道不可用：区分通道故障、空结果和部分成功；
- 结果生成失败：保留原回答和上一成功版本，允许只重试结果生成；
- 连接中断：说明正在恢复观察，不重复提交任务；
- 权限或到期：说明附件不可再访问，不暴露其是否属于其他用户。

## 9. 管理中心投影

管理中心 Session 详情继续使用已有 Turn 输入/输出附件能力，并统一读取新的附件绑定，不另建 HR
附件表。Owner 能看到：

- Session 和 Turn 归属、时间和业务状态；
- 用户输入与公开回答；
- 输入、输出附件元数据、版本、状态、保留截止时间；
- 图片/PDF 安全预览和所有 ready 文件下载；
- 联网来源和检索时间；
- 点赞/点踩、原因、补充内容和待分诊状态；
- 下载、删除、隔离和到期事件的审计摘要。

管理端仍通过安全票据读取对象，不能直接使用 MinIO URL 或本地路径。被删除、隔离、已过期或
历史字节缺失的附件只显示元数据和不可用原因。

## 10. 前端与服务组件边界

- `AgentConversationPage`：加载规范 Agent 路由、Conversation、消息和实时事件；
- `ConversationHistory`：HR 作用域历史、状态、未读和规范深链；
- `ConversationMessageList`：用户/Assistant 消息、引用和消息级附件；
- `MessageActions`：复制、反馈、重新生成；
- `ConversationComposer`：文本、上传队列、本轮启用标签、原子发送和停止；

- `AttachmentUploader`：选择、拖放、粘贴、状态、移除和失败重试；
- `AttachmentCard`：一致的输入/输出元数据、预览和下载；
- `ArtifactVersionList`：逻辑结果与所有版本；
- `CitationList`：编号引用和可展开来源；
- `FeedbackPanel`：原因、补充文本和提交状态。

共享组件只消费稳定的 Conversation/Attachment API，不知道 MinIO、MetaBot 临时目录或 FAE
内部实现。HR 专属文案和能力限制来自 Agent Catalog，不硬编码进通用附件组件。

## 12. 验收标准

### 12.1 核心场景

1. 用户在新 HR Session 同时拖入一份 JD、一个访谈 PDF 和三张图片，上传完成后一次发送；
   Agent 能读取全部启用文件，刷新页面后消息和附件仍存在。
2. 用户下一轮取消 JD、保留访谈 PDF 和其中一张图片，Agent 只获得这两个附件的 Task Grant。
3. Agent 连续生成三版 PPT；三版均可在右侧抽屉找到，第三版标为当前版本，每版均能独立下载。
4. Agent 生成的 PPT 无法打开时，页面显示校验失败且不出现“可下载”或成功交付文案；重试不会
   覆盖上一成功版本。
5. 用户关闭网页，任务继续；任务完成后历史列表显示未读，进入 Session 后能看到最终回答、
   来源和结果文件。
6. 搜索通道暂时不可用时，系统不把故障解释为“没有岗位”，恢复后可从原任务继续且不要求重传。
7. 用户点击复制得到完整可见回答；点击“需改进”可填写原因和补充内容，管理中心能在同一 Turn
   下查看反馈及附件上下文。
8. 用户、其他普通员工和 Owner 分别访问同一下载票据时，只有所有者和经审计授权的 Owner
   可以获得新票据和文件；转发或过期票据不可用。
9. 复制 HR 历史链接到新标签页仍进入 HR 工作台；错误作用域链接不会落到 Agent Brain。
10. 到期或用户删除后，附件不能预览、下载或签发新 Grant；管理端只保留最小审计元数据。

### 12.2 自动化验证

- 单元测试：限制计算、MIME/状态校验、版本当前项、权限、反馈校验、引用清洗、未读规则；
- API 集成测试：上传到绑定、原子消息提交、幂等重试、Task Grant、输出登记、票据下载、删除；
- Runtime 契约测试：只传本轮启用附件，公开回答/引用/结果分离，禁止本地路径成为交付；
- 浏览器测试：选择/拖放/粘贴、进度、刷新恢复、抽屉、预览、下载、复制、点踩输入和规范路由；
- 故障注入：扫描器离线、对象存储超时、SSE 断线、搜索不可用、输出校验失败、Worker 重启；
- 安全测试：越权附件 ID、票据重放、恶意 MIME、主动内容内联、日志敏感信息、删除后读取；
- 视觉回归：常规桌面、窄桌面、长回答、多附件、多版本和输入区不遮挡最后一条消息；
- 内容完整性回归：HR 常用词、岗位名和公司名不得被错误脱敏或替换，导出内容与网页正文一致。

### 12.3 发布门槛

- 上述十个核心场景全部通过；
- 不存在附件静默忽略、假成功文件卡、重复 Turn 或越权下载；
- 刷新/断线/Worker 重启后任务和文件绑定可恢复；
- 管理中心可追溯输入、输出、反馈和下载审计；
- 现有纯文本 HR Conversation、FAE 和其他专业 Agent 无回归；
- 生产启用前完成一轮脱敏真实 HR 样本验收。

## 13. 成功度量

上线后按 Agent 和版本观测，不记录文件正文：

- 附件上传成功率、扫描/解析失败率和 P95 就绪时延；
- 已声明输出与成功登记结果的一致率，目标为 100%；
- 下载成功率和票据拒绝原因分布；
- 关页或断线后任务恢复成功率；
- 因附件丢失要求用户重新上传的比例；
- 联网故障恢复成功率及“故障被误报为空结果”的次数，后者目标为 0；
- 点踩提交率、待分诊时长和文件类问题占比；
- 长 Session 中本轮启用材料的调整率，用于判断上下文控制是否易懂。

这些指标用于发现可靠性和体验问题，不把用户点赞率直接当作 HR Agent 回答正确率。
