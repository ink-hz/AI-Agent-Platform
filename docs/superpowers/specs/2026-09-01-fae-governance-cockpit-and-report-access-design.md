# FAE 治理驾驶舱与分析报告访问修复设计

日期：2026-09-01

状态：已完成产品确认，等待书面设计复核

范围：Agent Platform 的 `/admin/fae/issues` 与 `/admin/fae/reports`
明确不涉及：AI ADMIN `/office/*`、FAE 公网应用、FAE 推理链路及生产原始数据

## 1. 背景与问题

FAE 工作台已经具备概览、Session、反馈闭环和冻结分析报告的真实数据底座，但当前生产页面存在两个独立问题。

第一，反馈页直接复用了通用工程治理组件。87 个事项被作为长列表一次性铺开，其中 78 个仍处于待分诊状态；P1、已有根因、等待复跑和已关闭事项被大量原始反馈淹没。页面同时暴露 `Feedback Repair Ledger`、`ai-fae-agent` 等实现语言，顶部统计把处置状态与生命周期混在一起，右侧未选择事项时又留下大面积空白。结果更像数据库记录浏览器，而不是 FAE 管理者的治理工作台。

第二，冻结报告数据已经存在于生产只读副本，容器内可以完整组装 692 个 Session、1492 个 Turn、654 个复审 Session、21 项指标、8 项发现和 8 项建议，但生产鉴权白名单没有包含 `/api/admin/fae/reports/*`。浏览器请求因此被统一授权中间件拒绝，前端只能显示“数据暂不可用”。这不是数据同步或报告生成故障。

## 2. 产品目标

反馈页默认回答三个问题：

1. 现在最需要处理什么；
2. 每个问题处于根因分析、修复、部署、复跑还是复审的哪一步；
3. 关闭结论由哪些原始会话、工程证据和真实复跑支持。

报告页恢复真实只读访问，继续承担管理层成果阅读，不复制分析逻辑、不使用 Mock，也不放宽非管理角色权限。

## 3. 方案选择

采用“行动优先的治理驾驶舱”，而不是继续美化现有长列表。

比较过的方案：

- 仅调整颜色、间距和卡片阴影：改动最小，但 78 条待分诊记录仍会淹没重点问题，信息架构问题没有解决。
- 改成纯数据分析看板：适合观察趋势，不适合逐条完成根因、证据、复跑和复审闭环。
- 行动优先驾驶舱：顶部展示真实治理阶段，左侧为有界队列，右侧为闭环证据链；待分诊反馈池与已进入工程治理的问题分层。该方案被采用。

## 4. 页面信息架构

### 4.1 页面标题

主标题统一为“反馈与修复”，副标题为“从用户反馈到根因、修复、真实复跑和闭环结论”。移除 `Feedback Repair Ledger`。

“云端脱敏只读副本”是部署事实，不再作为醒目的业务告警。它显示为标题区右上角的次要状态标签，并附最近同步时间。只读不等于数据异常。

### 4.2 治理摘要

顶部固定为四个互斥、可解释的指标：

- 待分诊：`progress.status = pending_triage`；
- 处理中：`fixing | awaiting_merge | awaiting_deploy | awaiting_review`；
- 待复跑：`awaiting_replay`；
- 已闭环：`closed`。

重复、无需处理和暂不修复不混入“已闭环”，而是作为次级处置统计显示。反馈总数和负反馈回答数放入一个紧凑的“数据范围”说明，不占用主要 KPI 卡片。

云端所有 schema-v1 Issue 投影都包含 `progress`。云端 Repository 必须从这些受验证投影计算生命周期统计并返回 `lifecycle_status_available=true`，不能继续因为旧投影能力限制显示“暂不可用”。被隔离的 scope-invalid 记录只显示安全隔离数量，不参与业务统计。

### 4.3 默认队列

默认进入“需要行动”，排序规则固定为：

1. P0、P1 优先于 P2、P3；
2. 已进入工程闭环的事项优先于 `pending_triage`；
3. 等待复跑、等待复审、等待部署等明确阻塞事项优先；
4. 同级按最近更新时间倒序。

队列提供以下视图：需要行动、待分诊、待复跑、已闭环、全部。重复、无需处理和暂不修复通过“处置”筛选查看。

每页固定 20 条，服务端分页。禁止再请求 200 条后一次性渲染。列表项最多显示两行标题，只保留优先级、当前阶段、负责人和一条“下一步缺口”；主列表不重复显示 `ai-fae-agent`。

### 4.4 详情区

桌面端采用约 38% 队列、62% 详情的双栏布局。首次进入且未选择事项时，详情区显示“需要行动”摘要与使用提示，不展示空白占位。

选择事项后，右侧按固定顺序展示：

1. 问题摘要与当前阶段；
2. 原始 Session / Turn 关联；
3. 根因与影响范围；
4. 修复方案与工程证据；
5. 真实复跑答案；
6. 独立语义复审与最终结论；
7. 审计时间线。

不存在的数据明确显示“尚未完成”，不能用空卡片或假结论替代。云端保持只读，所有写按钮不渲染。移动端改为队列与详情上下排列，选择后详情优先滚入视口。

## 5. 查询与契约

继续使用现有 `/api/admin/fae/issues`，不新增第二套治理 API。扩展其云端状态能力：

- `status=pending_triage|fixing|awaiting_merge|awaiting_deploy|awaiting_replay|awaiting_review|closed` 按 `progress.status` 过滤；
- `status=open` 排除 `closed` 及非 actionable 处置；
- 默认排序使用第 4.3 节的稳定顺序；
- `limit` 的页面默认值改为 20，仍保留服务端上限；
- overview 从 schema-v1 `progress` 计算真实 `statuses`。

旧的非 schema-v1 投影继续 fail closed：详情段落标记 unavailable，不伪造生命周期。当前生产 87 条有效 Issue 均为 schema v1，因此新版页面可以完整显示生命周期。

## 6. 分析报告访问修复

将以下只读路由加入现有 FAE 管理读权限集合：

- `GET /api/admin/fae/reports`
- `GET /api/admin/fae/reports/latest`
- `GET /api/admin/fae/reports/{report_id}`

权限保持不变：仅 `platform_owner` 与 `platform_admin` 可读；member 与 management_viewer 返回 403；未登录返回 401；目录 hard-stale 时已认证 owner/admin 仍可只读冻结报告。报告没有任何云端写入口。

报告页错误态改为上下文明确的“分析报告读取失败”，保留重试按钮，不再使用会误导为全部 Platform 数据故障的通用文案。

## 7. 安全与数据边界

- 不改变钉钉登录、Cookie、CSRF 或审计边界；
- 不把原始客户身份、会话全文或附件写入前端静态资源；
- 列表只消费脱敏 Issue 投影，原始问题内容仅在已有管理权限内展示；
- scope-invalid 投影继续逐条隔离，不能为了页面完整而放宽验证；
- `/office/*` 不修改；
- FAE 公网域名、容器、配置和端口不修改。

## 8. 错误处理

- 报告路由无权限时显式返回 401/403，不转换成空报告；
- 报告不存在返回 404，页面显示“尚无已发布报告”；
- 副本过期或解密失败返回 503，页面保留重试入口并显示数据截止信息（若已知）；
- 单条 Issue 投影无效继续隔离，页面显示隔离数量；
- Issue 列表为空时区分“筛选无结果”和“没有治理事项”。

## 9. TDD 与验收

先写失败测试，再实现最小改动。

后端测试至少覆盖：

- 三个报告路由的 owner/admin、member/viewer、未登录和 hard-stale 权限矩阵；
- 云端 schema-v1 progress 汇总为真实生命周期统计；
- 云端生命周期筛选与默认行动优先排序；
- scope-invalid 记录不进入统计；
- 20 条分页契约和稳定翻页。

前端测试至少覆盖：

- 页面不再出现 `Feedback Repair Ledger`、主列表中的 `ai-fae-agent` 和“生命周期状态暂不可用”；
- 四个治理阶段指标真实显示；
- 默认每页请求 20 条；
- 重点问题排在待分诊长尾之前；
- 未选择事项时展示行动摘要；
- 详情仍完整展示 links、root cause、impact、evidence、replays、events；
- 云端不渲染任何 mutation 控件；
- 报告页 401/403/404/503 的语义化错误状态；
- 生产构建和移动端布局契约。

生产验收必须使用真实数据，至少确认：

- 报告 API 返回 692 / 1492 / 654 的受治理指标；
- 页面显示 21 项指标、8 项发现和 8 项建议；
- 反馈页显示 87 个有效事项、126 条反馈和 7 条安全隔离记录；
- 生命周期统计与生产投影一致；
- 任一事项可以下钻到现有的根因、证据、复跑和事件数据；
- 未登录访问页面和 API 均为 401；
- `/office/*` 与 FAE 公网应用前后状态不变。

## 10. 发布与回滚

在隔离 worktree 完成 TDD，实现后合并到本地 `master`，只推送 `master`。使用现有原子部署脚本发布并执行真实副本同步。回滚只回退 Platform release；不回滚数据库数据、不修改 AI ADMIN、不重启 FAE。

发布成功标志必须同时包含：生产 release SHA、API 健康、报告路由鉴权验收、真实 Issue 生命周期聚合验收和页面构建产物验收。
