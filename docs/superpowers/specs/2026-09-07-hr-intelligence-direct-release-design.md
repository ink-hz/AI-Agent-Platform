# HR 招聘情报直接发布设计

**日期：** 2026-09-07

**状态：** Owner 已确认方案

## 目标

取消 HR Intelligence Bundle 发布前要求 Owner 再次粘贴 Git SHA 和 Bundle ID 的人工确认。Owner 明确下达“上线”命令后，发布流程直接使用本地已验收的候选版本，不再停在文本审批门禁。

## 方案比较

1. **只取消重复人工确认（采用）**：自动读取当前完整 Git SHA 和指定 Bundle ID，继续执行版本一致性、Bundle 验签、磁盘、发布锁、回滚和业务验收。减少一次无业务价值的复制粘贴，同时保留技术保护。
2. **一次性临时绕过**：本次手工忽略运行手册，后续仍要求文本确认。实现最快，但留下文档与实际流程不一致，容易重复争议。
3. **删除全部发布门禁**：发布最省步骤，但可能把错误提交、损坏 Bundle 或磁盘不足带入生产，不采用。

## 设计

- 删除运行手册中的“两行精确批准”要求，改为 Owner 明确发出上线指令即构成发布授权。
- 发布候选身份由工具自动读取：代码为待推送 `master` 的完整 40 位 SHA，情报为命令参数指向目录名中的 Bundle UUID。
- 发布前仍必须确认：工作树无本任务 tracked 变更、候选分支已通过全量验证、Bundle 严格验签、远端 `master` 未意外前进。
- 先以 `--no-ff` 将完整特性分支合入本地 `master`，只推送 `master`，不推送特性分支。
- 平台发布继续使用现有签名 Release、精确 staging、发布锁、磁盘门禁和自动回滚机制。
- 平台发布成功后再运行现有 `import-hr-intelligence.sh`，只导入已验签 Bundle。导入失败不得改变当前已发布 Bundle。
- 不修改 Nginx 业务路由，不发布或重启 FAE、VOC、行政、Marketing 或其他独立应用。

## 验收

- 门禁测试不再要求 `APPROVE_RELEASE_SHA` 或 `APPROVE_HR_BUNDLE_ID` 文本。
- 本地后端、前端、构建和 Bundle 检索门禁继续通过。
- 发布报告包含发布前后 `df -B1 / /data`、当前及两个回滚版本、staging 清理、Docker 镜像、业务 HTTP 验收，以及是否修改共享 Nginx/其他应用。
- HR 页面能读取新 Bundle，且运行时没有采集、模型分析或“立即更新”入口。
