# HR 智能工作台：最小可靠网页交付边界

状态：Owner 于 2026-09-08 确认本设计方向，授权范围内连续本地实施，无需逐项确认。

## 1. 本次决定

先交付网页 HR 招聘业务闭环，不以完整 18 项双渠道统一重构为前置。保留 09-07 v0.3 的事实权威、冻结输入、认证传输与防重复执行边界；本文件调整交付范围和执行顺序，不另建执行架构。

唯一首批业务验收主线：

对话澄清需求 → 生成 JD/JR → 用户确认入岗位库 → 上传测试简历 → 结合岗位分析 → 生成面试题 → 下载 PDF。

既有官网岗位也必须能进入同一流程。普通咨询无需岗位。已发布招聘情报按需读取，不阻塞普通咨询，不在生产采集/分析。不存在的官网 JR 不伪称已同步；官网职责/要求保留来源，内部 JR 作为生成草稿确认。

## 2. 保留的最小可靠性

| 边界 | 验收要求 |
|---|---|
| 受理 | 先持久化原输入与幂等键，再报告已受理；重试同键不新建 Turn/Attempt |
| 执行 | 同一对话只有一个未结束执行；真实独立 Worker 推进，不由 SSE/API 读请求执行 |
| 结果 | 原结果可恢复；文字与附件传输分离，文件失败不回滚答案 |
| 读取 | 快照、历史、进度来自同一服务端状态；刷新不丢失，不扫描前 100 条猜终态 |
| 上下文 | 冻结当前输入、已确认岗位/候选人版本及明确选择的材料；验证实际送入 Agent |
| 失败 | 失败、取消中、结果可用但旧执行尚未停止分别表示；未知状态不自动重跑 |

结果已保存不等于执行器已停止。保留实际已绑定 run 的认证查询、取回原答案、取消请求和原生停止核验；明确证明停止后才能释放同会话占位。确认按钮、租约超时、HTTP 成功、回调终态或本地查无记录都不能代替停止证据。极少数不可判定异常允许人工排查，但页面必须显示原因，不能一直伪装为正常处理中。

自动重新执行旧 prompt、旧 Session 自动修复重跑、平台重试许可发放不在首批范围；当前 deny-only 行为保留。明确失败后的用户重试创建新 Turn 并保留原失败证据，也须服从原执行停止约束。

## 3. 实现边界

网页 → 现有 Turn/Attempt → 一个独立 HR DirectWorker → 现有签名 Relay Worker → 现有 MetaBot v5。

MetaBot 持久原事件 → 现有签名上行 → Result/附件 → 服务端快照和公开进度 → 网页。

- 复用现有 PostgreSQL，不增加消息中间件、通用任务框架或第二份执行账本。
- Turn/Attempt/Result/Position 各自保留原权威。Mission/task 只保留既有业务附件依赖的兼容关联，不再领取新 worker-owned 工作。
- 正文仍由 conversation_messages 持有；文件仍由现有附件服务持有。网页不建立飞书 Delivery，不伪造已送达或已读。
- 队列领取、续租、原事件投影和原执行查询使用独立有界调度；慢模型/上下文读取不占数据库锁，也不堵取消与已有结果恢复。
- 上下文使用已持久摘要和有界历史，不额外调用规划或摘要模型。当前输入和必要材料引用不截断；超过已冻结预算则明确拒绝，不静默丢内容。
- 保留现有配置模型和工具策略，并在实际启动边界校验，不能只凭先前健康探测保证一致。
- 已发布情报缺损时作有界降级/明确未知，不补读全量大对象或启动在线研究。

## 4. 首批不做

飞书统一入口与身份绑定、Feishu inbox/outbox 全迁移、跨渠道最终发送回执与分片、自动旧 Session 重跑、共享重试许可机制、全平台执行模式迁移、物理删除旧 Mission/task 表。

飞书维持现有入口，不因网页切换而一起启用 v5。既有明确故障单独处理，不将其统一重构变成网页前置。其他 Bot、Brain、群聊、行政、Office、共享 Nginx 不变。

工作台附件上传/下载、官网职责/要求、岗位上下文、候选人简历分析、面试 PDF 均不能以“最小化”为理由删除。旧的能力可直接复用，按新链路补连接和真实验收，而不是重新实现页面/业务域。

## 5. 验收与停止条件

1. 首个可演示检查点是一轮普通网页对话：真实服务链路受理、执行、公开进度、答案落库、快照恢复；不是某个底层类的测试完成。
2. 第二个检查点跑通完整招聘主线，验证模型输入确有指定岗位与简历，产物经真实附件服务下载并核对摘要。
3. 同一主线注入重复提交、刷新/断线、API/Worker 进程重启、回执丢失、文件传输失败；断言不重复调用执行器，已有答案不丢，未确认停止不释放。
4. 单元/契约测试、真实本地 PG/HTTP/进程测试、受控真实模型业务验收分别报告；替代模型只能证明工程链路，不能冒称分析质量或生产可用。
5. 首批发布只验网页涉及的运行边界，不等待飞书迁移；但原磁盘门禁、目标迁移编号、HR 范围与回滚防双执行纪律仍必须满足。
