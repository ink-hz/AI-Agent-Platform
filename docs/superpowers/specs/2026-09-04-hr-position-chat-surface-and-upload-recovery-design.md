# HR 岗位页对话主界面与附件上传修复设计

日期：2026-09-04

## 目标

把岗位详情页从“功能面板堆叠”收敛为以对话为核心的招聘工作界面，同时修复生产环境附件内容上传 409，并将回答后的复制、点赞、倒赞操作对齐 FAE 的成熟样式。

## 已确认问题

- 岗位页顶部、指标、页签、快捷任务、材料入口和对话区域纵向堆叠，主对话被挤窄、挤矮。
- “生成 JD/JR/人才画像/搜寻策略/面试方案”长期占据主页面，但本质上只是对话任务入口。
- 附件入口与输入框割裂，“未选择任何文件”和长说明形成噪声。
- 复制、点赞、倒赞使用文字按钮，和 FAE 已验证的轻量图标交互不一致。
- 生产证据显示附件创建成功，但内容 PUT 返回 409；数据库没有写入尝试，故障发生在 API 对传输层 `Content-Length`/实际读取长度的前置校验，尚未进入数据库或对象存储。

## 设计选择

采用“对话主画布 + 按需上下文抽屉”，不继续增加常驻卡片，也不重写岗位和候选人业务能力。

### 页面结构

1. 保留 HR 工作台全局导航。
2. 岗位页顶部压缩成单行上下文条：返回岗位列表、岗位名称、部门/地点、状态，以及一个“岗位信息”入口。
3. 页面主体只保留宽对话画布；会话列表维持可折叠侧栏，不因打开岗位信息、材料、候选人或成果而卸载当前对话。
4. “上下文、候选人、材料与成果”收进同一个按需打开的详情抽屉，并延续现有懒加载数据逻辑。
5. 五个生成动作收进输入框附近的“招聘任务”菜单，选择后直接提交对应任务；不再以横排按钮占据页面高度。

### 对话输入区

- 使用与 FAE 相同的整块 composer 视觉：输入文本在上，附件和发送操作在底部工具栏。
- 输入区在空会话和有消息时都保持足够宽度与高度。
- 默认只显示回形针入口、简短快捷键提示和发送按钮；无附件时不显示“未选择任何文件”和额度长说明。
- 上传中、失败、就绪文件以紧凑卡片显示在输入框内部；失败卡片保留重试与移除。
- Enter 发送，Shift+Enter 换行；切换详情抽屉和工作台页签不清空输入、附件队列或当前会话。

### 回答操作

- 复制使用 `Copy` 图标；成功后短暂切换为 `Check`，失败显示错误图标。
- 点赞、倒赞使用 `ThumbsUp`、`ThumbsDown` 图标和 FAE 同款悬停/选中状态。
- 图标按钮保留完整 `aria-label` 和 `title`。
- 倒赞仍必须打开现有原因和补充说明面板，不削弱反馈数据。

### 附件上传链路

- API 不再把代理提供的 `Content-Length` 当成唯一可信长度。
- 路由流式读取请求体并累计实际字节数，始终执行 50 MB 硬上限；读取完成后把实际长度交给服务层。
- 服务层继续将实际长度与创建上传时声明的文件大小做一致性校验，因此不会放宽额度或完整性保护。
- 兼容有长度、无长度和 chunked 的合法浏览器/代理请求；实际为空、超限或与声明不一致仍拒绝。
- 前端为创建、内容传输、完成、处理四个阶段提供可理解错误，不再展示 `Attachment API 409`。

## 不在本次范围

- 不改岗位、候选人、材料和成果的后端数据模型。
- 不增加 ClamAV 或新的安全基础设施。
- 不修改 FAE、其他 Bot、共享 Nginx 或权限模型。
- 不改变附件 50 MB 限额、会话保留策略和对象存储校验。

## 验收

- `AI-HR-Bot整体方案.md` 可在生产 HR 对话中完成上传并显示“已就绪”。
- 带附件消息可以发送，刷新会话后附件仍存在并可预览/下载。
- 岗位详情页首屏以对话为主体，详情与生成任务按需出现，切换时当前对话不刷新。
- 空附件状态不再显示“未选择任何文件”和长额度说明。
- 回答底部展示 FAE 风格复制、赞、踩图标；倒赞可输入原因与补充说明。
- 针对上传流、composer、岗位页状态保持和消息操作的自动化测试通过。
