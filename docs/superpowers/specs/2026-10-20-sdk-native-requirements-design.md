# SDK 原生需求管理入口

## 决策

SDK 需求、评审、变更、任务、用例、Bug 和发布以禅道 `OpenOrbbecSDK` 产品为权威来源。平台 `/sdk/` 只提供企业登录后的禅道入口。2026 年 CSV 是待梳理的来源材料，不等同于正式需求，不在原生工作区展示。生产启用 `PLATFORM_SDK_NATIVE_ONLY=1` 后，旧平台需求、评审、任务、CSV 和候选证据 API 全部返回 HTTP 410；旧数据保存在数据库中，后续迁移方案另行设计。不得继续用 `needNotReview=1` 绕开禅道评审。

旧候选证据链依赖平台本地评审和任务链接，不能用于禅道原生创建的需求。首版不展示或开放该链路。构建产物和硬件测试的正式证据方案须在禅道原生流程验收后单独设计，不能把测试用例记录当成真实构建或真机通过。

## 访问与权限

禅道运行在独立浏览器源 `https://sdk.orbbec.com.cn/`，Nginx 只代理本机 `127.0.0.1:18131`。平台会话只控制 `/sdk/` 入口；禅道使用每位员工自己的本地账号和原生权限，不使用共享 API 服务账号登录界面。两套身份暂不声称单点登录。直接访问禅道也必须经过其原生登录与产品权限校验。

当前 ZenTao OSS 22.6 的 `action::editComment` 受 CVE-2026-111346 影响。上线镜像从固定 digest 构建，只在控制器源文件 SHA 匹配时禁用该路由。升级到包含上游修复的版本后重新评估并移除本地补丁。禅道原生界面在 DNS、证书、漏洞缓解、独立用户权限和接口验收全部通过前维持本机监听。

## 验收

1. `/sdk/` 登录后仅展示原生需求入口和简明流程；不请求旧平台需求、CSV 或候选 API。
2. 禅道使用独立 HTTPS 源；未登录不能读取产品内容，普通成员仅能访问已授权范围。
3. 在禅道用员工账号完成需求草稿、评审、变更版本、拆任务、关联测试与发布的真实流程；记录操作者与版本。测试记录与正式业务需求区分。
4. 对 `action::editComment` 访问返回拒绝；构建镜像遇到未知上游源文件立即失败。
5. GitLab API、Issue、MR 和流水线保持未接入。旧平台候选 API 在原生模式中关闭，不能声称完成构建与发布自动化。
