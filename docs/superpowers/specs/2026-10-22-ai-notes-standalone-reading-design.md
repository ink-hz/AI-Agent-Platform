# AI 工程笔记独立阅读页设计

## 目标

员工可直接访问或分享 `https://agent.orbbec.com.cn/ai-notes` 及文章链接。工程笔记作为独立阅读页呈现，不占用 Agent Platform 的全局侧栏；从平台入口打开时保留原工作页。

## 方案

沿用现有 `/ai-notes` 路由、文章 API、钉钉登录和应用构建。在应用框架内，笔记路由渲染独立的窄页头、文章目录和阅读区；页头提供返回 AI 助手和企业账号入口。平台侧栏、AI 助手首页和公司全景的工程笔记链接以新页签打开相同地址。笔记不再属于公司全景的内部工作区；旧历史状态也不能把笔记重新包入全景。文章内目录选择继续更新 `/ai-notes/{category}/{article}`，刷新、分享和登录后返回原文章仍走已有路由契约。

独立 Vite 应用会重复身份、资源和发布链路；仅把现有平台页面放入新页签无法消除全局侧栏。因此使用同一应用的独立页面框架。

## 边界与验收

- 笔记目录和文章页面不显示平台全局导航；桌面、移动端保留笔记自身目录和阅读区。
- 从平台侧栏、AI 助手首页和公司全景打开新页签，原页面及未提交输入保留。浏览器修饰键仍使用原生链接行为。
- `/ai-notes`、`/ai-notes/`、文章深链在匿名状态提供静态登录壳；正文 API 仍须鉴权。无权限或目录失效时沿用现有错误提示。
- 前端组件测试覆盖两种入口、独立页面框架和登录返回；本地构建与相关后端鉴权测试通过后，只更新平台 API 容器并核对静态资源哈希。浏览器与钉钉内交互验收由用户执行。
