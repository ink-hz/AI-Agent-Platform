# AI 工程笔记独立阅读页设计

## 目标

员工可直接访问或分享 `https://agent.orbbec.com.cn/ai-notes` 及文章链接。工程笔记作为独立阅读页呈现，不占用 Agent Platform 的全局侧栏；从平台入口打开时保留原工作页。

## 方案

沿用现有 `/ai-notes` 路由、文章 API、钉钉登录和应用构建。在应用框架内，笔记路由直接渲染自己的左侧文章目录和右侧阅读区；返回平台的入口放在左侧目录内。平台侧栏、AI 助手首页和公司全景的工程笔记链接以新页签打开相同地址。笔记不再属于公司全景的内部工作区；旧历史状态也不能把笔记重新包入全景。在 `/ai-notes` 展示首篇文章时保留根地址，目录选择才更新为 `/ai-notes/{category}/{article}`；刷新、分享和登录后返回原文章仍走已有路由契约。

独立 Vite 应用会重复身份、资源和发布链路；仅把现有平台页面放入新页签无法消除全局侧栏。因此使用同一应用的独立页面框架。

## 布局复核（2026-10-22）

独立页首版同时加了顶部导航，并继续给笔记主体设置平台的 `reading` 布局属性。该布局的列宽、间距和圆角变量仅定义在 `.platform-shell`，独立页不在此节点下，导致依赖的声明失效；顶部导航还重复了笔记目录中的标题。修正后的职责是：独立外壳只负责占满视口和滚动边界，笔记组件自身负责两栏布局、移动目录和文章排版，平台的布局属性只用于平台内页面。这样根页和文章深链复用同一套笔记布局，不再依赖全局平台导航变量。

## 边界与验收

- 笔记目录和文章页面不显示平台全局导航；桌面、移动端保留笔记自身目录和阅读区。
- `/ai-notes` 保持为可分享的根地址，默认文章不改写浏览器地址；从目录明确选择文章后才进入文章深链。
- 从平台侧栏、AI 助手首页和公司全景打开新页签，原页面及未提交输入保留。浏览器修饰键仍使用原生链接行为。
- `/ai-notes`、`/ai-notes/`、文章深链在匿名状态提供静态登录壳；正文 API 仍须鉴权。无权限或目录失效时沿用现有错误提示。
- 前端组件测试覆盖两种入口、独立页面框架和登录返回；本地构建与相关后端鉴权测试通过后，只更新平台 API 容器并核对静态资源哈希。浏览器与钉钉内交互验收由用户执行。
