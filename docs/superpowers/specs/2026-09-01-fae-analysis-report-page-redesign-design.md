# FAE Agent 生产成果报告页面重设计

日期：2026-09-01

状态：产品设计已确认，等待书面设计复核

范围：Agent Platform 的 `/admin/fae/reports`、`/admin/fae/reports/{report_id}` 及其只读报告 API

明确不涉及：FAE 公网问答应用、FAE 推理链路、AI ADMIN `/office/*`、生产原始会话写入和分析模型重跑

## 1. 背景与现状

FAE 工作台已经接入第一份真实、经过复审的冻结生产报告。当前生产报告包含：

- 692 个生产 Session；
- 1492 个问答 Turn；
- 654 个完成独立复审的 Session；
- 21 项结构化指标；
- 8 项分析发现；
- 8 项改进建议；
- 0 个经过业务批准的脱敏案例。

报告数据本身足以支撑正式成果阅读，但当前页面把四个维度统一渲染成同一种指标卡片、发现卡片和建议列表。异构的计数、比例、分布和时延被压成重复网格，长分布被拼接为文本；发现与同名建议又被重复展示。页面虽然真实，却既不像管理层成果报告，也不利于 FAE 团队理解质量与改进重点。

当前实现还存在以下产品缺口：

- 第一屏没有形成“已经进入真实生产并产生业务价值”的明确结论；
- 692、179、216 等关键数字权重接近，已实现价值与潜在价值区分不够强；
- 654 个独立复审 Session 没有承担可信度背书的角色；
- 产品族、能力需求、质量比例和时延分位数没有适合其数据形状的表达；
- 当前前端只消费 `latest` 和默认 `detail`，没有使用已经存在的报告列表和版本参数；
- Evidence、Finding 与 Recommendation 的显式关联没有转化为有效下钻；
- 页面仍使用 `AI FAE PRODUCTION OUTCOME` 等工程化英文眉题；
- 管理层、FAE 团队和 Platform Owner 的阅读深度尚未形成服务端投影边界。

## 2. 产品目标

页面的核心叙事固定为：

> FAE Agent 已经在真实生产中形成规模，并产生了可量化、可审计的业务价值。

用户打开页面十秒内应能回答：

1. 这是不是一个真实投入生产的系统；
2. 它承接了多少、什么复杂度的工作；
3. 哪些价值已经由复审确认，哪些仍只是增长潜力；
4. 结论由多少真实数据和复审覆盖支撑。

继续阅读后，页面应回答：

1. 使用深度和需求结构是什么；
2. 已实现价值与增长潜力分别是什么；
3. 回答质量、交付可靠性和现有局限如何；
4. 生产数据暴露了哪些产品、资料和 Agent 改进机会；
5. 关键发现可以下钻到哪些受权限保护的证据和治理事项。

## 3. 非目标

- 不把页面改造成通用 BI 工具；
- 不在浏览器运行分析任务或模型评测；
- 不使用 Mock、演示数字或静态 HTML 替代结构化报告；
- 不从原始会话自动生成未经批准的典型案例；
- 不推翻 `fae.analysis-report` v1 契约；
- 不把实时运营数据混入不可变冻结报告；
- 不在前端硬编码本次 692、1492、179 或 216 等数值；
- 不复制 Session、Turn、Issue 或 Review 详情页；
- 不用颜色、单一评分或未经批准的阈值把事实包装成好坏结论。

## 4. 方案选择

采用“成果叙事 + 证据下钻”的正式管理报告。

比较过的方案：

- 运营数据大盘：筛选和图表密度高，适合日常监控，但会弱化业务结论，并与 FAE 概览重复；
- 电子白皮书：阅读感强，但版本比较、持续更新、权限投影和证据下钻较弱；
- 成果叙事 + 证据下钻：先给管理结论，再按四个维度解释事实，并允许授权用户进入治理证据。该方案被采用。

实时运营指标继续由 FAE 概览承担；分析报告页只阅读经过发布门禁的冻结报告。当实时数据晚于报告截止时间时，页面提示“生产数据已有更新”，并提供回到概览的入口。

## 5. 页面信息架构

页面固定为以下阅读顺序：

1. 生产成果封面；
2. 使用情况；
3. 业务价值及经批准的典型案例；
4. 回答效果；
5. 业务洞察与改进；
6. 折叠的报告口径与技术信息。

宽屏右侧显示章节目录；窄屏改为内容顶部的横向章节导航。章节数量固定为四个，不因新指标增加一级频道。

### 5.1 生产成果封面

页面标题使用“FAE Agent 生产成果”。删除工程化英文眉题。

封面包含：

- 报告标题、版本、周期和数据截止时间；
- 一句经过发布的管理层结论；
- 692 类“生产 Session”主数字和 1492 类“真实业务问答”次数字；
- 独立复审覆盖，显示为 `reviewed_session_count / session_count` 及其比例；
- 复杂业务承接证据：多轮、图片/附件、非工作时段；
- 已实现价值；
- 增长潜力。

“已实现价值”使用受治理的绿色语义，“增长潜力”使用蓝色语义。两者必须独立布局并包含明确说明：潜在价值不计入已实现成绩。页面不得声称节省工时、替代人力或创造收入，除非后续报告发布了相应的受复审指标和统计口径。

复审覆盖是报告可信度背书，不作为普通 KPI 卡片。复杂工作证据共同证明系统承接的不是简单 FAQ，不能把多轮会话数单独包装成业务价值。

### 5.2 使用情况

章节开头固定回答：“FAE Agent 是否承接了持续、复杂且带多模态输入的生产咨询？”

展示顺序：

1. Session、Turn、多轮会话、图片/附件会话、非工作时段会话；
2. 产品族横向排名；
3. 高频能力需求横向排名。

计数与比例按报告中实际字段展示。没有分母时只显示计数和已发布口径，不自行发明占比。能力标签可能在同一 Session 上重叠，必须标注“非互斥统计”。被隐私门禁压成“少于 5”的项保持原样，不推算真实值，也不参与精确条形长度比较。

冻结报告没有时间序列时不绘制伪趋势线。实时趋势留在 FAE 概览。

### 5.3 业务价值

章节首先呈现两个彼此独立的视觉语义区域：

- 已实现价值：由 `value.assisted_reviewed_sessions` 等受复审指标驱动；
- 增长潜力：由 `value.scenario_potential_conversion_sessions` 等潜力指标驱动。

每个区域都显示数值、统计范围、判断口径和数据截止时间。潜力区域固定显示“尚未完全闭环，不计入已实现成绩”。

典型案例只来自 `business_case_approved=true` 的报告案例。当前报告没有批准案例时，以一行克制说明“典型案例待业务批准”，不渲染大块空白卡片，不从 Evidence 或原始 Session 自动抽取内容充数。

### 5.4 回答效果

章节拆成两个子区：

**回答质量**

- 独立复审数量及覆盖；
- 完全解决率及分子/分母；
- 首轮解决率及分子/分母；
- 多轮收敛率及分子/分母。

**交付可靠性**

- 负反馈影响 Session 和 Turn；
- Fallback 回答占比；
- P50、P90、P95 回答时延。

比例使用带数字标签的水平比例尺，时延使用分位数带。没有经过批准的质量目标时，页面不使用红黄绿状态、不生成总分，也不把低于任意阈值称为“不达标”。Assumptions、filters 和 denominator 通过口径入口展示。

### 5.5 业务洞察与改进

章节顶部展示：

- 产品与资料信号；
- 业务场景分布；
- 问题层级分布；
- 受治理根因家族数量。

发现与建议不再分别重复。页面根据 `ReportFinding.recommendation_ids` 和 `ReportRecommendation.finding_ids` 的显式双向关系组装“改进主题”，不得根据相同标题猜测关联。

每个改进主题依次显示：

1. 优先级；
2. 发现与影响范围；
3. 根因假设；
4. 建议行动；
5. 责任角色；
6. 成功指标；
7. 已关联的治理问题和证据。

已关联 Issue 的主题可以进入“反馈与修复”详情。没有关联的主题明确显示“待建立治理关联”，不能伪装成已闭环。

## 6. 证据与口径交互

每个主要数字提供一个轻量口径入口，内容来自报告现有字段：

- 分子和分母；
- filters；
- assumptions；
- evidence artifact 引用；
- 数据周期与截止时间。

管理报告不复制原始会话全文。Evidence 下钻规则为：

- Metric 只显示统计口径，不直接展开私有样本；
- Finding 的 Session、Turn、Feedback、Issue Evidence 先由服务端做授权解析；
- 有权限且证据存在时，返回精确 Session、Turn 或 Issue 页面地址；
- 数据镜像未同步时，显示不可用原因；
- 权限不足时返回 403，不通过空链接或 404 猜测对象是否存在；
- 非 Owner 响应不包含原始 canonical key。

## 7. 版本与新旧状态

页面默认打开最新一份 `ready` 报告。顶部版本选择器显示：

- 报告截止时间；
- report version；
- ready / failed 状态；
- generated time；
- imported time。

规则：

- 报告发布后不可原地修改；
- 同一 `report_id` 的历史版本通过 `?version=N` 阅读；
- 新尝试失败时保留上一份 ready 报告作为默认可读版本；
- Owner 可以查看脱敏的失败阶段、错误码与是否可重试；
- `latest_source_sync_at > data_cutoff_at` 时显示“生产数据已有更新”；
- 报告数据领先于镜像时，报告主体可读，Evidence 下钻显示等待同步；
- 实时数据与冻结报告不得在同一数字上无标识混算。

当前后端已有列表、latest 和带 version 的 detail 能力。前端需要消费这些能力。列表接口应返回轻量报告摘要，避免为了版本选择加载所有指标、发现和证据；详情接口继续返回单份完整投影。

## 8. 权限投影

产品权限分为三层：

### 8.1 管理层成果阅读

可见：成果封面、四个维度的聚合结论、公开统计口径和批准案例。

不可见：原始 Evidence Key、具体 Session/Turn、客户身份、未经批准案例、技术失败正文。

### 8.2 FAE 团队运营阅读

在管理层内容基础上增加：回答质量、可靠性、产品与资料信号、改进行动和允许的聚合治理状态。

### 8.3 Platform Owner

可见完整发布报告、精确 Evidence 解析、关联 Issue、Session/Turn 下钻、技术口径和脱敏失败信息。

权限必须由服务端生成不同投影，不能只在 React 中隐藏字段。第一期若组织授权名单尚未配置，继续保持当前 Owner/Admin 边界并明确记录，不能临时把完整报告开放给 member。权限扩展需要复用 Platform 现有身份和授权底座，不新增第二套账号体系。

## 9. 指标呈现注册表

Platform 前端维护稳定的呈现注册表，键为 `metric_id`，值只包含：

- 所属章节与子分组；
- 展示顺序；
- renderer kind：number、ratio、ranked distribution、latency quantiles；
- 是否允许进入管理层封面；
- 必要的语义提示，例如“非互斥统计”。

注册表不包含任何本期数值、Evidence、分析结论或业务阈值。所有数据仍来自结构化报告。

未知 metric ID 不得静默消失。它进入当前维度末尾的“其他已发布指标”，使用安全的通用 renderer，并产生前端契约测试或可观测治理提示。非法数据形状由严格客户端解析器拒绝，不以 `String(value)` 掩盖契约错误。

封面派生值仅允许由同一报告中具名字段按稳定公式计算，例如 `reviewed_session_count / session_count`。派生值必须展示原始分子与分母，且不能改变报告的业务含义。

前端拆分为：

```text
FaeReportsPage
├── ReportVersionHeader
├── ExecutiveOutcomeCover
│   ├── ProductionScale
│   ├── ReviewCoverage
│   ├── ComplexWorkEvidence
│   ├── RealizedValue

├── UsageChapter
├── BusinessValueChapter
│   └── ApprovedBusinessCases
├── AnswerEffectivenessChapter
├── InsightAndImprovementChapter
└── ReportMethodologyDetails
```

删除当前统一 `DimensionSection` 的表现职责。四章仍共享排版原语、口径入口和安全的数值格式器，但每章拥有适合其内容的结构。

建议的代码边界：

- `faeReportPresentation.ts`：指标注册表、排序和安全派生；
- `components/fae-reports/ReportMetric.tsx`：数字、比例、排名和分位数原语；
- `components/fae-reports/ReportEvidenceLink.tsx`：权限感知 Evidence 状态；
- `components/fae-reports/ReportImprovementTheme.tsx`：显式关联后的发现与行动；
- `pages/FaeReportsPage.tsx`：数据加载、版本和页面状态；
- `pages/FaeReportDetailPage.tsx`：报告正文。若保留单页组件，也必须保持上述职责分离。

## 11. 视觉与响应式

页面采用白色阅读底、深蓝正文、绿色已实现价值、蓝色增长潜力、琥珀色风险。禁止大面积装饰渐变、发光效果、假头像和无意义图标。

主阅读列约 760–900px。宽屏在右侧提供约 220–260px 的章节目录与版本信息；低于 1100px 时收为单列；手机端章节导航可以横向滚动，但正文、图表和口径必须保持自然阅读顺序。

所有图形同时提供可读数字和文字标签。键盘焦点顺序与视觉顺序一致；章节锚点使用稳定 ID；链接和按钮具有明显焦点态；`prefers-reduced-motion` 下不使用滚动动画。打印样式隐藏平台导航和交互按钮，保留标题、周期、口径、主要数字及页内章节。

## 12. 页面状态与错误处理

- 无报告：显示“尚未发布经过复审的分析报告”；
- 404 指定版本：显示报告或版本不存在，不泄露未授权对象；
- 401：要求重新登录企业账号；
- 403：说明当前账号没有报告阅读权限；
- 503：保留工作台导航和重试入口，不声称 FAE Agent 故障；
- Source updated：显示报告截止时间和最新同步时间，并链接 FAE 概览；
- Evidence not synced：报告主体可读，具体证据显示等待同步；
- Failed attempt：显示脱敏 stage/code/message，不渲染虚假的发现与指标；
- 单个未知指标：进入通用指标区，不让整份报告空白；
- 整体契约非法：拒绝渲染并显示“报告内容未通过读取校验”。

页面在刷新、前进后退、指定 report ID 和 `?version=N` 下保持相同阅读位置和版本语义。

## 13. 实施阶段

### 阶段 1：阅读体验重构

- 建立指标呈现注册表和严格格式器；
- 实现成果封面和四章专用组件；
- 使用当前真实 report v1 验证 21 项指标、8 项发现和 8 项建议；
- 删除重复的发现/建议呈现；
- 保持现有 Owner/Admin 权限。

### 阶段 2：报告索引与版本

- 前端消费报告列表和 `?version=N`；
- 列表改为轻量摘要契约；
- 增加最新 ready、失败尝试、source updated 和历史版本状态；
- 保证 canonical route 与浏览器导航。

### 阶段 3：权限与证据

- 增加三层服务端投影；
- 增加精确 Evidence resolve；
- 配置管理层和 FAE 团队的明确授权；
- 验证非 Owner 不接收 canonical evidence key。

### 阶段 4：可访问性与交付

- 完成手机、窄屏、键盘和打印样式；
- 验收所有错误、新旧和空状态；
- 使用生产报告执行真实页面验收；
- 确认 AI ADMIN `/office/*` 与 FAE 公网应用未发生变化。

## 14. TDD 与验收

实现遵循测试驱动开发。先写失败测试，再做最小实现。

前端至少覆盖：

- 第一屏突出生产规模、复审覆盖、已实现价值和增长潜力；
- 已实现价值与潜力具有不同语义且潜力带免责声明；
- 21 个指标按稳定注册表进入正确章节；
- 未知指标进入通用区域而不是消失；
- 分布数据按排序条展示，`少于 5` 不被推算；
- 比例显示 numerator/denominator，时延显示 P50/P90/P95；
- 8 个 Finding 和 8 个 Recommendation 按显式 ID 组装，不重复成 16 张卡；
- 无批准案例时仅显示克制说明；
- 列表、latest、指定 report、指定 version、返回导航和刷新；
- 401、403、404、503、failed、source_updated 和 evidence not synced；
- 手机断点、键盘焦点、章节锚点和打印结构；
- 页面不出现 `AI FAE PRODUCTION OUTCOME` 或硬编码的生产数字。

后端至少覆盖：

- 列表摘要不包含完整 metrics、findings、evidence；
- latest 选择最新 ready，而不是最新 failed；
- version 精确读取；
- 三层投影字段矩阵；
- 未授权 Evidence 不可通过响应差异探测；
- Evidence resolve 精确到 Session、Turn、Feedback 或 Issue；
- source updated 与 report ahead of mirror 的时间边界；
- failed 报告只返回受允许的脱敏失败信息。

生产验收至少确认：

- 当前报告显示 692 个 Session、1492 个 Turn、654 个复审 Session；
- 已实现价值 179 与增长潜力 216 分区呈现；
- 使用、价值、效果、洞察四章完整；
- 21 项指标不丢失，8 个改进主题不重复；
