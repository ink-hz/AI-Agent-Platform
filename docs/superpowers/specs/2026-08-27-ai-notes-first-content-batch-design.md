## 背景与目标

AI 工程笔记页面已经具备左侧分类树、Markdown 阅读器和首页入口，但内容目录目前没有已发布文章。首批迁移从个人博客源码 `/Users/neo/Developer/personal/starship-blog-source` 中选择五篇以 AI 为主体的文章，清除旧站和旧组织语境，按当前公司的内部发布时间重新发布。

本批次的目标是：上线后五个分类各有一篇可阅读的代表文章；内容只服务于员工学习 AI 技术和 AI 工程实践；平台不依赖个人博客仓库。

五篇文章的作者统一为“苍渊”。作者作为结构化内容元数据进入 API 和阅读页，不在正文末尾重复手写署名。

## 内容准入标准

文章只有同时满足以下条件才进入 AI 工程笔记：

1. 主体是大模型、Agent、RAG、AI 开发工具或 AI 工程实践，而不是仅在标题或段落中提到 AI。
2. 能直接提高员工对 AI 原理、架构、工具或工程落地的理解。
3. 内容可以脱离原公司、原项目和个人博客独立成立。
4. 关键技术事实能够由官方文档、规范或研究论文等一手资料核验。

云原生、安全、投资、创业、读书、健康等泛技术或个人主题不进入本页面，即使文章中出现 AI。相同主题的重复稿只保留内容质量更高的一篇。

## 逐篇清洗规则

每篇文章单独处理、校验和提交，禁止批量原样复制。

### 通用处理

- 用当前内容模型重写 frontmatter，包括标题、稳定 slug、摘要、作者、标签、`publishedAt`、`updatedAt` 和 `draft`；本批次 `author` 固定为 `苍渊`。
- 阅读页已经在正文外渲染标题，因此删除正文中重复的一级标题。正文从导语或二级标题开始。
- 删除旧发布日期、旧更新时间、个人博客语气、旧站链接、作者品牌和与学习目标无关的宣传性表达。
- 删除或抽象化旧公司、项目、人员、客户、内部链接和组织上下文，不用虚构的新公司案例替换。
- 将“真实项目”“数百个 API”“多少行、多少轮、几天完成”等不可公开验证的经历性数字改成通用的工程条件、步骤或观察；只有确有保留价值且不暴露旧组织信息的经验结论才保留。
- 保留有学习价值的 Markdown 表格、代码块和 Mermaid；修复语法，移除原始 HTML。示例中的公司、营收、客户等数据改为明确的虚构示例或中性占位。
- 修复失效链接。容易变化的产品能力、API、框架定位和版本信息必须在迁移当天使用官方文档或一手论文核验；无法确认的内容标注为推断或删除。
- 去除绝对化、营销化和无法证明的结论，区分“公开事实”“工程推断”“作者建议”。

### 文章侧重点

- Agent 系统手册：保留 Agent loop、运行时、工具、上下文、治理、评估和落地路线；压缩重复的框架清单，避免形成过时的产品百科。
- 企业级 Agent 系统架构：保留状态机、信任层级、Hook、子 Agent、Prompt 分层、上下文、制品和测试体系；完全移除原项目规模、迭代次数和交付周期。
- Claude Code 架构分析：只把 Anthropic 官方公开能力写成事实；内部实现只能作为明确标注的工程推断。旧链接按当前官方文档结构更新。
- 向量数据库与 RAG：保留向量检索、Embedding、混合检索、RAG 和 GraphRAG；删除过时的模型知识截止日期示例，修正来源、术语和产品对比。
- AI Native 辅助架构设计：保留人机分工、材料治理、迭代审视、决策记录和质量门禁；改写基于“两项目、2800 行、19 轮、3 天”的旧经历叙事。

## 旧标记防护

首次迁移同步维护 `backend/app/ai_notes/legacy_markers.yaml`，至少加入源码中已确认的旧站或个人品牌标记：

- `inkbot.cn`
- `Ink Blog`
- `STARSHIP`
- `星舰`

迁移过程中如果识别出新的旧公司名称、域名、项目代号或人员标记，先加入清单，再继续发布。校验器应阻止含有这些标记的已发布文章进入目录。清单只保存标记，不保存或输出命中的正文。

## 发布流程

每篇文章先以 `draft: true` 进入目标目录，完成清洗、事实核验、内容校验和本地预览后，再设为 `draft: false`。首批文章的内部发布日期和更新时间均为 `2026-08-27`；这表示在当前平台的首次发布时间，不伪装成历史发布时间。

本批次已由内容负责人批准五篇候选和“仅 AI 主题”的范围。每篇清洗结果仍保持独立提交，便于逐篇审阅、撤回或继续修订。五篇全部达到发布标准后随平台统一上线。

## 展示与数据流

本批次沿用页面和 API 架构，只扩展作者字段：

1. 后端启动时扫描 `backend/app/ai_notes/content`。
2. 文章 frontmatter 的 `author` 为必填非空字符串，并由后端映射到目录摘要和单篇文章 API。
3. 只有 `draft: false` 且通过校验的文章进入只读索引。
4. 左侧目录树按分类目录和文件数字前缀排序。
5. 用户点击文章后，阅读页在标题下的元数据行显示 `作者：苍渊`，随后显示发布日期、更新时间和阅读时长。
6. 前端通过现有 API 获取 Markdown，并使用现有 GFM、代码高亮和 Mermaid 渲染能力展示。
7. 首页仅保留进入 AI 工程笔记的入口，不增加顶部标签栏或文章卡片区。

若某一篇未达到内容标准，它继续保持草稿且不影响其他文章发布；不得为凑满分类而降低准入标准。
