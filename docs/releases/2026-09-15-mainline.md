## 部署期间发现的扫码入口问题

用户从 HR 进入 `/login?return_path=%2Fhr%2F`，点扫码按钮后立即出现“登录未完成”，二维码尚未出现。不是钉钉扫码确认后的回调错误。

接口复现：未取得浏览器登录 challenge 时，POST `/api/v1/auth/dingtalk/start` 返回 400 `login request invalid`；先 GET `/login`，使用服务器发出的 Cookie 再 POST，同一路径返回 200 和钉钉授权 URL。未打印 challenge、OAuth state、授权 URL 或令牌。

代码根因：`App.tsx` 遇到会话失效时使用 SPA navigate 显示登录页，不请求服务器 `/login`，因此不一定取得 HttpOnly challenge；已打开页面的 challenge 又只有 600 秒有效期。`startQrLogin` 原来直接 POST，缺失或过期均被拒绝，前端只显示通用错误。

修复为点击扫码时先以 credentials=include、cache=no-store 请求已有 `/login`，校验成功后再走原 start 接口；原身份校验、限流、回跳路径和仅允许 login.dingtalk.com 的授权 URL 校验保持不变。刷新失败不提交扫码请求，没有绕过 challenge 或新增匿名放行。此补丁只处理扫码入口，钉钉客户端内免登不在本次完成范围。

验证：新增 4 项用例在修复前失败，修复后通过；覆盖 SPA 缺失/停留过期、正式与预览前缀、刷新失败及外部授权 URL 拒绝。与 auth/LoginPage 一起 118 项通过，TypeScript 与 Vite 构建通过。该项为前端请求边界测试；上述生产 HTTP 另外验证真实 Cookie 机制，不称为用户实际扫码成功。
