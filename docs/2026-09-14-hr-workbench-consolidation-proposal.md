## 1. 基线核实与边界

- `App.tsx` 确实将三个主对话地址交给 `HrLoopWorkspace`，另七条交给 `HrWorkspacePage cloudPrimary`。
- 历史对话禁止发送；普通岗位快捷动作、方法和情报选择通过 `openHrWork()` 转到主对话。带旧成果、候选人、附件或标准确认授权的 `fill()` **显示错误并返回，不执行跳转**。岗位名称/详情链接仍能进入详情，“选择岗位继续工作”才跳主对话。旧候选人组件还有写操作，不能笼统视为全部只读。
- 云端已有候选人建档/工作、方法/情报选择、成果查询和标准确认接口，但按钮存在不证明已覆盖独立岗位资料、历史版本和全部下载旅程。收敛不能只改七个路由的组件名。
- 指定报告路由还有真实读取缺口：`HrPanoramaWorkspace` 的归档判断只看 query，不看 `insightVersionId`；`HrLegacyPanoramaWorkspace` 声明该属性但没有消费。方案必须补准确报告读取。这不是 master-only 的白名单 403 问题，不修改已正确的 `{bundle_id}` 白名单。
- 测试书目需要校正：当前 `HrP0Combined.acceptance.test.tsx` 的唯一用例已是历史对话/成果只读，原整条招聘旅程已不在运行；`HrPositionSpine.acceptance.test.tsx` 在 `7b041174` 被删除。`HrPanorama.acceptance.test.tsx` 目前只核验公司目录及固定版本详情，不能单独证明导出/原始证据下载。任务书要求的业务旅程仍须恢复到新链验收。

## 2. 方案选择与页面职责

| 选择 | 得失 | 结论 |
| --- | --- | --- |
| 独立路由 + 一个 HR 壳 + 共享工作状态 | 岗位/情报可直接打开、刷新、后退；不丢聊天草稿；需要抽取状态与准确读取适配 | 推荐 |
| 全部塞进主对话抽屉 | 路由较少，但岗位与资料再次变成侧栏目录，历史深链接需额外协议，继续扩大单文件 | 不采用 |
| 保留两套工作台并补跳转 | 改动起步少，但继续维护两套草稿、对象范围和确认逻辑，无法一次退出 | 不采用 |

推荐导航保持“对话、岗位、HR 情报”；方法作为按需打开的阅读面板。候选人从岗位关联列表和对话的候选人入口进入同一候选人页面，不为本轮增加全平台人才库。

- **对话**：主体只放消息、输入和本次已选参考；材料、方法、成果按需展开。纯咨询无须建岗位，选岗位只确定本次工作对象，不自动发送。四类状态独立说明。
- **岗位列表**：每行显示岗位名称、来源/业务状态、最近更新和打开入口；搜索与筛选作用于完整分页数据，不做卡片墙。点击岗位名称进入资料页，选择岗位不意外开始工作。官网岗位、内部岗位、待确认草案的处置保留，草案合并需要用户选择可辨认的目标。
- **岗位资料页**：正文依次组织官网原文、当前标准、材料、候选人、已保存成果；历史版本/历史对话按需展开。岗位是资料归属，不是强制招聘步骤向导。成果按实际类型提供筛选，允许没有标准先讨论或准备面试。
- **HR 情报**：保留已上线的“原始资料 / AI 分析报告”两层及公司聚合阅读，方法/情报选择器不能替代这两层。历史情报归档在此进入，正文优先，证据展开，浏览不触发生产任务。
- **候选人**：复用云端候选人材料、人工核对、关联工作及面试原文能力。姓名与已审阅摘要可编辑，事实以业务标签呈现，用户在摘要中纠正和说明；不增加任意结构化字段编辑接口，没有 JSON 输入框。待确认同名身份必须主动选择新建或关联，目标显示姓名及可辨认的材料/岗位信息。

结构建议：`HrWorkspaceShell` 统一导航；一个按用户隔离的工作会话控制器持有工作、草稿、参考和上传状态；`HrLoopWorkspace` 缩为对话视图；新增岗位列表/资料、历史对话、统一成果阅读组件。保留下面列明的业务阅读组件。控制器不另建执行器，所有新工作只通过 `/api/hr/agent`。

## 3. 路由对照与一次切换

表中“切换日”是同一个发布时点，不是七次逐入口迁移。保留原地址不等于保留原工作台。

| 地址 | 当前承载 | 切换后的归属/行为 | 旧界面何时停止承载流量 |
| --- | --- | --- | --- |
| `/hr/`、`/hr/agent`、`/hr/chat` | 云端对话 | 统一壳中的云端对话，继续接收岗位/work 参数；别名不创建第二份工作 | 切换日同时接入统一状态；没有新旧发送双路 |
| `/hr/positions` | `HrWorkspacePage` + `HrPositionIndex` | **并入新链**：独立岗位列表，新工作由云端提交 | 切换日删除旧索引挂载 |
| `/hr/positions/:id` | 旧岗位工作流 | **并入新链**：岗位资料页，读取当前资料及分区历史 | 切换日删除旧工作流挂载 |
| `/hr/positions/:id/:section` | 旧工作流的 section | **并入新链**：`context` 打开标准；`candidates` 打开岗位候选人；`artifacts` 打开材料/成果；`chat` 打开该岗位关联对话列表，用户再选具体工作。未知 section 显示不存在 | 切换日同批替换，不保留逐段转发旧壳 |
| `/hr/positions/:id/conversations/:cid` | 旧只读对话 | **明确历史归档**：新历史阅读器；后端核对岗位与会话关联；不把 cid 当 cloud workId | 切换日停止旧壳/旧输入框挂载；原地址直接由新阅读器承载 |
| `/hr/conversations/:cid` | 旧只读对话 | **明确历史归档**：同一个历史阅读器，保留原会话与准确成果；没有发送/重试/确认按钮 | 同上 |
| `/hr/panorama` | 旧壳 + 两层情报/归档 | **并入新工作台**：保留两层独立阅读；`view=archive/topics`、`company/topic/bundle_id` 仍准确打开相应归档 | 切换日去掉旧顶层工作台；阅读组件只在新壳内承载 |
| `/hr/panorama/reports/:id` | 参数未被正确消费的情报页面 | **明确历史归档**：优先打开指定发布报告，带原始证据和既有导出；不加载默认目录替代正文 | 切换日由准确报告阅读器直接接管；不跳根目录 |

七条地址均不采用临时 `legacy-redirect`；它们承载真实资料，应直接解析到目标页面。新云端会话仍使用 `/hr/?work=…`，与旧 `cid` 命名空间分开。

新增成果深链接建议为 `/hr/results/:id?revision=…`（云端）和 `/hr/history/results/:id`（旧成果）；候选人链接为 `/hr/candidates/:id`，可附明确的岗位上下文。登录回跳、应用前缀、返回上一页和授权路由白名单同步覆盖；无权限或不存在显示真实状态，不跳到另一个“可用”对象。

**报告标识约定**：后端报告 API 接收 `bundle_id`，`hrPanoramaApi` 的 `publicationId` 当前等于 bundleId，路由字段名却是 `insightVersionId`。目标路由内部改名为 report/bundle 标识；盘点旧链接，若输入确为旧 insight ID，则由受认证的只读映射解析到唯一发布包。无映射或多义就显示不可定位，不取 current，不把任意 UUID 直接当成另一种 ID。映射不是保留旧 UI，也不改变原始报告身份。

## 4. 历史内容与读取契约

| 内容 | 新入口 | 读取与续作边界 |
| --- | --- | --- |
| 云端已保存成果 | 来源对话、关联岗位、关联候选人，均进入同一阅读器 | 使用 `results` 的 thread/position/candidate 单对象过滤和准确 revision；同一内容只保存一份，分页读完整。文件下载必须拿到真实字节 |
| 旧已保存成果/比较/面试方案及记录 | 对话历史、岗位成果历史、候选人历史记录 | 复用旧只读 API 与原身份，正文、关联和下载迁入专用阅读适配器；不保留旧确认/发送逻辑。已有三入口关联必须保住，缺少候选人索引时补受认证只读查询，不能仅藏进全局“历史” |
| 当前已确认标准 | 岗位标准区、对话已选岗位摘要 | 云端 `standards/current` 是新工作基准；历史 R12 当前快照单独标“切换前确认”，不伪装成云端确认或静默迁成新标准 |
| 历史确认版本 | 岗位标准区的“历史版本”，成果中原基准链接 | 保留原确认人/时间、正文与准确版本；云端客户端目前只有 current/confirm，须补历史列表及准确版本只读 API，再与旧 context 历史分来源呈现 |
| 历史对话 | 对话列表的“历史对话”、岗位关联对话 | 按真实 owner/授权读取消息和成果；新阅读器不挂可发送的旧输入框。营销等共用 Direct 工作台保留 |
| 历史公司/专题、报告与证据 | HR 情报“历史归档”、已有准确链接、成果引用 | 包/版本固定；标题与发布日期替代内部 ID。旧包失效明确不可用，不替换最新。保留原始证据下载与已有导出格式 |

历史只读适配是保留用户数据的产品能力，**不是永久双执行链**。不删除数据、不重放旧工作、不更改旧成果类型。原有“记录人工纠正”保留为独立的新用户记录，原分析仍只读；具体缺口和写入归属见 §4.1 第 7 项。

本轮 B 不承诺把所有旧成果直接变成模型可用的云端 `ExactRef`。旧阅读器提供阅读/下载；确需继续时，用户在云端明确选当前获准对象和材料，或上传明确导出的旧内容作为新材料。自动复制旧 candidate/material ID、标准 consent、hash 以冒充云端引用均禁止。旧页面不提供点了却拒绝/无作用的“继续分析”按钮。

新链内的“带入讨论”有真实行为：把具体对象、准确可读参考和可编辑问题放进原草稿，并展示将加入的内容；用户发送前不产生工作请求。不覆盖已有草稿，不提交隐藏指令；不做只填一句罐头话的任务按钮。确认标准是另一种显式动作：预览准确条目后由用户发带 CSRF/幂等与基准版本的 HTTP 请求，不能混进讨论草稿或模型工具。

### 4.1 必须补足的适配，而非宣称已有

1. 岗位列表/草案读取保留现有 API；原“建草案后创建旧会话”的生产路径退出，建立云端工作时保留草案身份与幂等恢复。无岗位咨询不经过这条路径。
2. 岗位资料聚合云端成果/标准及旧只读记录，各自显示加载失败，不能把失败合并为零。旧当前标准与云端基准分开，历史基准不可直接授权确认。
3. 补云端标准历史/准确版本、旧成果候选人关联查询与报告旧标识映射的只读契约。实施时优先复用已有后端读模型；新增端点必须同步路由授权并做真实 HTTP 回归。本轮不修改这些接口。
4. 候选人旧分析/比较/反馈、简历版本、面试 PDF 和材料提升能力逐项迁入云端视图或历史阅读适配，不能因组件删除消失。新候选人建档复用自然语言审阅表单；旧结构化事实用安全的业务标签呈现，不将内部字段原样输出。
5. 准确报告正文使用现存报告类型/API；任务 A 删除的零引用展示组件不恢复。新阅读器保留实际报告正文、来源、证据和导出，不新造总分/排名。
6. **云端面试 PDF 是待补能力**：当前 `hr_agent/results.py` 导出 Markdown，`routes.py` 的 file 响应固定为 `text/markdown`，不能声称已能交付 PDF。旧面试 PDF 保留原字节下载；新链需从已保存的准确成果修订生成 PDF，补受认证的格式导出/下载契约，不重新调用模型、不改变成果身份。验收核对 PDF MIME、实际可解析文件与中文正文、原候选人/岗位/修订归属及拒绝越权；不能将 `.md` 改扩展名当作 PDF。本轮仅列入 B 范围，未实现。
7. **人工纠正记录是待补契约**：云端候选人 API 目前没有反馈接口，不能把旧“提交纠正并绑定分析”的测试降成只读。推荐在新链新增用户 HTTP 追加/查询纠正记录，持久保存作者、正文、时间和准确原分析引用；引用显式分 `cloud_result`（结果修订）与 `legacy_analysis`（原岗位候选人关系、analysisVersionId），服务端逐项核对原对象/版本授权。旧引用仅作记录来源，不变成云端 `ExactRef`、不修改旧分析、不调用旧执行；同一纠正记录从候选人及原成果阅读器可见，重复请求使用同一幂等键。当前未建立云端身份的历史候选人只按其历史命名空间记录，不因同名自动关联。切换前补真实 HTTP 保存/查询/跨用户拒绝和原版本绑定测试；版本冲突要求重新核对，不把纠正偷偷绑定到另一版。讨论中复用纠正内容须用户另行明确选择，不能隐式提交模型指令。

## 7. 工作状态与失败处理

同一用户/工作有一份草稿状态，导航只切视图，不重新创建工作。选岗位影响明确的下一轮，已有工作范围不被页面选择暗改；切无关新工作清除继承对象。切页时在持久层的任务继续，回来按 workId 和游标读回消息，不依赖旧聊天 DOM 常驻。

未发送文本、准确参考、上传进度在统一壳会话状态保留；需要刷新恢复的草稿采用按用户/工作隔离的会话快照，退出账号/撤权立即清理，不把个人材料全文写入全局 localStorage。已上传且已登记的附件可重新读取状态；浏览器刷新无法还原尚未上传的 File 字节，明确请重新选择，不能假装已恢复。网络结果不明保留原幂等键。权限错误清掉旧内容；普通网络失败可保留明确标注的上次读取内容和重试，不能显示“0 条”。
