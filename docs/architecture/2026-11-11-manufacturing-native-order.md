# 制造工作流中的原生MES工单读取

这是本地开发交付的宿主组合说明，不是生产发布记录。业务需求、任务书与验收由[制造仓库](../../../AI-Manufacturing-Platform/docs/superpowers/plans/2026-11-11-oem-workflow-taskbooks.md)维护。

宿主在加载可信制造包后，先组合原生SAP/MES只读服务与各自路由；工单工作流通过显式可选`mes_access_service`关键字取得同一个MES服务实例。工单关联和刷新复用固定受审计接口，不经过HTTP回环或mock系统投影。构造阶段不读私有配置或连接源系统；请求到来后先核对项目与岗位权限，再读取私有配置和源数据。

原有`PLATFORM_MANUFACTURING_MES_CONFIG_PATH`、`PLATFORM_MANUFACTURING_MES_AUDIT_PATH`配对配置继续生效。配置、审计和锁文件不能与另一来源、工作流/权责/旧业务库及其sidecar、生产工具配置/快照/调查库重合。无效或缺失MES只使MES能力不可用，不阻止SAP或项目工作流。私有配置由服务端注入，浏览器不能指定URL、来源配置、接口或任意过滤条件。

新增精确读取路径：

```text
GET /api/v1/manufacturing/workflow/projects/{project_id}/work-orders/{work_order_id}/mes-materials
```

项目成员读取的是经授权关联后保存的类型化组件结果，不触发源查询。关联与刷新沿用项目命令路由、CSRF/Origin、只读、活跃人员、幂等、版本冲突及审计；当前还需要配置管理员与实际项目负责人/工程成员权限。组件查询不能成为普通成员的跨工单源查询入口。

旧制造包没有新注入参数时，宿主按原签名挂载。缺少新读取路由时保留受认证的503/no-store回退；原生服务路由验证失败的实例不会注入工作流。管理端原生鉴权证据仍按当前配置凭据隔离，工作流采集的稳定来源身份不会提升该管理端的鉴权结论。

接口和宿主回归已通过；实际测试MES经当前宿主工作流完成12行组件关联/刷新、重放、失败保留和重启恢复。平台身份与项目为隔离合成夹具，源MES账号和行数据为真实测试环境；不代表SAP对象等价、齐套、IQC、线边实收或生产发布。浏览器验收交用户。
