# 全景首页：实现与启用记录

## 行为与访问边界

平台管理账号登录平台后，根路径 `/` 默认打开全景。`/brain` 始终打开 Agent 大脑，`/agents` 保留专业 Agent 入口；原有任务、会话和编排不变。主站首页不再按人员名单在全景与员工大脑之间切换。员工使用 `/office/`、`/hr/`、`/voc/`、`/fae/` 等独立子应用；这些路径继续使用各自的入口和权限，不增加全站管理员拦截。

授权复用平台现有管理角色：`platform_admin` 与 `platform_owner`。会话中间件每次请求取得可信角色，正文与图片分别检查；不从姓名、部门或客户端标头取得权限。不修改 Account 契约，现有 access 端点仅返回管理权限判断结果，前端不维护第二套名单。管理角色撤销后，下一次内容请求被拒绝；已经阅读或保存的副本无法撤回。

正文、财务与产品依据、资产盘点、SVG 和 PNG 均在后端私有内容包，Vite 的公开资源仅含界面代码。全部内容接口及错误响应禁止缓存。内容源固定为 Orbbec-AI-Engineering 提交 `69a9de2168de6fa42b14d586587169487797e6f3`，`backend/app/ai_engineering/content/source-manifest.json` 保存每份文件的原始路径和 SHA-256；服务端读取内容时验证摘要。

## 本轮确认与配置

用户于本轮明确：主站暂供管理员使用，员工通过 `/office/`、`/hr/` 等子路径进入服务。因此取消此前显式 UUID 白名单与 `PLATFORM_AI_ENGINEERING_ALLOWLIST_FILE` 配置，无须另收首批名单。这里的管理权限与现有管理路由一致，包括平台管理员与平台所有者；管理观察员和普通成员不获得全景内容。

移除白名单文件读取、校验及部署挂载需求。行政、HR、VOC、FAE 的共享认证与业务权限保持原样，不修改 Nginx 路径或生产账号角色。
