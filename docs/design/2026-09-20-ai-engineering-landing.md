# 全景首页：实现与启用记录

## 行为与访问边界

指定内部账号登录平台后，根路径 `/` 默认打开全景。`/brain` 始终打开 Agent 大脑，`/agents` 保留专业 Agent 入口；原有任务、会话和编排不变。普通员工仍以大脑为首页。

授权以现有会话建立的 `AuthContext.internal_user_id` 为唯一依据，平台 owner、管理员、部门和姓名均不自动授权。不修改 Account 契约，通过独立 `/api/v1/ai-engineering/access` 探测权限。授权文件每次请求重新读取；撤权对下一次正文、图片请求生效，已经阅读或保存的副本无法撤回。

正文、财务与产品依据、资产盘点、SVG 和 PNG 均在后端私有内容包，Vite 的公开资源仅含界面代码。全部内容接口及错误响应禁止缓存。内容源固定为 Orbbec-AI-Engineering 提交 `69a9de2168de6fa42b14d586587169487797e6f3`，`backend/app/ai_engineering/content/source-manifest.json` 保存每份文件的原始路径和 SHA-256；服务端读取内容时验证摘要。

## 授权配置

API 进程环境变量 `PLATFORM_AI_ENGINEERING_ALLOWLIST_FILE` 指向绝对文件路径。文件须为服务运行用户拥有的普通私有文件（部署使用 0600），不能是软链接。容器运行用户当前为 UID 10001；不要把 owner 身份写成隐式豁免。

文件格式：

```json
{"schema_version": 1, "internal_user_ids": []}
```

待首批人员确认且与可信内部账号准确对应后，填入规范小写 UUID。最多 200 个，不接受重复 ID、姓名或角色。未设置变量时默认无人获准；路径不可读或内容异常时 access 返回 false，内容接口返回 503，原有平台继续服务。不在源码、镜像层、前端配置或日志中写入真实白名单。

需要实时撤权时，将文件放在已有私有目录的只读目录挂载内，以同目录新文件设好属主和权限后原子替换。**不要用单文件 bind mount 实现原子轮换**：它可能固定旧 inode，使容器继续读取旧名单。启用与每次轮换后，都要从容器内验证实际可见文件，并用授权／未授权会话验收。
