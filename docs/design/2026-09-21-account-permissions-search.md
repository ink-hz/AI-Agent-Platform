# 账号与权限：管理员名单与搜索授权

用户已批准实施；随后明确页面和导航仍叫「账号与权限」，不改名。

默认页面只显示平台所有者及管理员，展示花名/目录显示名、部门和可用操作。所有者不可移除，普通平台管理员只读该名单。所有者通过「添加管理员」打开搜索区，输入目录中的花名/姓名后返回有限匹配结果，选定具体人员后授权。授权绑定 internal_user_id，不能直接把输入文本当授权身份；同名通过部门区分，仍不能辨认时提示而不猜选。目录显示名之外的加密实名不新增解密或索引。

默认请求仅返回管理员。候选搜索按需请求，空查询不返回全量成员；仅 active member 可新增，保留现有角色转换规则。后端提供部门名称投影；不返回手机号、邮箱或身份提供方标识。管理员撤销仍允许非活跃管理员；硬过期只读时禁止变更。已有审计、CSRF、操作幂等、结果不确定时的恢复均保留。

账号与权限顶部统一提供「平台管理员｜FAE 权限｜VOC 权限｜其他授权」导航，其他授权含观察者和合作方。各分区合并为一个页面，顶部按钮仅切换本地状态，不刷新文档、不改路由。首次选择时加载分区，已经访问的分区隐藏并保留输入和执行状态；换账号或角色时清空。旧独立链接作为初始分区入口继续可用。左侧均选中「账号与权限」。FAE/VOC/合作方入口仅所有者可见，观察者入口对平台管理员可见。FAE 工作台另提供权限入口；VOC 的独立应用不在本次修改范围，权限页由平台承载。各授权页复用原组件及原授权边界。

默认页采用紧凑名单、管理员分区的添加按钮、按需搜索区；正常目录状态、范围占位、英文抬头和全局原因输入不出现在首页。其他授权页的现有业务规则保持不变。页面视觉由用户验收，开发侧运行 API、组件及构建检查。不执行生产授权变更，部署需用户指令，本次已获后续授权并完成。

## 2026-11-18 在册成员搜索

「平台管理员 → 添加管理员」按当前已发布的企业通讯录搜索活跃成员。已关联账号的人须同时满足账号活跃且角色为普通成员。尚未关联账号的人也显示花名和部门，并标记「尚未关联平台账号」。匹配使用通讯录显示名的字面子串，同名同部门的结果会提示核实。

页面通过原管理接口的新版视图 `candidates_roster` 查询。只允许平台所有者访问，每次读取记录审计。查询跨页时使用同一数据库快照，先按资格过滤，再判断结果是否超过展示上限。通讯录成员 ID 用于区分结果，实际授权继续使用已关联的内部账号 ID。搜索本身只读。旧客户端的 `candidates` 视图继续提供原账号投影。

## 2026-11-18 直接设置在册员工为管理员

前一版把搜索接入企业通讯录，写入和页面的操作恢复仍依赖已存在的平台账号。员工能被搜到，所有者却不能完成授权。搜索、授权、首次登录及撤销应共同使用经过钉钉身份绑定的内部账号。

所有者点击「设为平台管理员」后，未关联员工走专用的通讯录授权接口。页面提交搜索时的通讯录版本、选中的成员 ID 和请求 ID。目录换代后需要重新搜索，防止企业 userid 被另一名员工使用时误授。服务端从当前有效目录重读在职员工，以企业身份及 Union 身份两项映射核实人员。建号、绑定与原管理员角色授予共用一个数据库事务。首次登录继续走正常的钉钉验证并认回同一账号。登录先一步完成时，身份或版本冲突须重新搜索确认。

搜索结果提供可用于授权结果核对的内部账号 ID。对于未关联的员工，这个 ID 来自带独立前缀的目录版本和成员标识摘要；它本身不产生账号或角色。旧客户端和已关联员工保留原读写契约。同名同部门、结果过宽、权限不足和目录过期继续受原约束。所有者操作仍校验 CSRF、写入审计，重试使用原请求 ID，撤销后重放旧请求不会重新授予。管理员权限由平台所有者在生产页面选择具体员工后设置。

验收覆盖未登录员工被直接设置、第一次身份验证、撤销与重放、失败回滚，以及管理页搜索到授权再刷新列表的完整操作。

同一请求 ID 的第一条管理员审计意图固定操作、所有者和授权对象。若服务在记录意图后中断，重试会继续原操作。改换目标会返回冲突。已提交的操作可在目录换代或撤销后回读原回执。
