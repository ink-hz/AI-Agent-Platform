## 最短上线验收：一条业务链，不重复跑套件

1. 刷新、新建对话，发送「介绍一下你自己」。确认有处理中状态、完整 assistant 答案、正确结束；记录首个进度和完整回复耗时。
2. 同一对话提出岗位需求，生成 JD / JR，明确确认后入岗位库。进入岗位，核对 JD / JR 已保存且后续对话能引用。
3. 上传标明「测试」的模拟简历，要求结合该岗位分析并生成面试题 PDF。核对岗位和所选简历确实进入本轮上下文；下载并打开 PDF，内容应与任务一致。
4. 岗位与对话切换、刷新一次：同一会话和消息保留，结果能找回，无重复提交或重复执行。

## 出错时只做这些

- 记录失败操作、时间及 conversation_id / turn_id / run_id；直接查对应接口、状态和日志，不反复点页面猜原因。
- 最小复现 → 定位根因 → 最小修复 → 相关接口回归 → 必要发布。不要重跑无关全量套件。
- 接口优先；浏览器只补输入、流式呈现、切换和下载交互。不得伪造成功状态或绕过身份、签名、幂等。
- 执行状态不明时保留原任务并核对，不重新提交模型请求来修复交付；不强制切回旧执行器。
