# 工程知识库写作与发布标准

本标准是工程知识库从选题、清洗、重写到上线的唯一作者入口。目标不是追求文章数量，而是让每篇正式文章都准确、独立、可读，并能长期代表作者苍渊的技术判断。

## 1. 主题准入

- 精选收录五个领域：AI 与 Agent、SDK 系统架构、制造业务与流程、企业系统与集成、智能制造架构。每篇恰有一个主分类，手册、架构、方案、案例、方法等文档类型用标签表达。
- 每篇有清晰的读者与用途，精度优先于数量。手册、完整方案与总体架构可以保留连续长文及原章目录；跨文章去重以职责和阅读边界判断，不机械删掉必要上下文，也不以摘要替代全文。
- 不设固定字数、章节数、图数或引用数量。信息密度和可理解性优先。

## 2. 源稿清洗与研究

1. 对迁移源稿做全文精读，先理解论点、结构、事实和案例，再决定保留、重写或删除；禁止仅靠关键词或正则批量替换完成迁移。
2. 旧源仓库只读。正式文章不得依赖旧仓库运行，清除旧品牌与无法复核的个人经历。已审阅制造材料的公司语境、历史研究日期、目标设计与实施快照应保留，并明确其来源、证据强度和状态，不能冒充收录日现状。
3. 对会变化、可能有争议或影响工程决策的事实，优先查一手资料：官方文档、规范、标准、论文或项目仓库。二手文章只能作为线索，不作为唯一证据。
4. 区分公开事实、工程经验与作者判断。不能由来源支持的数字、效果和归因必须删除或明确限定。
5. 发布和更新时间必须符合仓库规则；作者在当前公司的时间边界不得早于 2026-05-25。

## 3. 作者身份与正文结构

正式文章 frontmatter 必须包含：

```yaml
author: 苍渊
motto: 博观而约取，厚积而薄发。
```

- 正文从二级标题开始，不写 Markdown 一级标题；页面标题由文章 frontmatter 统一渲染。
- 不写原生 HTML，不保留模板提示、旧组织标记、危险链接协议或无法访问的本机路径。
- 开头直接说明问题、边界和读者能获得什么；结尾给出可执行的判断或检查清单，不堆口号。
- 代码、表格和图示前后都要有解释：读者先知道为什么看，再知道看完得到什么。

## 4. Mermaid 与文本图规范

- 可以没有图，但不能为了图数凑图。需要表达三项以上关系、层级、状态变化或分支决策时，优先考虑 Mermaid 或简洁文本图。
- 一张图只表达一个中心关系。内嵌状态必须无需放大也能读懂；节点过多时拆图，不把整篇文章压成一张总览。
- 每个 Mermaid 块必须有且只有一个非空 `accTitle:` 和 `accDescr:`，二者在全部正式文章中都必须唯一。
- 每张图必须包含 `classDef` 或显式 `style`，用颜色表达稳定语义，而不是装饰。
- 大分组和图画布统一使用白色 `fill:#FFFFFF`，与博客白底连续；不得用 `#F8FAFC` 作为 subgraph 背景。
- `#F3F4F6` 只用于中性基础设施节点，不用于整张图或大分组。建议固定语义色：输入蓝、模型紫、数据青、策略黄、成功绿、风险红、基础设施灰。
- 图前说明它回答的问题，图后解释关键路径、边界或例外；不要只放图不解读。

## 5. 草稿与正式发布

- 新文章必须从 `draft: true` 开始。草稿可以未完成，但目录、文件名、frontmatter 和日期必须可解析。
- 只有全文精读、事实核验、去重、图示检查和独立审查完成后，才切换为 `draft: false`。
- `draft: false` 会触发后端统一发布策略：作者身份、正文清洁度、Mermaid 元数据与白底规范全部是硬门槛。
- 前端测试会自动发现所有 `draft: false` 文章，真实渲染并净化其中的 Mermaid，不维护人工文件清单。

发布前至少运行：

```bash
cd backend
.venv/bin/python -m app.ai_notes.validate
.venv/bin/pytest -q
cd ../webui
npm test -- --run
npm run build
```

## 6. 人工质量门禁

机器通过后仍必须完成：

1. 独立内容与代码审查，Critical 和 Important 问题必须清零；不能用自动测试代替事实边界和表达质量审查。
2. 桌面 `1440×900` 与手机 `390×844` 的真实浏览器验收由用户按 AGENTS.md 负责，检查正文宽度、字号、代码、表格和目录树；开发侧明确记录未执行，组件测试和真实 Mermaid 渲染不替代此项。
3. 逐张检查 Mermaid 的白底、颜色、文字、箭头、重叠与内嵌尺寸；再检查点击打开、滚轮缩放、拖拽、点击或 Esc 关闭，以及关闭后的正文滚动位置。
4. 部署后复核文章目录位置、API 内容数量、页面渲染和关键交互。生产抽查不通过时，停止继续迁移并先修复。

## 7. 完成定义

一篇文章只有同时满足以下条件才算完成：主题属于上述五领域之一、源稿已精读、事实有边界、文档职责清晰、必要上下文完整、作者身份正确、图示有必要且可读、自动门禁全绿、Critical/Important 为零、桌面与手机视觉验收通过、生产环境抽查通过。

## 工程知识来源与迁移

正式根目录为 `backend/app/ai_notes/library/`，旧 `content/` 即使存在于镜像继承层也不得扫描。15 篇新增稿及14篇原稿构成本轮29篇；来源清单见 `docs/knowledge-library/2026-11-11-source-manifest.json`。原14篇保留正文、slug、历史日期与标签，用显式 `legacyPaths` 兼容旧路由。新增稿收录日为2026-11-11，资料核验日、公司材料日期和2026-11-09实施快照分别注明。

已收录文章互链使用规范 `/ai-notes/{分类}/{文章}` 路径；未收录配套文件只链接经核实存在的真实仓库固定提交。无法确认远程的SDK研究来源保留相对文件身份、原行号和固定八仓基线于文内来源附录，不制造公开URL，不导入场景卡。来源、目标设计、静态研究、代码快照、运行和业务验收须分别陈述。
