# Fixed synthetic conditional PUT probe — prepared, not executed

This implementation makes no SSH, production, model or real S3 call during development. Root must independently review these exact bytes and supervise any actual invocation. This is the requested production S3 capability probe, separate from owner authentication or attachment erasure acceptance.

The script uses existing readonly /run/secrets/attachment-s3-access-key and attachment-s3-secret-key (regular0600, owner0/10001), fixed http://platform-minio:9000, bucket orbbec-agent-attachments, real boto3 SigV4/path addressing, no environmental proxies, and total_max_attempts=1. It accepts only an explicit --execute and protected absolute --binding and --evidence paths. The evidence directory must already exist,0700 owned by executing UID, and cannot contain private-ledger.json. Binding must be0600 owned by executing UID. No credentials are copied or printed.

Binding contract: JSON exact top-level run_id (32hex UUID), minio ({id:64hex,image:sha256 digest,pid:positive integer,started_at:actual timestamp}), client ({id:64hex,image:sha256 digest}), script_sha256. Root creates a uniquely owned client container stopped, inspects its exact ID/image, constructs the binding, then starts that exact ID with default Docker hostname matching ID prefix. Script verifies hostname and own source SHA. **MinIO/client image and MinIO PID/start are external Docker attestations, not independently proved by reading the binding inside the container.** Root must record exact container inspect before/after and reject mismatched generation. This permits a separate run after the maintenance restart; never reuse a prior probe to claim the new generation was tested. No placeholder production binding is provided.

Run inside that inspected client container using its installed boto3:

    python /probe/probe.py --binding /evidence/binding.json --evidence /evidence --execute

Mount /probe readonly, /run/secrets existing S3-secret volume readonly, and only the private evidence directory writable. Attach the client to the actual platform internal network; no Docker socket is needed inside. Root supervises overall container lifespan and reaps only its exact owned ID. The script arms a90s POSIX timer around Probe execution, with3s connect/5s read timeouts and no SDK retries; cancellation restores previous signal handlers, and preexisting timers are rejected. No claim is made that container setup or external supervision is part of that90s bound. The local suite has not independently exercised the CLI alarm/real network; root's execution receipt must record actual elapsed time and owned-container cleanup.

One fresh random synthetic key under platform-synthetic-conditional-probe/<run>/<uuid> is first completely enumerated (exact-key filtering, max8 pages/8 exact versions); any existing payload or delete marker rejects before writes. First conditional PUT creates public synthetic bytes. A second differing conditional PUT must produce actual HTTP412. Both exact-version and current HEAD/GET must retain the first immutable VersionId, bytes, length and metadata, and complete listing must contain only that version. It is deleted using only its acknowledged non-null VersionId; empty listing is verified. On the same now-empty key a zero-byte exact platform-erasure-fence=v1 object is conditionally written, challenged with another required412, verified by exact and current HEAD/GET, then its acknowledged immutable version is specifically deleted. No bare DeleteObject is ever issued. Only full successful execution yields cleanup_verified=true.

Every mutation has a fsynced private prewrite intent and logical request UUID. Actual response version IDs and provider request IDs are retained when returned; the logical UUID is a ledger marker, not S3 server idempotency. The private ledger contains exact synthetic key/version references; public stdout contains only hashes/status. Any unknown reply,403,invalid/null identity,timeout,version drift or assertion failure halts immediately without retries or automatic cleanup. Existing acknowledged versions and any unknown server-side mutation remain in the private ledger for root's exact inspection. There is intentionally no resume/retry command, no adoption of existing ledger, and no guessing unacknowledged versions by list to delete them.

Evidence: red/ is the expected missing-new-module collection failure (exit2), not an old-runtime semantic RED. green-1 contains exact source/test snapshots, command/exit records:10 local tests pass, Ruff succeeds. SDK responses are simulated; real temporary file ledger persistence is used. Causal tests include a provider deliberately ignoring IfNoneMatch (probe fails and retains both payload versions), unknown first PUT (one write only),403,null VersionId,preexisting key across pages,original-byte mismatch,and normal exact-version cleanup for both412 checks. These tests do not prove production S3 supports conditional writes. Root alone will perform the actual preflight and post-restart-generation runs.
