# 四个招聘集合的正文分析与复核说明

日期：2026-09-09。承接首批三家公司分析及评审修订，继续阅读智元、拓竹、影石、禾赛。成果按公司呈现，每家公司回答 Q9、Q3、Q4、Q5、Q10、Q11，另有 Q8、Q12 两篇跨公司比较。原先十二题保留，不将不同公司的材料强行填进统一篇幅或结论模板。此处沿用的数据源“智元”实际汇集集团子公司、业务部及归属未明岗位，不是本部样本；详见 [实体归属与评审修订](text-led-review-revisions.md)。

## 先读哪些判断

**[智元 Q9](agibot/q9-technical-intent.md)：数据采得合格，不等于值得继续投。**原文一方面要求控制采集质量，另一方面觅蜂预训练岗要求评估数据混合价值，另一未明示归属的实习岗要求判断 Ego 数据是否值得继续投入。觅蜂是明确搜寻入口，但不能据此将所有数据岗位归给觅蜂或本部。招聘不能只核查吞吐、清洗或标注经验，还需要看候选人如何识别无效数据投入。交互也有不同失败边界：取消流式输出、恢复任务状态、确认当前交互对象不是同一件事。不能把分别写明这些任务的岗位拼成已经跑通的统一系统。

**[拓竹 Q9](bambu-lab/q9-technical-intent.md)：创作结果最终要经得起实物约束。**材料和机械波动会影响默认切片结果，生成模型的外观效果不能代替可打印性；UV 的墨滴、材料和固化又有自己的失效机制。可迁移的人才经历应落到失败解释与验证方法，不能只比较工具词或作品效果。

**[影石 Q9](insta360/q9-technical-intent.md)：画面算法还要对端侧资源与创作结果负责。**成像、功耗、热约束与用户使用相互限制；重建岗位又明确把资产交给仿真和感知训练。正文支持区分优化和验收任务，不支持把这些岗位认定为同一条已运行流水线。[Q11](insta360/q11-internal-mismatches.md) 还发现“中级热设计”正文实际围绕射频和 EMC，按标题做岗位映射会误导搜寻。

**[禾赛 Q9](hesai/q9-technical-intent.md)：不能只用车载激光雷达概括招聘。**Kosmo 的客户设备资源适配、降级、重建质量和问题诊断构成具体交付要求；芯片、光学与制造反馈又是另一组任务。技术支持候选人应能把采集、设备、数据、算法及使用问题分开，而非仅会转交故障。

跨公司优先读 [Q8 创作者商业责任](comparisons/q8-creator-commerce.md) 和 [Q12 重建交付责任](comparisons/q12-reconstruction-handoffs.md)。前者区分众筹产品与履约、创作者内容与发布的具体责任，同时保留两边对商业结果的要求；后者明确比较岗位任务，拒绝把“客户部署”与“模型训练”包装为两家公司的互斥路线。

## 如何核查与评审

分析使用情报包 `2ed2262c-63a0-47e5-996c-7d00eb0be1a0` 的飞书原始归档。统一岗位文件只用于身份对照；未使用旧分析或 aggregates 生成判断。影石另读本包归档官网；智元、拓竹、禾赛官网采集失败，因此客户及产品相关结论明确保留为招聘自述。本轮没有用新抓取的网页填补旧包缺口。

[证据索引](text-led-evidence-index.md) 列出引用岗位、原始 ID、归档 SHA 路径与 JSON 指针。独立来源核查从原始归档重新定位岗位，验证归档摘要、身份和引文；各公司及智元分段另有阅读记录与原文核验。脚本用于来源一致性，不判定“智能程度”、能力强弱或分析合格分数。

实体归属及同族对照修订后核查结果：26 篇答复引用 224 个岗位，475 处岗位引文均能在对应原始正文中定位，身份与引用核查无失败。影石另有 4 处归档官网引文，经公司核查脚本验证；它们不计入 475 处岗位引文。各公司与智元四个分段的核查脚本均重新运行通过；整个分析目录的 294 个本地链接均可解析。这些结果证明来源与材料连接有效，不证明判断已经获得业务认可。

智元 Q9、Q5、Q10 与跨公司 Q12 另经独立阅读者审读并回查承重原文。评审未发现阻断性越界；Q12 标题及 Q5 的可售交付物表述按反馈收紧。

本轮复核中特别收住了三处推断：

- 影石有明确的数据任务，只能反驳“公开招聘没有安排数据工作”，不能据此宣布真实团队不缺人才。
- 智元明确写补齐售后测试自动化、组建 PQA 等目标，可以回答企业自述要补什么；不能证明现有团队完全没有该能力、已经缺员多少或目标已完成。
- 禾赛与影石的比较主要揭示岗位交付责任差异，不能提升为公司路线差异。独立评审后也改掉了容易制造二选一印象的标题。

供 Claude 或业务负责人继续评审的重点：判断是否确实依赖正文中的任务关系；反例是否足以收住泛化；招聘建议是否改变了所需经历和核验对象；是否把目标、广告自述或相邻岗位关系写成已实现事实。多条证据可以相互替代，不能机械要求“删掉任何一个引用结论就必须崩塌”；应判断承重证据整体失去支持后，结论是否仍在无依据地保留。

阅读笔记、完整岗位映射与核查脚本保存在本地 `.superpowers/sdd/hr-question-analysis/`（Git 忽略目录），正文与证据索引在本目录。只分享 Markdown 时，各题原文和归档定位仍可审查，但收件人不会自动取得本机笔记或归档文件；需复跑核查时应一并提供对应材料。

## 使用范围

这是离线语义分析成果。公司入口与逐题文件已经整理，尚未接入 Hannah、情报 API 或线上页面；未改采集、归一化、分析生产管道、权限及部署。本轮不以产出篇数证明业务价值，也不把这些判断写成固定路由或筛选规则。
