## 1. 数字主线连接的是语义与证据

“数字主线”可理解为产品定义、计划、制造、检验和服务之间可关联的数据链。它不仅要求拿到数据，还要知道数据对应哪个对象、哪个版本、哪个时点及何种业务语境。NIST 的研究指出，异构生命周期系统的数据聚合和上下文关联本身就是难题；其参考架构是研究方案，不是要求企业采用同样层数的部署规范。[S09：NIST 数字主线研究摘要](https://www.nist.gov/publications/reference-architecture-integrate-heterogeneous-manufacturing-systems-digital-thread)

最小关联集合可从订单号/行号、物料号、工艺与 BOM 版本、工序号、批次/序列号、设备标识、检验记录号开始。还要记录组织、地点、单位、生效区间、来源与责任人。工程变更必须解释“日期生效、批次生效、序列号生效、订单生效”中的实际规则，不能只留一个版本字符串。相同编号跨工厂是否同物同义，也应纳入核查。

GS1 官方支持资料把追溯拆为关键追踪事件 CTE 与描述这些事件的数据 KDE。可据此设计自己的收货、投料、转换、拆并批、包装和发运记录；并非买条码设备后就自动符合某项追溯标准。[S10：GS1 CTE/KDE 概念](https://support.gs1.org/support/solutions/articles/43000734535-what-is-the-gs1-traceability-standard-)

## 2. 集成方式要服从业务时效和一致性

| 方式 | 常见适用情形 | 设计时必须回答 |
| --- | --- | --- |
| 同步 API | 查询、校验、受控业务命令 | 超时后是否已执行；调用者能否查询最终状态 |
| 异步事件/消息 | 报工、收货、质量状态变化，多个订阅方 | 事件表示已发生事实还是待办命令；如何去重与排序 |
| 批量文件/ETL | 历史迁移、低频交换、汇总分析 | 截点、批次号、校验和、拒收明细与重跑范围 |
| CDC，变更数据捕获 | 形成分析副本或某些近实时分发 | 表变化是否能解释业务含义；删除与结构变更如何处理 |

CDC 观察到数据库行变化，不能自然等价于“业务已经批准完成”。批量并非落后，同步也不意味着可靠；关键是时效要求、失败成本、业务原子性以及运维能力。应为每个接口写明业务动作、对象、模式版本、授权、最大延迟、响应含义、限额、重试边界和对账人。

## 3. 把异常当作正式设计内容

**幂等与重复：**同一笔完工确认被传两次，库存不能增加两次。采用稳定的业务操作标识，记录处理结果，并保证去重记录与业务写入一致；同一标识内容冲突应显式报错。Microsoft 的幂等消费者文档指出，至少一次投递可能重复，消息系统的能力不自动覆盖外部业务副作用。[S11：Microsoft 幂等消费者模式](https://learn.microsoft.com/en-us/azure/architecture/patterns/idempotent-consumer)

**顺序与版本：**冻结、放行、撤销若乱序抵达，单纯去重仍可能把库存恢复成错误状态。以对象版本或业务序号识别旧更新，定义缺号处理、等待窗口和人工纠错；不能以网络接收顺序冒充业务发生顺序。

**对账与更正：**按对象、数量、金额或状态建立双方可解释的对账。原单、冲销单、重发批次和最终结果应关联。传输成功率高不等于账一致；“异常队列为空”也可能是错误被丢弃。应同时监控积压时长、拒收原因、重复率、未匹配对象与业务差额。

**时间、单位与精度：**区分事件发生时间、设备采集时间、平台接收时间、财务过账日期；保留时区与时间质量。件、箱、千克、米的换算要有适用物料、精度和舍入规则；不要默认所有箱数都乘同一包装量。更换传感器、量程或采样频率同样可能改变数据含义。

## 4. 设备连接与离线不能只靠“自动重试”

OPC UA 同时涉及信息建模和通信，并提供认证、加密、审计等能力；选择协议并不意味着数据已经同义，或安全配置已经正确。[S08：OPC Foundation 架构介绍](https://opcfoundation.org/about/opc-technologies/opc-ua/)

旧设备需要先确认可读信号、协议、采集负载与厂家支持。边缘层可承担协议转换、时间标记、质量标记和有限缓存，但应明确缓存上限、磁盘满策略、重连后的补传与重复识别。离线期间哪些任务可以继续、需要哪些受控资料、如何防止使用失效工艺，都必须由工艺、生产、质量和 IT/OT 共同裁定。恢复后补传保留原发生时间，不能全部改成恢复时间。关键执行依赖断开时，采取何种受控业务措施，应在现场风险分析和操作规程中预先确定。

## 5. 集成也是权限和安全边界

服务账号只获得所需对象、组织和动作权限；查询、报工、放行、工程变更分别授权。通过获准的接口交换数据，记录身份与业务原因；密钥和证书有生命周期，不能把共享超级账号当集成能力。NIST OT 安全指南强调性能、可靠性与安全的特殊要求，讨论网络分区、允许的跨区通信与最小权限。其分区原则需要结合实际数据流落实，并非照搬一张金字塔图。[S12：NIST SP 800-82r3，见 6.2.1 与网络分区章节](https://nvlpubs.nist.gov/nistpubs/SpecialPublications/NIST.SP.800-82r3.pdf)

业务验收应包含断连、延迟、重复、乱序、权限不足、过期版本、单位错误和跨期间更正。每个情形都要保留“系统检测到了什么、谁作决定、最后业务账和实物状态是什么”的证据。可恢复性和可解释性应与正常吞吐一起验收。
