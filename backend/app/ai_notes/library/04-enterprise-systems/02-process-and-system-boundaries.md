> 以下为离散制造的教学参考流程；流程制造、按项目制造、外协和连续生产需要调整对象与状态。不是对本企业现状的判断。资料核验日：2026-10-27。

## 1. 先贯通业务，再画接口

一条典型链路是：客户需求或预测 → 产品与工艺准备 → 需求与供应计划 → 采购/外协 → 收货检验 → 生产订单下达 → 备料配送 → 工序执行 → 完工与质量放行 → 入库发运 → 成本和财务结算。这里的箭头表示业务依赖，不代表必须串行，更不表示各环节必由独立软件承担。企业可能按库存、订单、配置或工程项目组织制造；Microsoft 的公开生产流程文档也展示多种订单和制造方式并存的产品实例。[S05：Microsoft 生产流程概览](https://learn.microsoft.com/en-us/dynamics365/supply-chain/production-control/production-process-overview)

应同时画出正常路径和异常路径：需求减少如何取消；工程变更如何处理已投产订单；供应商少交如何补料；设备停机如何重排；超耗、替代、报废、返工如何批准；完工后发现缺陷如何冻结和追回。只有正常订单可以跑通的接口图，无法说明工厂能否持续运行。

## 2. 业务负责人与数据权威不是一回事

“权威系统”指某个业务对象或属性的正式来源，不等于谁拥有整台服务器，也不意味着其他系统不能保存副本。更可靠的做法是按实体、属性和状态划分权威。下表是需要会议确认的建议模板，不是通用强制分工。

| 对象/关键属性 | 业务决策人 | 建议明确的权威与交接 |
| --- | --- | --- |
| 客户订单、原始承诺交期 | 销售/订单管理 | 订单系统保留承诺及变更记录；排程结果不自动覆盖客户承诺 |
| 物料编号、单位、采购属性 | 主数据负责人联合工程/采购 | 编码与属性可分权，但每项属性有唯一审批入口 |
| 工程 BOM、图纸、技术版本 | 研发 | 工程受控来源发布；生产接收有回执 |
| 制造 BOM、工艺路线、工时 | 工艺/制造工程 | 明确由 PLM、ERP 或工艺系统管理；转换关系受控 |
| 计划建议、排程版本 | 计划 | 区分试算、批准、已下达，明确冻结窗口与重排权限 |
| 生产订单、允许生产的数量 | 计划/生产 | 确定创建与变更入口；MES 不另造无法关联的工单 |
| 工序事实、实际消耗、人员设备 | 现场生产及相关专业 | 在发生点记录，纠错有原记录和原因，不覆盖历史 |
| 检验结果、处置与放行 | 质量 | 结果来源、判定规则、处置批准与库存解冻分别确认 |
| 库位与容器移动、财务库存 | 仓储/财务 | WMS 执行事实与企业库存账有明确过账和对账关系 |
| 成本、会计期间与财务凭证 | 财务 | 财务结账权威不由 BI 或 MES 报表替代 |

PLM 中“产品定义正确”和 MES 中“实际用了哪个版本”是不同问题。不能只保留最新版图纸，就宣称历史追溯成立。生产订单下达时应记录适用版本与变更处置；必要时保存执行时的受控快照或可重建引用。

## 3. 库存必须同时看数量、位置、状态与时间

**在库/on-hand**首先要明确是实物已收、账务已记，还是某产品字段包含预计收货；**可用/available**还取决于预留、质量冻结、有效期、所有权和用途限制；**在制/WIP**表示生产过程中的物料、半成品或成本，不能直接加到可销售成品中；**冻结**是限制状态，货物可能仍在原库位。Microsoft 文档明确区分实物库存、实物预留、可用实物及预计供应，并指出某些“可预留”字段受参数影响。跨系统不能只按同名字段对接。[S07：Microsoft 在手库存字段说明](https://learn.microsoft.com/en-us/dynamics365/supply-chain/inventory/inventory-on-hand-list)

原创例：某物料 A 在同一时间、同一仓库与批次维度下实物 100 件，其中质量冻结 20 件；其余 80 件中已有 30 件预留，且没有其他限制，可用于新需求的实物为 50 件。另有在途 40 件、线边已领用在制 15 件，不能据此宣称“现在可发货 105 件”。这个例子假设冻结与预留集合不重叠；若重叠，不能简单重复扣减。企业还须定义线边物料是否已转入 WIP，避免两处各算一次。

验收时选择同一物料、组织、仓库、库位、批次/序列号、所有权、质量状态、单位和截点，先解释差异，再调整数据。用今天的 ERP 汇总对昨天的 WMS 明细，差异可能来自时间口径而非丢单。

## 4. 厂商中立的集成地图

| 业务方向 | 传递内容 | 接收方必须确认 |
| --- | --- | --- |
| 研发/工艺 → 计划与执行 | 物料、BOM、路线、版本、生效规则 | 引用完整、版本受控、变更适用范围明确 |
| 企业计划 → 现场执行 | 订单、数量、优先级、交期、允许用料 | 接收成功与可执行分开，缺版本或缺料返回异常 |
| 执行 → 企业库存与成本 | 消耗、完工、报废、工时、撤销/更正 | 一次业务只产生一次有效过账 |
| 仓储 ↔ 生产 | 备料需求、配送、签收、退料、余料 | 仓内移动与生产领用分清，容器批次可关联 |
| 质量 → 计划/仓储/执行 | 检验要求、冻结、处置、放行 | 限制及时生效，解冻审批与通知可审计 |
| 各系统 → 数据分析 | 主数据、业务事实、口径版本 | 分析副本不绕过业务授权改账 |

Oracle 的外部 WMS 文档描述接收/发运请求与完成确认的往返，Microsoft 的质量文档展示检验期间限制库存使用的配置实例。它们说明“命令—执行—确认”和跨域状态传递的必要性；具体接口结构仍需查本企业已选系统版本。[S20：Oracle WMS 集成](https://docs.oracle.com/en/cloud/saas/supply-chain-and-manufacturing/25c/famml/third-party-logistics-and-warehouse-management-systems.html)、[S21：质量管理实例](https://learn.microsoft.com/en-us/dynamics365/supply-chain/inventory/quality-management-processes)

边界验收至少追问：失败谁接单、多久被发现、重复如何消除、更正如何回传、关账后如何处理、业务人员如何知道最终结果。接口返回成功只证明某一步被接受；订单、库存、质量和成本一致，才构成业务闭环。
