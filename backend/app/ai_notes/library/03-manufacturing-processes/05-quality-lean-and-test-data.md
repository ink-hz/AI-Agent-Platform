制造信息化既要知道产品是否合格，也要解释过程是否稳定、为什么出现等待，以及能否用原始数据复核判断。本文补充质量和精益的基础知识，帮助读者识别系统应当保留什么。整理日期：2026-10-27。数值例子均为教学假设。

## 产品合格 过程稳定与过程能力

三个问题需要分开：产品是否符合规格；过程是否处于统计稳定状态；稳定过程的波动能否满足规格。规格限来自产品要求，控制限来自过程数据，两者含义不同。不要把没有越过控制限写成产品必然合格，也不要因一批全检合格就判断长期过程稳定。[R04 NIST 过程能力](https://www.itl.nist.gov/div898/handbook/pmc/section1/pmc16.htm)

对适用正态分布、过程稳定等前提的双侧规格，常见总体指标为：

```text
Cp  = (USL - LSL) / (6 × σ)
Cpk = min((USL - μ)/(3 × σ), (μ - LSL)/(3 × σ))
```

USL、LSL 为规格上下限，μ、σ 为过程均值与标准差；现场估计值还受采样与估计方法影响。该公式不应直接套用到混合分布、失稳过程或不合适的样本。[R04 NIST 定义](https://www.itl.nist.gov/div898/handbook/pmc/section1/pmc16.htm)

**教学例子**：假设一稳定过程的尺寸规格为 9.90—10.10 mm，μ=10.00、σ=0.02 mm，则 Cp=Cpk≈1.67。若波动不变但均值移到 10.06 mm，Cp 仍≈1.67，而 Cpk≈0.67。例子说明居中与波动是两个不同问题，不据此设定本公司的验收阈值。实际接受标准由产品要求、客户约定和质量专业判断确定。

## 抽样检验与过程控制

抽样接收的核心是根据约定方案对一批产品作接收或拒收决策。它与估计整批实际不良率不是同一个任务，也不能代替持续改进过程。[R05 NIST 接收抽样](https://www.itl.nist.gov/div898/handbook/pmc/section2/pmc21.htm)

在信息系统里，仅保存“合格”不足以解释结论。应保留批次、总体与抽样数量、抽样方案及版本、样本标识、检验项目、结果、判定规则、检验人和处置。复检、加严、让步接收与返工后再检需要分别留痕，不应覆盖最初失败结果。具体抽样方案和风险水平由质量团队确定。

## 质量工具如何进入流程

AIAG 的公开介绍包括 APQP、Control Plan、PPAP、FMEA、SPC 和 MSA。它们源于汽车行业质量实践，可用来理解产品策划、过程风险、量测与控制的衔接；是否适用及如何应用，应按产品、客户和业务要求决定。[R03 AIAG 工具概览](https://www.aiag.org/expertise-areas/quality/quality-core-tools)

| 现场问题 | 应连接的业务资料 | 信息化应帮助回答的问题 |
| --- | --- | --- |
| 新产品转量产准备是否充分 | 设计与过程评审、试产问题、批准记录 | 未解决问题会影响哪些产品和生产条件 |
| 哪些失效值得优先预防 | 风险分析、控制措施、实际异常 | 风险对应的预防与检测措施是否落实 |
| 现场该检查哪些特性 | 控制计划、检验规范、作业指导 | 当前产品和工序应采用哪个有效版本 |
| 测量结果是否可信 | 量测系统分析、校准、设备状态 | 数据变化来自产品、过程还是测量系统 |
| 改进是否有效 | 原始记录、分析方法、处置与复核 | 相同条件下问题是否复发，样本是否可比 |

电子装联方面，IPC-A-610 的公开介绍侧重电子组件可接受性，并说明与 J-STD-001 配合使用。知识库仅据公开页面解释其用途，具体判定条件应查阅企业合法获得、合同适用的标准版本。[R08 IPC 中文官方介绍](https://www.ipc.org.cn/standards/ipc-a-610)

## 测试与标定数据应怎样保存

对模组、相机或电子设备，一条 PASS/FAIL 记录通常不足以复核故障。建议围绕“哪个对象、在什么配置和条件下、用什么方法、产生什么原始结果、谁作了什么判定”组织数据。以下是数据设计建议，不表示所有产品都需要全部字段。

| 数据类别 | 建议考虑的字段 |
| --- | --- |
| 对象 | 产品、序列号、批次、工单、关键部件及关联关系 |
| 版本 | 硬件、固件、算法、测试程序、参数集、判定规则 |
| 环境与资源 | 时间、地点、工位、设备、工装、必要环境条件 |
| 测量 | 特性名、值、单位、精度、上下限、必要原始文件 |
| 结论 | 原始失败、复测、返工、最终处置、批准与放行 |
| 证据 | 原始文件标识、产生时间、完整性信息和保留规则 |

产品算法中的几何标定、测试设备的计量校准和质量判定属于相关但不同的事项。需要分别记录适用对象与方法，不能因为产品运行过标定程序，就认为测量设备已完成计量校准。对于误差、校准周期和能力要求，由相关产品与计量专业人员确认。

## 精益视角下的信息化问题

价值流观察同时看物料与信息，不只看机器是否在运行。可以把一条订单的实际加工、等待、搬运、检验、返工和决策排队放在同一时间线上，寻找重复输入或等待批准造成的停顿。[R06 Lean 价值流图](https://www.lean.org/lexicon-terms/value-stream-mapping/)

需求节拍 Takt time 的基础计算为“可用生产时间÷客户需求量”。它表达需求所需的节奏，与实际工序周期和订单交付周期不同。[R07 Lean 节拍](https://www.lean.org/lexicon-terms/takt-time/)

**教学例子**：假设每日可用于该产品族的净生产时间为 420 分钟，需求为 210 件，需求节拍为 2 分钟/件。若某工序在相同条件下实际单件周期为 2.4 分钟，说明需要进一步检查能力与资源安排；不能仅凭这个平均值就自动决定加人或扩产。还需考虑多机并行、产品组合、换型、波动与实际工作日历。

信息化改善可以从减少信息等待开始：变更已批准却未到达现场、到货后没有检验状态、工单完工后未形成可信测试记录，都属于需要跨角色解决的问题。看板的价值在于触发明确处理动作，而不是展示更多图表。
